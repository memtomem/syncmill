# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

syncmill orchestrates multiple CLI coding agents (Claude Code, Codex CLI, Kimi Code) over a single task, giving them pluggable shared long-term memory (memtomem by default, optional mem0 or LangGraph SQLite) so they collaborate and compete. It ships five orchestration strategies — `route` (priority fallback), `pipeline` (sequential chain), `compete` (concurrent head-to-head), `council` (multi-round propose → critique → synthesize deliberation), and `decompose` (split the task into subtasks, run them across agents concurrently, then synthesize) — and the architecture is built to grow more.

Detached `apply --detach` and `room round --detach` workers require POSIX
process-group and file-locking primitives; foreground commands remain the
portable path.

The agents shell out to real `claude`/`codex`/`kimi` binaries (note the `kimi-code` agent's binary is `kimi`), so `syncmill run` requires those CLIs installed and authenticated. The **test suite is fully hermetic** — `tests/conftest.py` provides fake agents/memory backends/registries so tests never touch the real `~/.memtomem` DB, the network, or the agent binaries. When adding behavior, mirror the existing pattern: monkeypatch `syncmill.agents._sync_run` (sync path — the Popen-backed runner `execute` calls; plain `subprocess.run` is no longer on that path) or `syncmill.agents.asyncio.create_subprocess_exec` (async path) for agent execution, inject a `FakeBackend` via `make_memory()` for memory logic, use the low-level fake memtomem store in `test_memory_backend.py` for adapter-private-boundary tests, inject a `FakeGate` for quality-gate behavior (and exercise the real `CommandGate` with harmless `true`/`false`/`python` commands), and use the `git_repo` fixture for worktree/git tests.

## Architecture

The whole system is one rule made concrete: **the Supervisor is the only component that touches both agents and memory. Agents are pure functions — prompt in, `TaskResult` out — and know nothing about the selected backend, each other, or the Supervisor.** This isolation is enforced at the type level: `AgentRunner.execute`/`aexecute`(prompt, workdir, timeout) receive only a `str` prompt. Never thread a `Task`, memory handle, or another agent's result into an agent.

Request flow (`CLI → Supervisor.run`, in `supervisor.py`):

1. Resolve a strict Git root. `capture_repository_snapshot` blocks unsafe states and
   captures HEAD + dirty tracked + untracked (ignored excluded) in a private control
   clone without changing the source index/branch/object database.
2. `Supervisor` builds an `AgentRegistry` and project-scoped memory for initialized projects.
3. Per run: build a snapshot-backed `WorktreePool`; every strategy worktree starts
   at the same synthetic snapshot commit. A pending continuation seeds the parent patch.
4. Re-order candidates by capability, execute the strategy, and keep provider-native
   sessions affine to `(agent, worktree)` across phases.
5. Before cleanup, `ArtifactStore` atomically writes the manifest, result, and
   `winner.patch`. Persistence failure changes the run to failed and retains the recovery workspace.
6. On success share the result to memory. In `finally`, finalize observability and
   remove private worktrees. Source changes happen only through explicit `syncmill apply`.

### The extension points

- **Memory backends** (`memory_backend.py`): `MemoryBackend` is the async, raise-freely storage contract; `SyncmillMemory` owns every best-effort/degradation path. `MemtomemBackend` remains the default and the only runtime module allowed to reach memtomem private internals; the migration-only exception is documented below. Optional adapters are `Mem0Backend` (`syncmill[mem0]`), restricted to Qdrant for exact count/delete semantics, and `LangGraphBackend` (`syncmill[langgraph]`), backed by persistent `AsyncSqliteStore`; both use local FastEmbed defaults, no sessions, and verbatim storage. Backend construction goes through `build_backend(config.memory)`, which refuses non-verbatim storage. The contract also carries the multi-agent surface — `search_multi` (merged multi-namespace search), `add_returning_id`, `share_chunk` (provenance copy), `register_namespace` (metadata upsert) — with `BackendCapabilities.native_multi_namespace_search`/`share_provenance_links` documenting the memtomem-native vs adapter-fallback split (see the Memory section). Tests fake each SDK boundary; opt-in real smokes use temporary stores.
- **Agents** (`agents.py`): subclass `CLIAgent`, implement `_build_command`, and override `_parse_output` / `_is_error_output` for that CLI's output format — you get both the sync `execute` and the async `aexecute` paths for free from the base class. Register the class in `_AGENT_CONSTRUCTORS`, add a matching `AgentConfig` field in `config.py` (an id with a hyphen — e.g. `kimi-code` — uses the underscore field name `kimi_code`, which `SyncmillConfig.agent_config` maps for you), and add the id to `agent_priority`. Output formats differ per CLI: Claude extracts the `result` key from its JSON, Codex joins `agent_message` items from its JSONL, and Kimi Code (`kimi`) keeps the `role:"assistant"` text lines from its `stream-json` JSONL. Only Claude exits 0 on an in-band error (hence its `_is_error_output`); the others signal failure with a non-zero exit.
- **Strategies** (`strategies/`): implement the `Strategy` Protocol and register it in `_STRATEGIES`, then select it via `default_strategy` (or the `--strategy/-s` CLI flag). `_make_strategy` raises on an unknown name — mirror that hard-fail rather than silently defaulting. **Package layout** (extracted from `supervisor.py` in #12, once all four strategies made that module unwieldy — the demand the "don't pre-abstract" invariant gated on): `strategies/base.py` holds the `Strategy` Protocol plus every cross-strategy helper (`_enrich_prompt`; the gate helper `_gate_accepts`; the breaker helpers `_breaker_runnable`/`_breaker_record`/`_breaker_all_open_failure`; the failure builders `_no_stages_failure`/`_aggregate_failure`; the convergence seam `_select_winner`; and the per-worktree diff collection `_collect_files_changed`/`_git_changed_files`) — diff collection lives *below* the strategy modules here, not in `supervisor.py`, precisely to keep the import graph acyclic (the Supervisor imports the registry, so it sits *above* the strategies). Each strategy is then its own module (`route.py`, `pipeline.py` with its private `_pipeline_failure`, `compete.py`, `council.py` with the `_council_*` prompt builders, `decompose.py` with the `_decompose_*` prompt builders + `_parse_subtasks`), and `strategies/__init__.py` owns the registry (`_STRATEGIES`, `available_strategies`, `_make_strategy`) because it needs every concrete class. The Supervisor imports `Strategy`/`_make_strategy` from the package and keeps only the run lifecycle + `_matched_order` (capability re-ordering is applied once at the Supervisor, never per strategy). Tests that monkeypatch `_git_changed_files` must target `syncmill.strategies.base` (where `_collect_files_changed` looks it up), **not** `syncmill.supervisor`. Five strategies exist: `RouteStrategy` (try agents in priority order, fall back on failure, aggregate errors if all fail), `PipelineStrategy` (run agents as sequential stages — each reads prior stages' results from `shared` and writes its own there, fail-fast on a broken stage; the prompt enricher `_enrich_prompt` is shared by all), `CompeteStrategy` (run every agent **concurrently**, each in its own worktree, then keep a winner), `CouncilStrategy` (multi-round deliberation; see below), and `DecomposeStrategy` (split the task into subtasks, run them across agents concurrently, then synthesize; see below). Each strategy is handed a `WorktreePool` and owns its worktree topology — Route/Compete/Council acquire one isolated worktree per agent, Pipeline a single shared one, Decompose one per planner + per subtask + per synthesizer — and sets per-worktree `files_changed` (via `_collect_files_changed`) on the result it returns. `CompeteStrategy` is syncmill's first *concurrent* strategy: it bridges async via `run_async` over the `aexecute_isolated` fan-out (per-agent worktree + per-agent timeout), and converges through `_select_winner` under `config.selection.mode` (never wall-clock/`duration_seconds`). The default `verified` mode selects the first gate-passing COMPLETED result in priority order; `priority` checks only the first completed candidate; `judge` ranks all gate-passing candidates and falls back to verified priority if judging fails. It aggregates failures like Route when none qualify. `_select_winner` is the quality-gate (#10) and selection-policy seam (see the quality-gates extension point below); it does **not** auto-apply the winner's diff (worktrees stay disposable — the Supervisor shares the winner to `shared` and normally tears down the run worktrees; recovery retention is exempt). `CouncilStrategy` (#13, v0.3) is the **multi-round** strategy: each agent gets one worktree reused across three kinds of *concurrent* phase — **propose** (every runnable agent drafts a solution; the completers become the council *members* and each proposal is published to `shared`), **critique** (`config.council.rounds` times — each member re-reads the council's proposals + prior critiques from `shared` and refines its own worktree, publishing each critique back; a failed critique is tolerated, not dropped), then **synthesize** (every member produces a final solution from the whole deliberation, and the council converges by **reusing `_select_winner`** — so a council is "deliberate over rounds, then compete on the synthesized candidates"). Deliberation flows **only** through `shared` (relevance-ranked, best-effort — the same handoff Pipeline uses), never agent-to-agent, so the synthesized winner reflects more than one agent's input by construction. `members` is just `(agent, worktree)` pairs — no per-member result state — because synthesis re-runs everyone and `_select_winner` is the single convergence point; the returned winner's `duration_seconds` is the council wall-clock (sum of each concurrent phase's slowest agent). Like Compete it neither cleans worktrees nor applies the winner's diff — the Supervisor shares the winner and normally tears down the run worktrees. `DecomposeStrategy` (#14, v0.3) is syncmill's first task-**splitting** strategy — where every other strategy runs agents on the *same* task, decompose runs them on *different pieces* (the maintainer chose the concurrent/isolated integration model over a sequential shared-tree one: collaborate via shared *knowledge*, not file merges). Three phases: **decompose** — the highest-priority runnable agent (`runnable[0]`) plans the breakdown in a scratch worktree via the **sync** `execute` path (a single sequential step needs no fan-out, like route/pipeline), returning a JSON array parsed by `_parse_subtasks` (robust to fences/prose; a failed/empty/unparseable plan **degrades** to a single whole-task subtask, so a flaky planner never aborts — best-effort like memory); **subtasks** — the subtasks are distributed **round-robin** over the runnable agents (`runnable[i % len(runnable)]` — "across agents") and run **concurrently**, each in its own worktree via the new `aexecute_each` fan-out (the per-item-prompt counterpart to `aexecute_isolated`'s broadcast), each completed subtask's summary published to `shared` (a failed subtask is tolerated, not shared; **none** completing → aggregate failure, like council with no proposal); **synthesize** — every runnable agent reads the subtask summaries from `shared` and produces the integrated solution in a **fresh** worktree (broadcast via `aexecute_isolated`), converging through the shared `_select_winner` seam under the same selection policy. All memory I/O sits strictly between fan-outs (the shared-loop rule); the winner's `duration_seconds` is the decompose wall-clock (planner + slowest subtask + slowest synthesizer). Like Compete/Council it neither cleans worktrees nor applies a diff — integration is by shared knowledge (the subtask worktrees are torn down, their code discarded, exactly as the losers' trees are). `config.decompose.max_subtasks` (≥1, default 8) caps the breakdown.
- **Quality gates** (`gates.py`, #10): a gate validates an agent's work **after it finishes**, against the diff in that agent's worktree — reactive, never a pre-run liveness probe (respects "no `health_check`"). Implement the `QualityGate` Protocol (`evaluate(worktree) -> GateReport`); the shipped `CommandGate` runs each configured command (via `shlex.split`, no shell — chain checks by adding entries, not `&&`) and passes iff all exit 0, in the **same isolated environment the agents get** (`isolated_git_env`) — a gate check reads the repository, so an ambient `GIT_DIR` would have it validate a different tree than the worktree under judgement, and an ambient `GIT_CONFIG_PARAMETERS`/`core.hooksPath` would execute someone else's script inside an agent-writable worktree. `build_gate(config.gate)` returns the gate or **`None` when no commands are configured** — the disabled default, so behavior is unchanged out of the box (set `SYNCMILL_GATE__COMMANDS='["pytest -q", ...]'`). The gate is plumbed through the **strategy layer only** — agents stay pure `(prompt, workdir, timeout)` functions and never see it. The Supervisor builds it per-run and injects it into `Strategy.execute(..., gate=)`; the shared `_gate_accepts` helper means "passed the gate" is one thing everywhere: pass → accept; fail → downgrade the result to FAILED with a gate error (attached as `result.gate`) so the rejection flows through the existing failure plumbing. Each strategy applies that verdict per its topology — **Route** falls back to the next agent, **Pipeline** fails the chain (gating only the final cumulative tree, since intermediate stages may legitimately be broken mid-chain), **Compete** downranks failers in `_select_winner`, **Council** gates only the synthesis phase (reusing `_select_winner` — propose/critique are ungated deliberation, only the converged final solution must clear the gate), and **Decompose** likewise gates only the synthesis phase (the planner and the individual subtasks are ungated — a subtask is a partial piece that needn't pass alone — and only the integrated synthesis, again via `_select_winner`, must clear the gate). A gate-rejected result is never shared to `shared` (it's a FAILED result, which the Supervisor already skips).
- **Circuit breaker** (`breaker.py`, #8): reactive per-agent back-off from *repeatedly* failing agents — `RouteStrategy` already falls back on one failure, the breaker remembers failures **across runs**. `CircuitBreaker` tracks consecutive failures per agent: after `failure_threshold` in a row the circuit **opens** (the agent is skipped) for `cooldown_seconds`, then goes **half-open** (one trial), and any success **closes** it (resets the count). The three states are derived from `(failures, opened_at)`, never stored. **Reactive, not a `health_check`:** `allows()` decides purely from *recorded past outcomes* — it never calls an agent to test liveness; skipping an OPEN agent is "it kept failing when we ran it," not a probe. State **persists** to `state_path` (JSON, atomic temp+`os.replace`) loaded on construction — this is mandatory, since each `syncmill run` runs an agent at most once, so "N in a row" only accumulates across separate invocations. `build_breaker(config.breaker)` returns **`None` when `enabled=False`** (the default), so the disabled path never touches the filesystem and behavior is unchanged. Like the gate it's plumbed through the **strategy layer only** (agents never see it); the Supervisor builds it once (it carries cross-run state + a `degraded` flag the CLI surfaces, unlike the stateless per-run gate) and injects it into `Strategy.execute(..., breaker=)`. Shared helpers keep it uniform: `_breaker_runnable` drops OPEN agents (all five strategies skip them; Route falls back, Pipeline chains the remaining stages, Compete, Council, and Decompose fan out only the survivors — all return `_breaker_all_open_failure` if the breaker tripped everyone), and `_breaker_record` records each run agent's **RAW execution status taken *before* the gate** — so a gate rejection (a quality verdict on a *working* agent) does **not** trip the breaker; only an agent that fails to *run* does. **CouncilStrategy is the one deliberate exception to "one record per run."** A council runs each member up to `2 + rounds` times (propose + critique rounds + synthesize), but records the breaker **exactly once per agent, at the propose phase** — the unique phase where every runnable agent executes once, from identical input, so it is the fair "can this agent run?" probe. The threshold is denominated in *runs*; recording every council execution would make council trip the breaker ~`(2 + rounds)`× faster than the other strategies (a strategy-dependent regression) and would conflate execution-reliability with a working member struggling on the harder critique/synthesize prompts — the same reason a gate rejection never trips it. So council's critique/synthesize re-runs of an already-recorded member are deliberately **not** recorded, keeping council's contribution to the cross-run "N in a row" count one-per-agent-per-run, identical to the other strategies. **DecomposeStrategy preserves that same one-record-per-agent-per-run invariant by a different mechanism: it records each agent's RAW outcome at its FIRST execution this run** (a `recorded` set), deduping all later runs. Decompose has no council-style uniform-and-easy phase to record at: the planner is one agent on a planning prompt, the subtasks are a non-uniform round-robin, and synthesis (the only phase where *every* runnable agent runs) is the **hardest** prompt — recording there would over-penalize a working agent struggling on integration, the very reason council records at propose, not synthesize. So "first execution" records the planner at its short/early (typically easy) planning step and every other agent at its first subtask (or, failing that, its synthesis), probing every agent that runs exactly once — and, as everywhere, the pre-gate status, so a synthesis gate rejection never trips it. Two "agent didn't run" cases are deliberately different: a **degraded** breaker (unreadable/malformed state file) is best-effort/advisory like memory — it degrades *permissive* (`allows()` returns True for everyone, surfaced as a yellow CLI notice) so a broken breaker never blocks or aborts work; an **OPEN** circuit (recorded failures, still within cooldown) is *intentionally* skipped, and if that empties the candidate pool the strategy fails fast with a clear "all circuit-open, cooling down — retry or disable" result (`_breaker_all_open_failure`, parallel to the gate failing the run when every output is rejected). That fail-fast is the back-off doing its job — respecting the cooldown the user opted into — not the breaker aborting healthy work; "advisory / never aborts" describes only the degraded path.
- **Capability matching** (`matcher.py`, #9): declarative, config-driven re-ordering of the candidate agents by *suitability* for a task, layered **over** the `agent_priority` baseline. Each agent declares capability tokens in config (`SYNCMILL_CAPABILITIES__AGENTS='{"codex": ["python"], "kimi-code": ["rust"]}'` — a map keyed by the **real** agent id, so hyphenated `kimi-code` is a verbatim key, unlike the underscore `AgentConfig` fields); a task carries a hint in its `Task.tags` (the previously-unused field, reused — set via the repeatable `--capability/-c` CLI flag). `DeclarativeMatcher.order` scores each agent by the **set-intersection size** of its declared capabilities with the (normalized, case-insensitive) hint and **stable-sorts descending**, so a matching agent moves ahead of raw priority while equal-fit agents keep priority order (the tie-break is sort stability over the input). It **re-orders, never drops** — the output is a permutation, so nothing is stranded and the two acceptance criteria hold by construction: a matching agent sorts ahead (score ≥ 1 > 0), and *nothing matching* (or no hint) is an all-zero stable sort = identity = priority order. **DECLARATIVE, never a probe** — a pure dict-lookup + set-intersection of static config with `task.tags`, strictly more passive than the breaker (respects "no `health_check`"). `build_matcher(config.capabilities, config.agent_priority)` returns **`None` when no agent declares a capability** (the disabled default → identity ordering, behavior unchanged); the optional `known_agent_ids` only **advisory-warns** (never raises) on a capability declared for an id not in the lineup (a config typo), while free-form *tokens* are never validated (an unmatched token is the graceful fallback). Unlike the gate/breaker — whose verdicts mean different things per strategy, so they're threaded **into** `Strategy.execute` — capability matching has **no topology-specific semantics**: it produces exactly one artifact, a re-ordering of the flat candidate list every strategy already consumes as a priority sequence. So the Supervisor applies it **once** in `run` (`_matched_order`, the `else`/non-forced path only — a forced `-a` agent has no ordering to influence), **before** dispatching to the strategy and **before** the breaker's per-strategy OPEN-agent filter (preference first, then availability) — making **all five** strategies capability-aware with no `Strategy` protocol change: Route tries the best-matched agent first, Pipeline leads its chain with it, Compete and Council make it the winner-priority (Council's members preserve the matched order, so the best-matched agent leads the synthesis selection), and Decompose makes it the planner + leads its subtask round-robin and synthesis-winner priority. This is the deliberate, uniform reading of #9's "layered over the existing priority order" (#9 only mandates Route; Pipeline/Compete/Council/Decompose are the free consequence of re-ordering at the source). Built once in `Supervisor.__init__` (stateless/config-derived, no filesystem — unlike the breaker); the CLI rebuilds a display-only matcher so the `Agents: …` banner shows the **actual** matched order rather than raw priority.
- **Model routing** (`model_routing.py`, PR 1 of `docs/difficulty-model-routing-plan.md` — the canonical contract; read it before touching this): difficulty-based selection of the **provider-internal model** — never the agent lineup, order, or strategy semantics. Default `off` is byte-identical legacy behavior (no classifier, no decision, no ContextVar scope, no plan key). `[model_routing]` config (`ModelRoutingConfig`, the ONE nested model with `extra="forbid"` — a typo inside a cost-control table must be an error; `mode` rejects `enforce` as reserved) maps tier→provider→selector with **verbatim real-id keys** (`kimi-code`); selectors are shape-validated only (one argv token, no control chars) — an unavailable selector stays an ordinary provider failure (route falls back; the breaker records it like any failure). ONE immutable `ModelRoutingDecision` per top-level run, computed in `Supervisor.run` right after `_matched_order` + the no-agents guard and **projected onto the eligible lineup only**; `run_item` passes `enable_routing=False` (Board is a PR-2 surface — observe must never classify the ENRICHED board prompt), and a continuation (`parent_run_id` set) NEVER classifies — it inherits via `inherit_decision` (strict v1 validation, `ValueError("corrupt model routing metadata")` fails closed; a legacy parent = no flag even under observe). ### Memory (`memory.py`)

`SyncmillMemory` applies syncmill conventions over the selected `MemoryBackend`: namespace `agent-runtime:{agent_id}` is private per agent and `shared` is the cross-agent knowledge base. The Supervisor is the **sole reader/writer** — there is intentionally no MCP sharing between agents. Backend APIs are async, as is the agents' `aexecute` path, while orchestration stays sync. `run_async()` bridges both into that sync world by **reusing a module-level event loop**; do not switch to `asyncio.run()`, which closes resources needed by later calls. `close_event_loop()` releases it at CLI shutdown.

**Multi-agent API semantics (memtomem-aligned):** syncmill now mirrors memtomem's MCP multi-agent tools through the backend contract — the MCP tools themselves are MCP-SDK-coupled, so `MemtomemBackend` reproduces their semantics on the `MemtomemStore` surface + the sanctioned storage privates (never `import memtomem.server.*`, and never `start_agent_session`, whose bound agent id would OVERRIDE the explicit namespace filter and break board scoping). Four pieces: (1) **Unified search** — `search_context` is ONE `search_multi` call over `[agent-runtime:{id}?, shared, global-shared?]` (`_CONTEXT_TOP_K` rows); memtomem gets a single native comma-union merged-ranking call (`mem_agent_search`'s `include_shared` shape), mem0/LangGraph an adapter-side per-namespace merge (`BackendCapabilities.native_multi_namespace_search`). (2) **Provenance shares** — an unscoped `share_result` is a two-step agent-share: `add_returning_ids` into the producer's `agent-runtime:{id}` (replicating `MemtomemStore.add`'s guard→sidecar-lock→mix-refusal→`append_entry`→`index_file(lock_held=True)` flow to keep `IndexingStats.new_chunk_ids`, which `add` discards; the lock span is 0.4's write-locking contract — an unlocked append lets the watcher index the new file first WITHOUT the explicit namespace, stranding the agent-private chunk in `default`, so mix-guard, append and re-index share ONE cross-process sidecar-lock span (the real smoke pins it) — so strategy intermediates now populate the agent namespaces, and an agent's future `search_context` surfaces its own past work), then `share_chunk` COPIES **every** chunk to `shared` (a long result splits — sharing only the first chunk would drop the output half) with the collapsed `shared-from=<id>` tag + a best-effort `chunk_links(link_type="shared")` row (`share_provenance_links`). A failing step falls back to the direct `shared` add **and degrades** (the lost provenance contract is surfaced, never silent), but a PARTIAL share (some chunks copied, some not) degrades **without** the fallback — those chunks are already in `shared`, so a full direct copy beside them would inflate `shared_stats` and feed near-duplicate rows to every reader; a `WriteBlockedError` (redaction guard) skips the fallback — the same guard would re-block. A board-scoped view always writes directly (both namespaces collapse to the scope — the leak guard is untouched, and D4's union-read rides the same `search_multi` namespace list). **Two MCP-parity details are load-bearing:** each write invalidates the search pipeline's TTL result cache (the MCP add path does; `MemtomemStore.add` does not — without it an intra-run pipeline/council/decompose handoff can be served the pre-write cached result), and **every** write — `add` and `add_returning_ids` alike, since `add` now routes through the same flow — goes to a **namespace-suffixed daily file** (`{date}.{ns}.md`, `:`→`.`) because under default memtomem config re-indexing one file holding the same content-hash twice collapses to the last write — the two-step's identical copy would DELETE the private original and orphan the link (a real FK failure the opt-in smoke caught). Routing `add` through `MemtomemStore.add`'s namespace-SHARED `{date}.md` was the same bug in a second costume: `delete_by_namespace` removes DB rows only while the markdown is what the index is rebuilt FROM, so a GC'd `board-run:*` chunk survived in a file a later `shared` write re-indexed — and, its rows gone, was treated as new and stamped `shared`, leaking board-internal content into global knowledge. For the same reason `delete_board_runs` follows each row delete with `delete_namespace_sources` (an optional backend method — file-less backends simply don't offer it), so a delete survives a reindex; that method **raises rather than reporting zero**, and the ledger acknowledges a run only when BOTH halves succeed (a namespace whose source survived is not purged — tombstoning it would retire it from collection while its text is still re-indexable). **Known residue:** a store written before this change kept every namespace in one shared `{date}.md`, whose entries carry no namespace — nothing selects them, and deleting the file would take shared knowledge with it, so pre-upgrade scratch stays re-indexable and is a manual cleanup. **A third parity detail is load-bearing:** every write passes an EXPLICIT unique heading (`_entry_title` — ms timestamp + full uuid) instead of relying on `append_entry`'s default. Under memtomem 0.3 that default was `## Entry {now}` at SECOND resolution (0.4's default is now ms + full uuid, but the explicit title keeps the pinned deterministic shape from drifting with the upstream default), and two entries sharing a heading in one file re-chunk into a SINGLE chunk — so a second write inside the same second swallowed the first entry's text and re-minted its chunk id, which `add_returning_ids` had already returned, making the two-step share look up a chunk that no longer existed and silently fall back to a direct write with the provenance link gone. Back-to-back writes to one namespace are exactly what a pipeline/council/decompose handoff does, so this was live, not theoretical (the real smoke's `rapid write` block pins it; only the real store re-chunks, so the hermetic fake can pin the unique heading but never the consequence). Milliseconds alone would only narrow the window, hence the uuid suffix; the `> created:` line memtomem's own parsers read keeps its second resolution. **The unique heading only reaches content that does not open with `## `** — `format_entry_block` treats heading-led content as supplying its own heading, skips the title entirely, and in that branch emits the tags blockquote BEFORE the content's heading. syncmill's payloads used to open with `## Task Result` / `## Board Item Result`, so this was not a same-second window at all: EVERY result carried the same heading, consecutive results merged into one chunk, the returned ids were re-minted, and the survivor's tags landed in the previous entry's section — leaving it unreachable by `tag_filter`, the documented retrieval key for kind-tagged artifacts. Both payloads therefore label themselves in **bold** (see memory.py's heading note; a hermetic test pins the shape, `add_returning_ids` warns if a heading-led payload ever returns, and the real smoke now uses the PRODUCTION payload shape — exercising plain text there passed while every orchestration write was broken). **Residue:** a bold label is not enough if the BODY carries headings — agent output is embedded verbatim, so an agent writing `## Summary` still opens a section two runs can share. Closing that needs either mutating the agent's text (the backend contract is verbatim storage) or an upstream chunker change. (3) **Registration metadata** — `register_agent` upserts `mem_agent_register`-style description/color via `register_namespace` (unconditional; `_AGENT_COLORS` supplies defaults; `None` = default, explicit `""` = clear, passed verbatim), keeping `ensure_namespace`'s create-if-missing for `shared`. (4) **Kind-tagged artifacts** — every share carries `[kind, agent_id, task:{task.id}]`: the winner is `task-result`; strategies tag intermediates `pipeline-stage` / `council-proposal` / `council-critique` / `decompose-subtask`, and Decompose publishes its **parsed** plan as `decompose-plan` (what actually runs after normalization/capping — never the raw planner response, never the degraded whole-task fallback) — so unified search surfaces work plans/results and `tag_filter` retrieves one artifact class exactly. Requires `memtomem>=0.4.0,<0.5` (`require_user_base`; the upper bound because the replicated add flow rides privates — bump it only WITH the required real smoke `SYNCMILL_TEST_MEMTOMEM_REAL=1`). memtomem 0.4 forces `mcp>=2.0.0,<3` (the fastmcp module is removed in the 2.0 SDK — see the gateway section), so the two pins move together. **Known limitation (day-file naming):** memtomem 0.4 natively writes per-namespace day files as `{date}--{slug}-{digest}.md` while syncmill's replicated add flow writes `{date}.{ns}.md`; both are per-namespace (the upstream mix-guard passes), but `delete_namespace_sources`'s `*.{ns}.md` glob does not match memtomem-native files — an extension of the pre-existing residue already documented on that method.

**Memory is advisory/best-effort.** Every `SyncmillMemory` method catches its own exceptions, logs a warning, sets `degraded`/`last_error`, and returns a safe default. A broken or misconfigured backend must never abort a task — the agent still runs, just without shared context. Preserve this when editing memory or the Supervisor; the CLI surfaces `supervisor.memory.degraded` as a yellow notice. memtomem applies `~/.memtomem/config.json` last and shares its global DB by default; mem0 and LangGraph use separate stores unless configured otherwise, with explicit staged migration available between every installed backend pair.

### Interactive collaboration (human drives one agent, syncmill runs the rest)

Programmatic `claude` runs may be billed separately from interactive use. To keep Claude **interactive** while syncmill orchestrates the others: exclude claude from the run (`run … --exclude claude`, repeatable; or persistently via `SYNCMILL_CLAUDE__ENABLED=false`) and drive Claude yourself in the terminal. The two sides collaborate **only through the `shared` namespace** — never by syncmill invoking claude, so the agent-isolation invariant is untouched (the interactive session is a separate process, not a syncmill agent).

This needs zero extra wiring: syncmill's `SyncmillMemory` and memtomem's MCP multi-agent tools use the **same `shared` literal on the same `~/.memtomem/memtomem.db`** (exact-match namespaces). The one rule — the interactive session must target `shared` **explicitly**, because its default namespace is cwd-scoped (`claude:<cwd>`), which syncmill does not read.

- Interactive session **writes** (so syncmill sees it): `mem_add(content=..., namespace="shared")`, or `mem_agent_share(chunk_id=..., target="shared")` to promote an existing chunk.
- Interactive session **reads** syncmill's results: `mem_agent_search(query=..., include_shared=True)` or `mem_search(query=..., namespace="shared")`.
- syncmill side: `share_result` writes the winner to `shared` **with `mem_agent_share`-compatible provenance** (original in `agent-runtime:{agent_id}`, `shared` copy carrying `shared-from=<chunk-id>` + a `chunk_links` row) and the tags `[task-result, {agent_id}, task:{task-id}]`; `search_context` reads the agent namespace + `shared` in one merged-ranking search to enrich the programmatic agents' prompts. The interactive session can pull one artifact class exactly via `mem_search(tag_filter="decompose-plan")` (or `council-proposal`/`council-critique`/`pipeline-stage`/`decompose-subtask`/`task-result`).

Collaboration is via shared *knowledge*, not file merges: the interactive session edits your real working tree while syncmill agents edit isolated worktrees, so syncmill's diff never sees the interactive edits. `CompeteStrategy` now runs the syncmill *agents* head-to-head; entering the human's interactive session as a competitor judged alongside them is still future work (the interactive session is a separate process, not a syncmill agent).

`syncmill session` (#17, below) makes this mode **durable**: instead of running the bare CLI in your own terminal (where it dies on terminal close / SSH drop), it launches that same interactive binary inside a dedicated, reattachable tmux session. The collaboration contract is identical — the session still targets `shared` explicitly (`session start` prints the `mem_add`/`mem_agent_search` reminder) — it just survives detach.

### Read-only MCP gateway (`gateway.py`, #15)

The `serve` command runs a **one-way (read-only) MCP gateway** over the `shared` namespace so external/interactive MCP clients (Claude Code/Desktop, Cursor, …) can *read* syncmill's shared knowledge — the **consumer-facing** complement to the interactive mode above. It is **not** a strategy and **not** an agent: it preserves the core invariant exactly (agents never touch MCP; the Supervisor remains the sole *writer*) by being a separate, non-agent, read-only *consumer*. The gateway touches memory but never agents, so "the Supervisor is the only component that touches both agents and memory" still holds. `gateway.py` is a **flat top-level module** (no subpackage — don't pre-abstract; one module is enough). The seam is `build_gateway(memory, *, board=None, board_error=None) -> MCPServer` (the official `mcp.server.mcpserver.MCPServer`, mcp 2.0 SDK — `mcp.server.fastmcp` was removed in 2.0), which registers the read-only tools as closures over the injected `memory` (and, in **Phase 2**, the injected `board`) and returns the server *without running it* (the test seam — the public `await mcp.list_tools()` asserts the exact tool set so a write/delete/index tool can never sneak in; tools are driven in tests via `await mcp.call_tool(...)`, which returns a `CallToolResult` whose `structured_content == {"result": str}`). #15 shipped the three `shared` tools — `shared_search(query, top_k)`, `shared_read(chunk_id)`, `shared_stats()`; **Phase 2 adds three read-only `board_*` tools** — `board_list(state, goal, limit)`, `board_get(item_id)`, `board_stats()` — so **the exact-set guard now asserts six tools** (`test_exactly_six_readonly_tools`), still with **no write tool** for memory OR the board. The board tools are registered **unconditionally** (a stable surface) and report `_BOARD_DISABLED` ("not enabled") when no board is injected, OR `_BOARD_UNAVAILABLE: <error>` when the board was **enabled but failed to open** (`board_error`, threaded from `serve`) — the disabled-vs-broken distinction, mirroring the shared tools' healthy-empty-vs-unavailable split, while the shared gateway stays alive. `board_list` clamps `limit` to `[1, MAX_BOARD_LIMIT=200]` and returns **most-recent-first** (reversing `Board.list`'s FIFO so a truncated read keeps the newest, not the oldest, items); board **id (uuid) validation lives in `board.py`** (`Board.get` rejects a malformed id as not-found without a query — the single-coupling rule, mirroring `get_shared`). Board reads are sync sqlite called directly inside the async MCP handlers (quick — no thread offload); `serve` builds the board best-effort and closes it in its `finally`. **All memtomem coupling stays in `memory.py`** (the same single-coupling rule as the Supervisor): three shared-scoped, best-effort read methods on `SyncmillMemory` — `search_shared`, `get_shared`, `shared_stats` — each returning **`None` on a genuine per-call backend failure** (vs `[]`/a `dict` on success) so the gateway distinguishes "unavailable" from "healthy-empty" **without** consulting the sticky `degraded` flag (a prior unrelated degrade must not poison a later healthy empty read). **Isolation is load-bearing:** `MemtomemStore.get` is *not* namespace-scoped, so `get_shared` verifies the returned chunk's `namespace == shared` and returns `None` otherwise (else a guessed/leaked id would leak an `agent-runtime:*` private chunk); `search_shared` always passes `namespace="shared"` (never the agent prefix/`None`/`include_shared`) and filters non-shared rows defensively; `shared_stats` uses `list_namespace_meta()` (the only meta method carrying `chunk_count`) and reports the `shared` entry **alone** — never enumerating other namespaces (a metadata-leak guard). A malformed `chunk_id` is a client typo → `get_shared` returns *not-found* **without** degrading (validate the UUID first; only a real store error degrades). The CLI clamps `top_k` to `[1, MAX_TOP_K=50]` (untrusted-input guard). **Event-loop & transport:** the `serve` path never uses `run_async` — `MCPServer.run()` owns its own anyio loop and the async tools `await` the memory methods directly inside it; memory is constructed eagerly (sync; lazy memtomem init) and closed in a `finally` via `anyio.run(memory.close)` (a fresh loop, deliberately off syncmill's shared module loop). Under stdio, **stdout is the JSON-RPC channel** — every human-facing line (startup notice, degraded/HTTP warnings) goes to **stderr** (`err=True`); the command writes nothing to stdout. HTTP (`--http`, `streamable-http`) is loopback-by-default; on the mcp 2.0 SDK `host`/`port` are **run-time transport kwargs** — `mcp.run(transport="streamable-http", host=..., port=...)` — and the SDK computes its DNS-rebinding `transport_security` allow-list from the host actually passed at run time (loopback hosts get automatic protection), so the old construction-time-host rationale (a stale loopback policy after mutating settings) is structurally gone; a non-loopback `--host` is warned about (the warning doubles as the cue that auto-protection engages only for loopback hosts) and there is **no auth** (document/front with a trusted network or authenticated proxy). `mcp>=2.0.0,<3` is a direct dependency, moving in lockstep with the memtomem pin.

### Live tmux monitor (`monitor.py`, #16)

The `--monitor` flag (or `SYNCMILL_MONITOR__ENABLED`) gives a **live tmux view of a concurrent run** — one pane per agent, streaming output as it happens, auto-attached. Like the gateway it's an **observability layer, not a strategy or agent**, and it preserves agent purity exactly: the `AgentRunner` signature is **unchanged** (still only `(prompt, workdir, timeout)`). Four locked design decisions (maintainer-approved via AskUserQuestion): (1) streaming via an **ambient `contextvars` seam** in `agents.py` — `_OUTPUT_SINK` (default `None` → today's `communicate()` path **byte-for-byte**) + the `stream_to(sink)` context manager + the `OutputSink` Protocol, which live in `agents.py` precisely so `agents.py` imports nothing from `monitor.py` (acyclic). When a sink is set, `aexecute` uses `_communicate_teed` (drains stdout/stderr concurrently like `communicate`, tees each chunk to the sink, **bounded** reap via `wait_for(proc.wait(), _REAP_TIMEOUT_SECONDS)` — never a bare `await proc.wait()`, which would re-introduce the grandchild-pipe hang). (2) The `Monitor` is **threaded through the strategy layer** (`Strategy.execute(..., monitor=None)`), like the gate/breaker: the concurrent strategies call the shared `base.py` helpers `_monitor_phase`/`_monitor_streaming(agent_ids)`/`_monitor_status` (no-ops when `None`) — announce each phase, wrap each fan-out in `_monitor_streaming` (opens the seam **and** lazily creates that agent's pane), report per-agent raw status; the sequential strategies (route/pipeline) accept-and-ignore (the seam is async-only, so they can't stream). (3) UX = **auto-attach**. (4) Because orchestration is deliberately **sync on the main thread** and `tmux attach` needs the foreground, the mechanism is **run-orchestration-inside-tmux** (outer/inner split): the OUTER `syncmill run` builds a detached tmux session whose control pane runs the REAL orchestration by re-invoking `syncmill run` (DETERMINISTIC argv reconstruction in `_inner_argv`, **never `sys.argv`**; `--monitor` deliberately OMITTED). The inner argv is launched through a `sys.executable -c <_ENV_SHIM>` exec shim that **replaces** the pane's inherited environment with the OUTER's **`0600` `<run_dir>/env` snapshot** (`_write_env_snapshot`) — it `os.environ.clear()`s, applies the snapshot, then re-keeps only the tmux-owned pane vars (`TERM`/`TMUX`/`TMUX_PANE`, the same set `_SNAPSHOT_SKIP_ENV` omits) before `execvp`. **Replace, not additive `update`:** a new session inherits the (possibly stale) tmux **server** env, not the client's, so an additive overlay would leave any stale `SYNCMILL_*`/auth/PATH var the outer client lacks and silently change the inner's config — clearing first gives the inner **exactly** the outer's full env (PATH/`SYNCMILL_*`/auth, **incl.** `SYNCMILL_MONITOR_DIR`) plus the pane's three terminal vars. This is **without** serializing secrets into the tmux command-line argv (the earlier `-e KEY=VALUE` approach leaked secrets into `ps` and could blow the exec arg limit — **do not reintroduce it**). The shim **self-unlinks** the snapshot in a `finally` **before** parsing it (the `session.py` recipe, adopted here too): the file is the outer's whole environment, the detach-early and failed-attach paths deliberately RETAIN the run dir, and the parent can't delete it (the detached pane's shim runs asynchronously after `new-session` returns) — so without the self-unlink a plaintext key dump waits in `/tmp` for a later run's 24h sweep that may never come. `agents._isolated_process_env` strips `SYNCMILL_MONITOR_DIR`/`SYNCMILL_RUN_ID` (`_RUN_IPC_ENV`, literals — `agents` must not import `monitor`) so an agent that invokes syncmill can't false-trip `inner_dir()` and overwrite the parent run's envelope/result.json. All argv is passed DIRECTLY (no shell re-parse → no injection, works under fish/csh). The snapshot excludes the tmux-owned `TERM`/`TMUX`/`TMUX_PANE` (`_SNAPSHOT_SKIP_ENV`); the OUTER then `tmux attach`es (foreground, blocks) with only `TMUX`/`TMUX_PANE` stripped (`_ATTACH_STRIP_ENV` — **`TERM` is KEPT**, the attaching client needs it to render; stripping it breaks attach) so attach works even from inside an existing tmux session, and `_tmux_attach` returns the rc so a failed attach (non-zero, no `result.json`) is surfaced + exits non-zero rather than mistaken for a clean "detached, exit 0". On detach it reads the inner's `result.json`, renders it (the **shared** `render_result`/`render_task_result`, so monitored and unmonitored output are byte-identical), and exits with its code. The INNER detects itself via `inner_dir()` — the **single source of truth** requiring **both** the env var **and** a `.syncmill-inner` sentinel file (so a stray exported var can't masquerade a normal run as inner) — builds a `TmuxFileMonitor` (`build_monitor(config, *, monitor_dir)`, pure, `None` when `monitor_dir` is `None` so normal runs/the outer never build one), tees output to per-agent logs via `FileSink` (a single **non-blocking `os.write`** in `O_APPEND` — never blocks the shared event loop, never raises out), drives the panes **from inside the session** (`$TMUX` inherited; lazy `split-window` + `tail -F` per agent it actually runs, so panes track the **real** runnable set after the breaker/matcher filters — no outer/inner drift), and on `finish(result)` writes `result.json` (atomic temp+`os.replace`) + keeps the control pane's result on screen (`remain-on-exit`). The Supervisor builds the monitor per-run (`build_monitor(config.monitor, monitor_dir=inner_dir())`), injects it into `Strategy.execute(..., monitor=)`, and calls `monitor.finish(result)` in its `finally`. The CLI **gates the outer launch** on (monitoring enabled ∧ NOT inner ∧ strategy in `CONCURRENT_STRATEGIES` ∧ `_stdout_isatty()` ∧ `tmux_available()`) — each missing precondition prints a notice and **falls through to a normal run** (the monitor is a convenience, never required; a `MonitorLaunchError` from a failed `tmux new-session` likewise falls back). The inner installs a SIGHUP/SIGTERM→`SystemExit` handler so the Supervisor's `finally` (worktree cleanup) still runs on tmux-server death. `monitor.py` is a **flat top-level module** (gateway.py precedent), banner-split into shared / INNER monitor / OUTER launcher, with the OUTER half importing nothing from the INNER half. **Two NEW deliberate `aexecute` divergences to preserve:** a *teed timeout* surfaces the pre-timeout bytes to the sink/log (plus a `[timed out…]` marker) even though the result's `output` stays empty (the log is a live VIEW, the result is the CONTRACT); and the teed path replaces `communicate()` only when a sink is active. Hermetic tests never launch tmux: `_FakeProc` grew `.stdout`/`.stderr` `_FakeStream`s for the teed path, an autouse `reset_output_sink` fixture forces `_OUTPUT_SINK` back to `None` per test, `FakeMonitor` records ordered events + opens the real sink, and `monitor._tmux`/`_tmux_attach`/`tmux_available`/`_stdout_isatty`/`inner_dir`/`launch_monitored_run` are all patchable seams. **Scope note (v0.3):** Claude's `--output-format json` emits one final blob (no incremental stream), so its pane fills at completion where codex/kimi (JSONL) stream live; the M10a detached-run GC registry was deliberately **not** built — the existing `cleanup_orphaned_worktrees` already sweeps stranded worktrees every run.

### Durable interactive sessions (`session.py`, #16-sibling, #17, v0.4)

The `session` command group (`start`/`list`/`attach`/`stop`) makes the interactive-collaboration mode **durable**: it launches an agent's **bare interactive CLI** (`claude`/`codex`/`kimi`) inside a dedicated tmux session that survives detach (`Ctrl-b d` / terminal close / SSH drop) and **reattaches by deterministic name** — the v0.4 acceptance criterion. The **complement** to #16: where `--monitor` is an *ephemeral* view of a *programmatic* concurrent run, `session` is a *long-lived* host for a *human-driven interactive* agent. Maintainer-approved (AskUserQuestion): (1) scope = the four-verb lifecycle; (2) a new **flat `session.py`** (gateway/monitor precedent) that *reuses* monitor's tmux primitives; (3) a **standalone `_INTERACTIVE` map** (`{agent_id: [binary]}`) for the launch command.

Core invariants: **not an agent, not a strategy, touches neither agents nor memory** — pure tmux + process launch (so the "Supervisor is the only thing touching both agents and memory" invariant is untouched). The interactive session NEVER enters `AgentRunner.execute`/`aexecute` (that would re-incur programmatic billing and break agent purity), so the per-agent launch command is a standalone `_INTERACTIVE` map **deliberately separate from** `CLIAgent._build_command` (it duplicates the `kimi-code → kimi` binary fact on purpose — interactive mode does **not** route through the registry, so it can run an agent that is `enabled=false` for orchestration; the CLI validates the requested agent against `_INTERACTIVE` keys, **not** `registry.available()`). `session.py` **reuses monitor's primitives** via `from syncmill.monitor import _tmux, _tmux_attach, _SNAPSHOT_SKIP_ENV, INNER_ENV` (`monitor.py` stays **UNCHANGED**) — private cross-module imports, the established `cli.py`→`supervisor._matched_order` pattern, so tests patch the **lookup site** `session._tmux` (not `monitor._tmux`, the `strategies.base` `_git_changed_files` lesson). It defines its **own `SessionLaunchError`** rather than reusing `MonitorLaunchError` (whose contract is "the CLI falls back to a normal run on catch" — but `session` has **no fallback**, it errors: `session` IS the tmux feature; the CLI gates `tmux_available()` as a hard error, and `_stdout_isatty()` for the foreground-attaching `start`/`attach`).

Durability mechanism: **deterministic names** `syncmill-session-<agent>` (not the monitor's uuid suffix) are the reattach key — `start` recomputes the name, and if the session exists it skips creation and attaches (reattach); else it creates a **detached** `new-session -d -s <name> -c <workdir>` running the bare binary through a session-specific exec shim, then attaches. No `remain-on-exit` (unlike the monitor — the session **should** vanish when the user quits the agent). The working dir is the **resolved `repo_root`** (the real tree — interactive edits land there, per the collaboration contract; the CLI validates `is_dir()` because tmux `-c` silently falls back to `$HOME`). Like the monitor, the detached session would inherit the stale tmux-**server** env, so the outer's environment is restored from a **`0600` snapshot file** (never argv — no secrets in `ps`) via **`_SESSION_ENV_SHIM`** — a *session-specific* shim (NOT `monitor._ENV_SHIM`) with two deliberate differences, both codex-design-review-driven: (a) it **self-unlinks the env file in a `finally` immediately after the read, BEFORE `json.loads`** — the detached pane's shim runs *asynchronously after* `new-session` returns, so the parent can't delete the file without a use-after-free; the shim consuming it is race-free and shrinks the secret window even on a corrupt snapshot; the parent only `rmtree`s the run dir on the **failure** paths (where the shim never started); (b) the snapshot **excludes `INNER_ENV`** as well as `_SNAPSHOT_SKIP_ENV`, so an already-exported `SYNCMILL_MONITOR_DIR` can't reach the interactive process and false-trip `monitor.inner_dir`. **Lifecycle ops match EXACT known names** (`{session_name(a) for a in _INTERACTIVE}`), never the `syncmill-session-` prefix — so `list`/`stop --all` can't show or kill a monitor run even if a user sets `SYNCMILL_MONITOR__SESSION_PREFIX=syncmill-session` (a destructive-op collision codex flagged). `#{session_attached}` is a client **count**, so attached = `int > 0`. A sentinel-guarded (`.syncmill-session`, distinct from monitor's `.syncmill-inner`), age-bounded `_sweep_stale_session_dirs` reaps orphaned run dirs (the #16 R5 ownership lesson). Hermetic tests (`tests/test_session.py`) never launch real tmux (patch `session._tmux`/`_tmux_attach`/`_sweep_stale_session_dirs`); the shim is exercised in a real tmux-free `python -c` child (env applied + file unlinked, incl. a corrupt-env case), and the gate/arg-shape surface in `tests/test_cli.py` via `_patch_session_seams`. **#17 = last v0.4 item.** No new config table (don't pre-abstract — the session prefix is a module constant).

### Persistent work-board (`board.py`, Phase 1 + Phase 2 of the agent-team platform)

The `board` command group turns syncmill from a single-run, stateless orchestrator into one with **durable, structured records of team work** — goal, owner, state, what's blocked/why, what's done **and verified**, dependencies, and a handoff baton. It is a **new flat top-level module** (gateway/monitor/session precedent — *don't pre-abstract*) backed by its **own SQLite store** at `~/.syncmill/board.db`: memtomem can't back it (markdown+embedding *knowledge* chunks have no structured status/dependency fields, no state machine, no atomic compare-and-swap). *State lives only on the board; knowledge lives only in memtomem's `shared`; the two cross-link by id.* Five locked design decisions (codex-reviewed pre-code over 5 rounds):

1. **Applied at the Supervisor run-lifecycle level, NOT threaded into `Strategy.execute`** — like `_matched_order`, the board has no topology-specific meaning. A new `Supervisor.run_item` *wraps* `run`; the **`Strategy` protocol is unchanged**; `run` gains exactly **one optional kwarg `memory=`** (`mem = memory or self._memory`, used at ALL five memory call sites — register/start_session/strategy/share/end — so plain `run` is behavior-identical). 2. **Agents stay pure** — orchestrated agents NEVER touch the board; the Supervisor mediates by rendering the item into the prompt (`render_item_prompt`, deterministic) and parsing an OPTIONAL ` ```syncmill-board ` fenced block back out of `result.output` (`parse_board_update` — its OWN parser, NOT a reuse: it degrades to `{}` and **NEVER raises** — incl. on pathologically-nested JSON, whose `json.loads` raises `RecursionError`, a `RuntimeError` not a `ValueError`, so it is caught explicitly. Recognized fields are sanitized **individually** (one malformed field can't discard a valid `state`); the all-or-nothing part is the `outputs` **list** (a mixed list is dropped whole, never salvaged to a subset — the `DecomposeStrategy._parse_subtasks` *philosophy*). `_extract_board_block` requires a genuine close fence — a 2nd `syncmill-board` OPEN fence is never mistaken for the first block's close, matching `strip_board_block` so the parser and the stripper agree on block bounds). 3. **The board store is LOAD-BEARING, built LAZILY** — it's the source of work + system of record, so unlike memory/breaker it does **not** degrade silently: a corrupt/unopenable db raises `BoardError` (caught at `Board.__init__` for `sqlite3.Error` — a corrupt file, `OSError` — an unwritable parent dir, *and* `RuntimeError` — an unresolvable `~` when no home dir is set; `expanduser()` runs **inside** that try so `Board()` raises **only** `BoardError`, the contract `serve` relies on to catch a bad board and still close memory in its `finally`) → the CLI converts to `click.ClickException` (the `session.SessionLaunchError` "no fallback — it IS the feature" contract). Disabled by default (`build_board`→`None`); the Supervisor builds it lazily on first `run_item` (stored on `self._board`, closed in `close()`), **NOT** in `__init__`, so an enabled-but-corrupt board can never break a plain `run` (which never calls `run_item`). 4. **State machine `planned → running → (blocked | review) → done`**, where **`review` vs `done` = "done AND verified"**, load-bearing in `Board.transition`: a move TO `done` requires ≥1 passing structured `Evidence` (a `GateReport` maps to one) OR a human sign-off (`Evidence{kind:"human"}`), else `BoardError` — a bare `board update ID --state done` is rejected (the human CLI path). An AGENT's advisory `state:done` is honored only when **THIS run** produced passing verification (a gate that passed *this* run) — stale evidence from an earlier, now-discarded run does NOT certify the current work (`apply_update` gates the advisory `done` on the run's own evidence, while still persisting the accumulated evidence that backs the human `review→done` promotion); otherwise it is CLAMPED to `review`+audit (**never raises** — a good run is never turned `blocked` by an invalid advisory field). The human path also rejects a manual move INTO `running` (it is owned by the claim lease, never set by hand — `board update` does not offer it). Dependencies gate dispatch; an **atomic claim** (`BEGIN IMMEDIATE` CAS `planned→running`, stamping `lease_run_id`+`claimed_at`) is the no-duplicate-work guard on **every** path (`claim` by-id and `next_runnable` alike — opened in autocommit `isolation_level=None` so writers drive `BEGIN IMMEDIATE`/`COMMIT` by hand; WAL + `busy_timeout`); `human_required` items are excluded from auto-dispatch; FIFO order is `created_at, rowid` (rowid breaks same-clock-tick ties so insertion order holds). Append-only `transitions` audit table. **Stale-claim recovery** `recover_stale_running()` reclaims items past `lease_timeout_seconds` from `running`→`planned` (the `cleanup_orphaned_worktrees`/`_sweep_stale_session_dirs` analogue), run at the top of every `run_item`. The lease is the **fencing token**, not just a dispatch guard (adversarial-review catch): `apply_update(run_id=)` is a **lease-fenced CAS** (`WHERE id=? AND state='running' AND lease_run_id=?`) so a slow run whose item was reclaimed + re-dispatched to another runner can't clobber the new owner or revert a verified `done` — its stale write is dropped; the **crash-block path is fenced the same way** (`Supervisor._block_on_crash` threads `run_id` into `transition(run_id=)`, an identical `WHERE state='running' AND lease_run_id=?` CAS that drops a 0-row match), so a stale *crashed* run can't clobber a re-dispatched owner or revert a verified state either — including a crash AFTER `apply_update` already resolved the item (e.g. Ctrl-C during the shared-memory write), since the item has then left `running`; and `transition` preserves the lease on a *same-state annotate of a running item* (only clearing it when actually leaving `running`) and resolves a no-`--state` annotate's target from its **in-transaction** read (a `to_state=None` sentinel, never a stale pre-read), so a `board update` annotation can't strand a live claim into stale-recovery. Every transactional method rolls back on **any** exception (not only `sqlite3.Error` — e.g. a corrupt-row `ValueError`), so a `BEGIN IMMEDIATE` write lock is never leaked. 5. **The board↔`shared` boundary is closed via a per-run memory scope** — `run_item` runs the item through the normal pipeline with a **board-scoped `SyncmillMemory.scoped(run_id)`** that collapses BOTH the shared namespace AND every per-agent (session/search) namespace to `board-run:{run_id}` (via a single `_agent_ns` seam). So the strategy-internal shares (pipeline/council/decompose) AND `start_task_session`'s prompt-log all write to the per-run scope — intra-run handoff still works — and **nothing board-enriched leaks into the persistent global `shared` or `agent-runtime:*`**. After the strategy returns, `run_item` writes ONE sanitized summary to GLOBAL `shared` via `SyncmillMemory.share_board_result(item_id, task, strip_board_block(output))` (built from the item task + the agent output with the `syncmill-board` block stripped — never the enriched prompt); the **cross-link is the SINGLE composite tag `board-result:{item_id}`** (memtomem `add()` returns no chunk id; `search(tag_filter=...)` is a `str`/comma-OR, NOT a list). Decisions + the handoff baton are injected DETERMINISTICALLY from the board into the prompt, never via top-k recall (**Phase 2 (D4)** additionally has board runs **union-read** global cross-run `shared` — the scoped view's *reads* widen to the real `shared` while its *writes* stay confined to `board-run:{run_id}`, so the leak guard is untouched). The per-run `board-run:{run_id}` scratch namespaces are **GC'd automatically**: `run_item` sweeps them best-effort right after `recover_stale_running` and BEFORE minting its own `run_id` (`Supervisor._gc_board_run_namespaces` — the current run's namespace is a non-candidate *by construction*, and a drained `--loop` call still sweeps). The protocol is **two-phase, enumerate-THEN-lease-read** — `SyncmillMemory.list_board_run_ids()` (prefix-filtered `list_namespace_meta`, `None`=unavailable vs `[]`=healthy-empty, the gateway convention) then `Board.live_lease_run_ids()` (the `running` items' `lease_run_id`s, the do-not-delete set) then `SyncmillMemory.delete_board_runs(dead)` — the ORDER is load-bearing: a namespace only exists after its claim stamps the lease, so enumerating first means any live concurrent run shows up in the later lease read (leases-first would open a claim+write window). **"Holds no lease" is not sufficient on its own:** `recover_stale_running` takes the lease of a run that is merely SLOW, so `collectible_board_run_ids` gives a RECLAIMED run one further lease timeout of grace (the reclaim stamps `board_run_namespaces.reclaimed_at` in the same transaction) — without it the collector deletes the scratch namespace a live pipeline is still handing off through, and the delete succeeds so nothing degrades. A run that left `running` normally has no `reclaimed_at` and is collectible immediately. This **narrows** the race, it does not close it — a run alive past the grace period is still collectable (see the accepted residual race below). Columns added to the board schema after its `CREATE` shipped need an entry in `_ADDED_COLUMNS` (`CREATE TABLE IF NOT EXISTS` is a no-op on an existing db) and must tolerate a **concurrent first open**: the check and the `ALTER` are two statements, so a `duplicate column` `OperationalError` means a racing process already added it and is swallowed (anything else raises). Comments must stay OUT of a `CREATE` body — sqlite stores the statement verbatim and re-parses it on `ALTER TABLE … DROP COLUMN`, where an inline comment truncates the input. `delete_board_runs` reconstructs the `BOARD_RUN_PREFIX` (`memory.py` constant) from bare run_ids, so it can only ever delete `board-run:*` — never `shared`/`agent-runtime:*` (a guard by construction) — via memtomem's per-namespace-transactional `delete_by_namespace` (chunks+FTS+vectors+meta row), continuing past a per-namespace failure. **(Closed residue, memtomem#1705.)** `delete_by_namespace` used to early-return 0 for a CHUNK-LESS namespace without removing its `namespace_metadata` row, leaving a metadata-only scratch namespace (registered, never written) a perpetual sweep candidate. Fixed upstream in 0.3.9 — below syncmill's `>=0.3.12` floor, so every version the pin admits drops the metadata row unconditionally and a zero-chunk delete is a genuine full purge the ledger acknowledges. The return value is still the CHUNK count, so zero remains the normal reading for such a namespace. Single-coupling rule intact: memtomem calls in `memory.py`, the lease SELECT in `board.py` (raises `BoardError` like its siblings), policy in the Supervisor — whose sweep wrapper downgrades EVERYTHING (memory `None`, `BoardError`) to a log line: GC never blocks dispatch. Accepted residual race: a slow live run already past its lease reclaim loses its scratch mid-run — benign (its board write is fence-dropped anyway; memory is advisory; the namespace recreates on the next write). No new config, no gateway change (the read-only 6-tool surface is untouched).

`run_item` flow: `_require_board` (lazy build; clear error if disabled) → `recover_stale_running()` → atomically claim (`claim(id)` or `next_runnable(run_id)`; `None` stops a `--loop` caller) → `Task(prompt=render_item_prompt(item))` → `run(memory=scoped)` → `parse_board_update(result.output)` → `board.apply_update(...)` [advisory] → `share_board_result(...)` to global shared. Wrapped in `try/except BaseException` → a genuine CRASH transitions the item `→ blocked` (`_block_on_crash`, best-effort, sets `human_required`) and re-raises; a FAILED result is **not** a crash (`apply_update` records it as `blocked`). **`--strategy` is NOT a `run_item` param** — the board CLI mutates `config.default_strategy` BEFORE constructing the `Supervisor` (matching how `run` selects a strategy in `__init__`). The CLI `board` group mirrors `session`: `_require_board` (mirror `_require_tmux`) hard-errors when disabled; `add TASK [--goal --depends-on(repeatable) --human-required]` (no `--owner` — `owner_agent` is RECORD-ONLY in v1, stamped from `result.agent_id`), `list [--state --goal]`, `show ID`, `run [--id --loop --strategy --agent --team --goal]` (Phase 4: `--goal <g>` scopes the atomic claim to that goal via `next_runnable(goal=)` — mutually exclusive with `--id` — and auto-applies the team declaring `g`; `--team` overlays a profile pre-`Supervisor` and beats the goal mapping), `update ID [--state --evidence --sign-off --note --clear-human-required]` (the human path; `done` REQUIRES `--evidence`/`--sign-off`). **Hermetic tests:** `tests/test_board.py` drives the REAL `Board` against `tmp_path/"board.db"` with an injected `now` (like `test_breaker.py`) — CRUD/audit, atomic dedup on BOTH paths (two `Board`s/one db → exactly one claims), dep/skip, stale recovery, done-gate, gate→Evidence, advisory-done-clamps, corrupt+unopenable db→`BoardError`, parse/strip tables; `conftest.py` adds a duck-typed `FakeBoard` + `FakeMemory.scoped`/`share_board_result` (the scoped child's shares stay off the parent's global `.shared` — the leak guard); `test_supervisor.py` covers `run_item` (board-scoped-memory leak guard, crash→blocked, lazy build never touched by a plain `run`, `close()` closes the board); `test_cli.py` exercises the `board` subcommands via `CliRunner` with a tmp db. **`Evidence`/`WorkItem`/`WorkState`/`Decision`/`BoardStats` live in `board.py`, not `models.py`** (they never flow through a strategy — the `breaker._AgentState` rule).

**Phase 2 — Collaboration depth + read API** (4 deliverables, one PR; the design grounded against the merged Phase-1 code, which shifted two plan details — see below):
- **D1 Decisions (never-re-litigate).** A separate `decisions` table in the same db (orthogonal to work items — no state machine, no lease): `Board.add_decision(text, *, scope="", supersedes=None)` (atomically retires the superseded one **of the same scope** — a missing/already-retired/cross-scope target raises `BoardError` (same-scope CAS: `WHERE id=? AND superseded_by IS NULL AND scope=?`, so superseding can never silently retire a different goal's decision), and the new decision is NOT inserted; empty text rejected) + `Board.active_decisions(goal=None)` (non-superseded, oldest-first; `goal=None` → all, a goal string → global `scope=""` + that-goal-scoped). `run_item` fetches `active_decisions(goal=item.goal)` and injects the texts via the EXISTING `render_item_prompt(item, active_decisions=)` seam — **deterministic, in full, never top-k**. **Grounded divergence from the plan:** the plan put a `_enrich_with_decisions` helper in `strategies/base.py`, but Phase 1 already shipped the injection seam *inside* `board.py::render_item_prompt`, and a `base.py` helper would force a `board → strategies` import that violates the acyclicity invariant — so the seam stays in `board.py` (no `base.py` helper). The decisions read is **best-effort in `run_item`** (a `BoardError` degrades to no-decisions and logs, never blocks the item — decision injection is advisory prompt enrichment, not load-bearing dispatch). CLI: `board decide "<text>" [--scope --supersedes]`, `board decisions [--goal]`.
- **D2 `board stats`.** `Board.stats(*, now=None, stall_seconds=None) → BoardStats` computed entirely from existing rows + the append-only audit (no new write-path instrumentation): `false_done` (DONE with no passing `Evidence` — an integrity alarm, impossible via the gate), `redispatched` (items with >1 `planned→running` audit row = work a stale reclaim forced a redo — the *materialised* duplicate-work signal; a purely concurrent claim the CAS averts leaves no trace by design and need not be counted), `reclaimed_stale` (count of `recover_stale_running` reclaims, matched by the shared `_STALE_RECLAIM_NOTE`), and aged `blocked`/`human_required`/`dropped_handoffs` (untouched past `stall_seconds`). `BoardConfig.stall_seconds` (≥1, default 3600) is the aging window (`SYNCMILL_BOARD__STALL_SECONDS`); `build_board` threads it into `Board`. CLI: `board stats`; renderer `render_board_stats`.
- **D3 gateway `board_*` read tools.** `build_gateway(memory, *, board=None, …)` registers three MORE read-only tools — `board_list(state, goal, limit)`, `board_get(item_id)`, `board_stats()` — so the exact-tool-set regression guard goes **3 → 6** (`test_exactly_six_readonly_tools`). The tools are registered **unconditionally** (stable surface) and report `_BOARD_DISABLED` when `board is None`; a `BoardError` surfaces as unavailable (per-call, like the shared tools); `board_list` clamps `limit` to `[1, MAX_BOARD_LIMIT=200]` and **validates `state` up front** against the work-item state set (`_VALID_BOARD_STATES`, derived from `WorkState`) — a bad `state` filter is a **client argument error** returned as a corrective message naming the valid states, NOT mislabeled as the board being "unavailable" (which would make an LLM abandon a healthy board; only a genuine backend `BoardError` is "unavailable"). **No board-write MCP tool** (read-only + no-auth posture preserved). **Board id (uuid) validation lives in `board.py`** (the single-coupling rule): `Board.get` now rejects a non-uuid id as not-found WITHOUT a query (mirrors `SyncmillMemory.get_shared`; every real id is a `uuid4`). `serve` builds the board best-effort (a corrupt board degrades the board_* tools with a stderr warning rather than killing the shared gateway) and closes it in the `finally`. Board reads are sync sqlite inside the async MCP handlers (quick — no thread offload).
- **D4 board-run global-`shared` union-read.** A board-scoped `SyncmillMemory` view now captures the REAL global `shared` namespace (`_global_shared_ns`, set in `scoped()`); `search_context` UNION-READs it alongside the per-run scope **only when scoped** — so a board run is enriched by cross-run knowledge (prior `board-result` summaries) while its WRITES stay confined to `board-run:{run_id}` (the leak guard is untouched). A plain (unscoped) run is byte-identical (its `_shared_ns` IS global `shared`).

Testability is structural: `take_snapshot(board, state=, selected_id=, now=) -> BoardSnapshot` is the pure fetch seam (unit-tested against a real Board, no Textual); the interval timer's callback IS `action_refresh` (same path as the `r` key and the post-edit refresh), so `tests/test_dashboard.py` builds apps with `refresh_seconds=3600` and drives every tick explicitly under headless `App.run_test()` — no timer waits, no real TTY; edit-matrix coverage goes through the single write funnel `_apply_update` directly (one modal end-to-end test proves the widget plumbing), and assertions target app-owned seams (`status_text`/`detail_text`/`last_action_error`, plus the TEAM-pane mirrors `team_detail_text`/`last_team_error`), never Textual widget internals (version-shifty across textual's 1.x→8.x majors); the TEAM-pane tests follow the same recipe (funnel-direct matrix + one `TeamEditModal` end-to-end + a `u`-toggle end-to-end, config loaded from a tmp toml via `load_config_at`). `textual` is a direct dependency (floor = the uv-resolved version actually tested); its `rich` comes bundled — don't add rich directly.

### Full TUI command center (`tui.py` + `tui_jobs.py`)

`syncmill tui` is deliberately separate from the compatibility `dashboard` app. It
has Board/Runs/Reports/Teams/Status/Sessions/Rooms tabs and may open with no Board
connection; a disabled or broken board is a limited-mode page, never an excuse to
create a DB. `--tab auto` (default) opens the first ENABLED-and-OPENED surface in
the order Rooms → Board → Runs → Status; an explicit `--tab` is always honored
(store bindings are independent — a corrupt Rooms SQLite must not disable the
filesystem-only Artifacts view). Runs nests Operations (JobStore) / Artifacts
(ArtifactStore, the SAME `project_id(root, config.project.id)` identity the
session store and `syncmill runs list` use) sub-tabs; artifact `g` apply goes
through a detached `ArtifactApplySpec` worker (never in-process), `k` discard runs
in a thread worker (blocking repository apply lock). A Sessions checkpoint lands
on Runs → Artifacts with the run selected. Rooms candidates have d/o/m
Diff/Output/Details views (Diff paged + digest-bound over the WHOLE file via
`RoomStore.load_candidate_patch_head`; failed candidates open on Output). The
global Footer is replaced by a per-tab action bar (two lines, availability-gated);
detail Statics rendering raw agent output/diffs are `markup=False`. Polling
preserves state by construction: `_sync_options`/`_update_static` signature-skip
unchanged content, and `_focus_primary` is only ever called on tab switches.
EVERY poll path is degrade-guarded (`_ROOM_POLL_ERRORS`/`_SESSION_POLL_ERRORS`/
`_JOB_POLL_ERRORS`) — an unguarded read escapes the interval callback and kills
the app, so a store failure must show DEGRADED and keep the last good view.
`JobStore.control` likewise converts everything to `JobError` (its callers catch
only that): the manager can vanish between the poll and the keypress, taking the
token file and leaving a truncated socket reply.
Board reads/writes stay on Textual's thread because SQLite is thread-affine.
Orchestration never runs inside Textual: a pure `BoardJobSpec` becomes the existing
`board run --id` or `board run --loop [--goal]` argv, and `JobStore` launches a
detached POSIX manager. The manager owns per-board `flock`, atomic 0600 job state,
two-segment bounded logs, a token-authenticated Unix socket, and a same-interpreter
Click child in its own process group. `q` only exits the UI. Explicit stop is
SIGINT-first; explicit force after ten seconds is SIGKILL and never fabricates a
Board transition. PID fields are informational only. `Board.renew_claim` plus the
Supervisor's separate-connection heartbeat prevents a healthy run from crossing the
lease timeout and being dispatched twice. Default tests use fake children only.

### Named multi-team profiles (Phase 4 — `[teams.<name>]`, `--team`, `board run --goal`)

Phase 4 generalizes "team" to **named, savable profiles** (`python-team`, `rust-team`, …) — an ordered agent subset + optional capability map + optional strategy + the board goals the team owns. **Profiles are CONFIG, not a store**: a `TeamConfig` dict field `teams: dict[str, TeamConfig]` on `SyncmillConfig` (declared, so root `extra="forbid"` accepts it), written as `[teams.<name>]` tables in `syncmill.toml` — the table name is the **verbatim** team name (hyphens kept, the `[capabilities.agents]` key rule) — or the JSON env form `SYNCMILL_TEAMS='{"python-team": {...}}'` (dict fields don't ride `__` nesting; env teams deep-merge with toml teams). **The mechanism is overlay-before-Supervisor**: `config.apply_team(config, name)` mutates `agent_priority ← team.agents` (subset + order), `capabilities.agents ← team.capabilities` (only when non-empty), and `default_strategy ← team.strategy` (only when set) — post-construction mutation, exactly the `--repo`/`--strategy` pattern — and because `Supervisor.__init__` derives the registry, matcher, and strategy from those fields, **the whole stack follows for free**: no `Strategy`-protocol, registry, or matcher change; agents stay pure. Selection surfaces: `run --team`, `board run --team`, or **automatically by goal** — each profile may declare `goals = [...]` and `board run --goal <g>` (new flag) both **scopes the atomic claim to that goal** (`Board.next_runnable(run_id, goal=)`, an extra WHERE inside the same `BEGIN IMMEDIATE` — threaded via `run_item(goal=)`; `--id`/`--goal` are mutually exclusive) and applies the team declaring `g`. Precedence: **explicit `--team` > goal→team mapping > `default_team` > none** (`default_team` is the P3 TEAM-pane addition below), and an explicit `--strategy` flag beats the profile's strategy. `board run --id` alone also honors the mapping via a **read-only pre-Supervisor peek** of the item's goal (no claim taken — team assignment must not be path-dependent); a plain `board run --loop` (no `--goal`) never applies goal mappings (**one Supervisor = one lineup per invocation**, no per-item rebuild). Validation split (all pre-claim on `board run`, the `--agent`-typo lesson): structural breakage (empty/duplicate `agents`/`goals` entries, empty goal `""` — it would own every goal-less item, a **goal declared by two teams** — insertion-order-dependent selection, rejected hard naming both teams) fails at construction via `TeamConfig` field validators + a root `model_validator`, surfaced cleanly by the CLI's **`_load_config()`** (wraps `SyncmillConfig()`, converting `pydantic.ValidationError` → one-line `ClickException`; used at **every** `SyncmillConfig()` site in `cli.py` — the codex design-review Major, same rationale as `_validate_strategy`); an unknown team name or a profile naming an unknown agent id fails in `cli._apply_team` (BadParameter listing teams / ClickException listing valid agents — `_AGENT_CONSTRUCTORS` import, the established private cross-import); a profile strategy typo rides the widened `_validate_strategy`. A team whose agents are all disabled is NOT a config error (the usual "No agents available" result; `team show` surfaces it). On a monitored run `--team` **is forwarded in `_inner_argv`** (unlike `--monitor`/`--emit-patch` — it's config selection like `--strategy`; omitting it would silently rebuild a team-less inner lineup). Read-only `team list` / `team show <name>` render profiles (enabled/disabled/unknown-agent status) without touching board/tmux/Supervisor, so a broken profile is still inspectable (`team show` now echoes the shared `teamfile.render_team`, byte-identical to the dashboard TEAM pane). Hermetic tests: `test_config.py` (toml/env/deep-merge/validators/`apply_team`/`resolve_goal_team`), `test_board.py` (goal-scoped claim: FIFO skip, atomic dedup, deps/human_required still gate), `test_supervisor.py` (`run_item(goal=)` threading; id-path ignores goal), `test_cli.py` (overlay/precedence matrix, `_load_config` conversion, `_inner_argv` forwarding, peek path against a real tmp board db, `team list/show`).

### Team-profile writing (`teamfile.py`, the P3 TEAM-pane follow-up — `team save`/`use`, `default_team`)

The **first (and only) toml-WRITING module** — a new flat top-level module (gateway/monitor/session/board/dashboard precedent): `team save`/`team use` and the dashboard TEAM pane all funnel through it, while reads stay on pydantic-settings' `TomlConfigSettingsSource`. It lives OUTSIDE `config.py` deliberately (imperative writes don't belong in the declarative-settings module, and the unknown-agent check needs `_AGENT_CONSTRUCTORS` — a `config → agents` import cycle); the import graph stays acyclic: `teamfile → config, agents, artifacts`; `cli → teamfile`; `dashboard → teamfile`. **tomlkit** (new dep) gives comment-preserving round-trips: every write parses the existing document, mutates the smallest span, dumps, and lands via a temp+`os.replace` atomic write (the breaker/board recipe) — a failed write can never truncate `syncmill.toml`. **Atomicity is not enough on its own**, so every write also runs inside `config_write_lock(path)` — a BLOCKING cross-process lock delegating to `artifacts._cross_process_lock` (already re-entrant per thread, fork-guarded, `flock`/`msvcrt`). Atomic replace only guarantees no reader sees a half-written file; it does nothing about two writers each parsing the document and the second replace discarding the first's table — the lost update `team save` racing the dashboard/TUI TEAM pane (or `init --force`) actually produced. Blocking, not fail-fast (the `JobStore` never-wait rule is about *probing* a live holder): the critical section is one sub-millisecond parse-mutate-dump, so a waiter serializes invisibly where a busy error would surface a benign micro-race the user can do nothing about. `save_team`/`set_default_team`/`write_document` take it internally (so `project.py`'s `init` merge is covered too — it holds it across its own read→write), and the four callers that read-then-write (`team save`'s validate→save, `team use`'s `file_team_names`→set, the dashboard and TUI TEAM panes) hold it across the whole span, which re-entrancy makes free. **Only the acquisition is wrapped into `TeamFileError`** — a body failure keeps its own identity rather than being relabelled a locking one — and the lock file is never unlinked (a fresh inode per acquire would let two writers hold two different locks). **The lock path took two revisions to get right, and `_lock_path_for`'s docstring is the record.** It must be (a) DERIVED, never probed — a first attempt asked `git rev-parse --git-common-dir`, which made the lock's identity depend on a subprocess, so a writer without `git` (or with a read-only common dir) picks a different file and two locks serialize nothing; and (b) OUT of the working tree — a second attempt put it beside the config with a `.git/info/exclude` rule written by `init`, but that file is machine-local, so any clone or un-re-`init`ed upgrade drops an untracked lock into `git status` and into every agent worktree (snapshots capture untracked files). It now lives in syncmill's own state root (`~/.syncmill/locks/`, the board-db/breaker precedent) keyed by a sha256 of the config's **realpath**, so two routes to one file share a lock; an unresolvable/unwritable root is a `TeamFileError` (the `Board` precedent). Knowingly traded: the path is per-USER, so two OS users editing one shared config are not serialized — the rare case, degrading to the pre-lock behavior, in exchange for universal correctness in the case that actually happens. That primitive's `fchmod` is also now skipped where the call does not exist (Windows), since an `AttributeError` there is outside its `OSError` guard and would fail every config write before the lock was taken. `set_default_team(path, None)` checks for a missing file BEFORE locking, so `team use --clear` still touches nothing. `save_team` replaces `[teams.<name>]` **wholesale** (the flags/modal define the FULL profile — a partial merge could not express "clear goals"; only the replaced table's own comments are lost), emitting `strategy`/`goals`/`[teams.<name>.capabilities]` only when set/non-empty; tomlkit places a new top-level scalar BEFORE the first table (regression-tested in `set_default_team` — appended after `[teams.x]` it would re-parse as that table's member). The write target is `toml_path()` — derived from `SyncmillConfig.model_config["toml_file"]`, so write and discovery are the SAME file by construction (and the hermetic suite's autouse `isolate_toml_discovery` repoint automatically isolates every save test — a forgotten repoint writes to an absent tmp path, never the repo root). **Validation is two-view** (a codex pre-code design-review Major): `validate_team_save` runs the shared `config.check_team_goals` (extracted from the `_validate_teams` model validator so the rule can't drift) over BOTH the RESOLVED env+toml view with the candidate substituted (guarantees the next `_load_config()` under the current env can't die) AND the FILE-standing-alone view (an env override deep-merges above the file and can mask a dup-goal that would brick `_load_config` once that env is removed). `TeamFileError` is the single error type at the seam (the `BoardError` contract): the CLI converts flag-shaped failures to `BadParameter` and config/write failures to `ClickException` (the `_apply_team` split); the dashboard mirrors it into `last_team_error`. **`default_team`** (`team use <name>` / `--clear`; env `SYNCMILL_DEFAULT_TEAM`) is a plain `SyncmillConfig` field deliberately NOT validated against `teams` at construction — a dangling value must not brick every command *including its own fix* (`team use --clear` skips `_load_config()` entirely for the same reason); `run`/`board run` apply it via `cli._apply_default_team` (no explicit `--team` → overlay + a clean dangling-default `ClickException` naming the fix), an empty string counts as unset (the `-r ""` house rule), and the banner/echo says `(default)`. `team use` with an env-only team (resolves via `SYNCMILL_TEAMS` but absent from the file) warns that the persisted default dangles without that env (another codex Major — warn, not reject); `team save`/`use` also print env-shadow advisories when `SYNCMILL_TEAMS`/`SYNCMILL_DEFAULT_TEAM` are set. On a monitored run the resolved default rides the EXISTING `--team` forwarding (it's resolved into the same local `team` variable before `_launch_monitor_if_requested`), so `_inner_argv` is unchanged. `load_config_at(path)` (a one-off subclass pinning `toml_file`, global `model_config` never mutated) is the dashboard's post-write reload seam. Hermetic tests: `test_teamfile.py` (round-trip comment preservation, wholesale replace, both-view validation incl. the env-masked file conflict, `set_default_team` placement regression, atomic-write failure, the lock matrix — private lock file, re-entrant caller span, acquisition-failure conversion, body failures not relabelled, plus a real two-process lost-update regression under `skipif(no POSIX flock)` — `parse_capability_specs`, `render_team`, `load_config_at`), `test_config.py` (`default_team` env>toml, dangling-does-not-fail-construction), `test_cli.py` (save/use matrix, precedence incl. `board run` goal/peek/default, dangling-default error, `--monitor` forwards the default, `team show` byte-identity), `test_dashboard.py` (TEAM pane below).

### Run reports (`report.py` — run identity S2 + the envelope writer S3 of the ecosystem plan)

`report.py` is the flat module for the **run-envelope join artifact** of the toolgraph/tracegraph/syncmill ecosystem (`contracts/run-envelope.schema.json`, shipped with fixtures + `tests/test_contracts.py` in S1). Two halves. **Identity (S2):** `resolve_run_id(explicit)` is the single resolver every path converges on — precedence **explicit > monitor-inner env > fresh uuid4**: board `run_item` passes its lease/scope run_id (lease, `board-run:{run_id}` memory scope, and envelope are provably ONE id — no double issuance); a monitored run's OUTER mints the id (it never builds a Supervisor) and propagates it via the 0600 env snapshot as `SYNCMILL_RUN_ID` (never argv), honored ONLY when `inner_dir()`'s env-var+sentinel double-check confirms this process is the in-tmux inner (a stray exported `SYNCMILL_RUN_ID` can never leak into a normal run); a direct run mints fresh. **Writer (S3):** `build_reporter(config.integration.report)` returns **`None` when disabled (the default — zero filesystem touch, byte-identical behavior)**; enabled, the Supervisor-built `RunReporter` writes `{runs_dir}/{run_id}/envelope.json` (default `~/.syncmill/runs`) — `start()` right after the candidate lineup exists (retention sweep + a **fully schema-VALID skeleton**: honest `result.status:"failed"`, `finished_at == created_at`, every sub-block present — `finished_at` is required non-nullable, so even a SIGKILL'd run leaves a parseable artifact for the contract's strict consumers), `finish()` **first in `run`'s `finally`** — before `monitor.finish` (whose result.json unblocks the OUTER, whose report-path print is existence-gated) and before `pool.cleanup_all()` (no worktree race: patch/files_changed were already captured by `_collect_files_changed`). The envelope is **body-free by contract**: digests (`sha256:<64hex>`) and counts only — never prompts/output/patch content/file-path lists; `finish` writes the one body-carrying artifact `result.json` into the run dir via **`monitor._result_to_json`** (the mandated private cross-import, `session.py` precedent, so the payload can't drift from the monitor's IPC file), digests the exact bytes written, and digests the patch over the same surrogateescape bytes `emit_patch_file` writes (the digest verifies the actual `--emit-patch` file). **Everything degrades** (the memory idiom): `RunReporter` methods catch `(OSError, ValueError, RuntimeError)` (RuntimeError = no-HOME `expanduser`, the board lesson) and warn; the Supervisor wraps `start`/`finish` in belt-and-suspenders `except Exception` guards (the `monitor.finish` discipline) so nothing report-shaped can ever skip the memory-session close or worktree cleanup. **Not threaded into `Strategy.execute`** — the reporter is Supervisor-run-lifecycle-level like `_matched_order`/the board (it only consumes the returned `TaskResult`); agents stay pure. **3-path unification:** direct — the Supervisor writes it and the CLI prints `[syncmill] report: <path>` from the `supervisor.last_report_path` seam after `render_task_result`; monitored — the INNER (the real Supervisor) writes under the OUTER-minted id and the OUTER prints the same line after `render_result`, **gated on the envelope actually existing** (the OUTER can't know the inner's config; `launch_monitored_run(report_runs_dir=)` takes a plain path — monitor never imports report, acyclic); board — `run_item` best-effort **patches the `board` block** (`patch_envelope_board`, a read-modify-write atomic rewrite) after `apply_update`, deliberately NOT gated on the lease fence (the fence protects the board/shared system of record; the envelope records what THIS run worked on) — on a crash the block honestly stays `null`. The envelope's `team` comes from **`config.applied_team`**, stamped by `apply_team` (covers direct/inner-forwarded/board paths by construction); `degraded` lists the run's degraded best-effort subsystems (`memory`, `breaker` — open vocabulary). **Retention** is Supervisor-level, never the CLI (it must cover all three producer paths): oldest owned run dirs beyond `keep_last` (≥1, default 50, counting the current run) are removed, the current run_id always excluded, each removal independent, and **only directories syncmill marked as its own** are candidates at all, since `runs_dir` is free-form user config and an unmarked dir is somebody else's data (the `monitor.py`/`session.py` sentinel rule). The marker is `RUN_DIR_SENTINEL`, written by BOTH producers — `RunReporter._ensure_run_dir` and `FileTracer._write` (the trace-only path creates the dir itself, so `tracer` imports that one constant from `report`; acyclic, since `report` never imports `tracer`). Run dirs predating the marker are accepted via their envelope, but **only** when it parses, carries syncmill's `kind`, AND names its own directory — a filename alone is never ownership (`result.json` is as generic as names get, and a foreign dir holding one must survive). `_sweep_retention` has **two callers** sharing that one implementation so the semantics can't drift — `RunReporter.start()` when reporting is on, and the public `sweep_runs_dir(runs_dir, keep_last, current_run_id)` wrapper the Supervisor calls when reporting is OFF but tracing is on (the tracer's default dir is this same tree, so `build_reporter`'s `None` would otherwise leave it unowned; see the tracer section). The wrapper degrades on every **ordinary** exception (`except Exception` inside, no caller guard) rather than relying on a belt-and-suspenders call site like `start`/`finish`, because it is called *inside* `run`'s try — whose `except BaseException` marks the run artifact recovery-required, so a raising sweep would falsely condemn a healthy run. `BaseException` is deliberately not caught: an interrupt belongs to that finalization path. **Atomic writes use the breaker `mkstemp` recipe** (unique temp in the same dir + `os.replace` — collision-safe for a `finish`/`patch_envelope_board` overlap, unlike monitor's single-owner `.tmp` sibling). The run dir's lifetime is retention-owned — never couple it to `_gc_board_run_namespaces` (the memtomem scratch GC). Read surface: `syncmill report list` / `report show <run_id>` (`list_reports`/`load_envelope`/`render_report`) are **read-only viewers that work while writing is disabled** (the `team list` posture). Config: `[integration.report]` / `SYNCMILL_INTEGRATION__REPORT__ENABLED` — `IntegrationConfig` nests `report` because the design doc reserves sibling `[integration.*]` tables for the tracer/toolgraph stages (`[integration.trace]` shipped as S3′ and `[integration.toolgraph]` as S5, both below — sub-blocks are ALWAYS present, consumers never branch on absence; `finish(trace=, preflight=)` merges the real blocks over the skeleton's disabled defaults, which stay `disabled` on the SIGKILL path). Hermetic tests validate **every generated envelope against the real schema + the `test_contracts` redaction `_scan`** (`test_report.py` writer/retention/digest-stability matrix, `test_supervisor.py` per-path goldens incl. the inner seam + crash + degrade-never-strands-cleanup + reporter-before-monitor ordering, `test_cli.py` report group + report-line + OUTER pass-through, `test_monitor.py` existence-gated print).

### Trace export (`tracer.py` — S3′ of the ecosystem plan)

`tracer.py` is the flat module for the **OTLP-JSON trace exporter** — spans tracegraph ingests with zero adapter changes (`tracegraph ingest-otlp <file>`), because syncmill emits the exact three attributes its `OTLPSpanAdapter` consumes (`openinference.span.kind`, `graph.node.id`, `graph.node.parent_id`) plus an additive `syncmill.*` **allowlist** tracegraph ignores. The emitted document shape is **pinned byte-level by tracegraph's T1 generators** (`examples/syncmill_otlp_traces.py` + its goldens) — protobuf-JSON attr encoding (`intValue` carries int64 as a *string*; bool checked before int), span `name` as a **stable structural label** (agent ids/phases/indices, never uuids/timestamps — tracegraph `diff`/AHU labels on `name`, so an unstable name makes every diff a divergence), flat `parentSpanId` containment under the run root (causality rides `graph.node.parent_id` + span `links`, never `parentSpanId` and never timestamps), and bounded error messages (`timeout` | `exit_code=N` | `gate: <summary>` — raw output is forbidden). **Retrospective recorder, not live spans:** strategies append completed `SpanRecord`s right after each attempt/fan-out returns (the same shared-loop boundary as `_breaker_record` — a live tracer would penetrate the agent layer), with `start ≈ end − duration_seconds` (safe: tracegraph never promotes timestamps to causality). **All five strategies are instrumented** (route + compete in S3′; pipeline/council/decompose in S6). The span builders live in `strategies/base.py` (the single generalized `_attempt_span` — `phase=`/`name=`/`round_no=`/`links=` params cover stage/propose/critique/synthesize/plan/subtask — plus `_gate_span`/`_select_span` beside the `_monitor_*` helpers) so link/naming semantics can't drift between strategies; builders put **bare-suffix keys** in `attrs` and `FileTracer.flush()` prefixes `syncmill.` + enforces the allowlist + injects `run_id`/`schema_version`, so a builder can never leak a body-shaped attribute. Semantics locked by the T1 goldens + the design's §2.3 span table: route attempt `node_id=attempt:{agent}:{i}` with parent = the **previous failed attempt** (fallback = caused by the prior failure); compete attempts `attempt:{agent}` all parent on `run` (completion order is never causal), `worktree_slot` = fan-out index; **attempt spans carry the RAW pre-gate status** (snapshot taken before `_gate_accepts`/`_select_winner` mutate results in place — a gate rejection is a quality verdict, same reason the breaker records raw; council/decompose snapshot duration too, since the winner's `duration_seconds` is mutated to the phase-summed wall-clock); gate spans (`TOOL`, parent = their attempt) exist only for candidates actually gated (the lazy `_select_winner` prefix); the `select` span parents on the **winning attempt** and links **every other raw-COMPLETED candidate** (the golden reading of "examined" — computable without changing lazy `_select_winner`; a timed-out sibling is never linked; a gate-rejected raw-completer is). **S6 semantics:** pipeline stages `stage:{i}:{agent}` chain on the previous stage (the chain IS the causality; a broken stage leaves its span and stops; the gate-accepted final stage carries `winner`/`files_changed_count` with its OWN pre-sum duration, its verdict on a `gate:{agent}:{i}` span; no slot, no select). Council: `propose:{agent}` fans out from `run` (the one fresh-worktree phase → slot); `critique:{agent}:{r}` (attr `round`) and `synthesize:{agent}` parent on that member's OWN previous-phase node (**worktree continuity** — a FAILED critique still becomes the next parent) while `links` carry the previous phase's **PUBLISHED** (COMPLETED → shared) nodes — declared availability, never claimed consumption (the design's finding-6 approximation: the handoff is relevance-ranked best-effort search, so actual consumption is unknowable). Decompose: `plan` is the hub (name `plan:{planner}`, recorded even FAILED — the degraded whole-task subtask still parents on it); `subtask:{i}` parents on `plan` (name `subtask:{i}:{agent}` — the round-robin repeats agent ids, so the diff-stable label needs the index; slot=i); `synthesize:{agent}` parents on `plan` linking the COMPLETED subtask nodes (fresh worktrees → slot). Council/decompose reuse compete's select-span semantics on the synthesize candidates; an **early aggregate-failure** (no council members / no completed subtasks) leaves **no select span** — selection never ran, distinct from ran-but-nobody-won (select parents `run`). `syncmill.status` is derived (`TaskStatus` has no TIMEOUT: `error.startswith("Timed out after")` is the only timeout signal; `cancelled` is contract vocabulary but unreachable — a cancelled agent re-raises, never becomes a TaskResult); `syncmill.exit_code` only when `>= 0` (the `-1` sentinel is noise); `files_changed_count`/`winner` stamped on the winner only (losers' worktrees are never diffed — a deliberate divergence from the synthetic goldens, which are a shape contract, not an attr-value contract). **Wiring:** `build_tracer(config.integration.trace, run_id=, fallback_dir=config.integration.report.runs_dir)` returns **`None` when disabled** (the default — byte-identical off path); `fallback_dir` is a deliberate signature addition (`dir=""` means "the report runs_dir" and only the Supervisor sees `ReportConfig`); `otlp-http` keeps the durable file and additionally streams completed body-free spans to Phoenix through the optional exporter; streaming failures and queue drops degrade to warnings/receipts without failing the run. `include_output` remains warn+ignore in `build_tracer` (once per run), not a config validator (which would fire on every construction). The Supervisor records the `syncmill.run` root span in its `finally` (final status known there) and flushes **before `reporter.finish`** (which digests the artifact into the envelope `trace` block: `{status:"ok", protocol:"otlp-json-file", trace_id, artifact:"trace.otlp.json", digest}`) — both guarded so nothing trace-shaped can skip the memory-session close or `pool.cleanup_all()`; a flush failure yields `trace:{status:"error"}` + `"trace"` in the envelope `degraded` array. `FileTracer.flush()` is **all-or-nothing** (buffer + mkstemp/`os.replace` — `OTLPSpanAdapter` raises on partial documents, dangling parents, duplicate spanIds; a dangling link/duplicate node_id degrades with a warning rather than emitting a rejectable file). **Trace-only retention** (closing the v1 residue): trace enabled + report disabled used to leave `{runs_dir}/{run_id}` dirs holding only trace files un-swept forever, since retention rode `reporter.start` and `build_reporter` returns `None`. The Supervisor now calls `report.sweep_runs_dir` under `report.keep_last` when `reporter is None ∧ tracer is not None ∧ not trace.dir` — one `keep_last` bounds SyncMill-owned run directories whichever producer fills them. Placement is load-bearing: **FIRST statement inside `run`'s `try`**, not before it, so a `KeyboardInterrupt`/`SystemExit` mid-sweep still enters finalization — the `except BaseException` recovery path and the `finally`'s trace flush — instead of escaping the lifecycle entirely (note that path *retains* the workspace via `pool.retain()`, making `cleanup_all` a deliberate no-op; the point is that finalization runs, not that worktrees are removed); and being inside the try (after the snapshot-capture and artifact-init early returns at supervisor.py:505/:557) means an early return can never prune old runs while producing no trace of its own. `tracer is not None` — not `trace.enabled` — so a degraded `build_tracer` (unresolvable `~`) also keeps the both-off path at zero filesystem touch. The strict-preflight branch needs no sweep: `_validate_strict_reporting` rejects `toolgraph.mode=strict` without `report.enabled`, so it is always reporter-backed. **Remaining deliberate residue:** a custom `trace.dir` is NEVER swept — a user-pointed directory is user-owned and may hold more than run dirs, so syncmill won't delete inside it. Hermetic tests never import tracegraph: a **pure-python mini-validator** (`test_supervisor._mini_validate_otlp`) mirrors the adapter's raise conditions, `test_tracer.py` pins the document shape against the T1 contract, and the strategy tests drive `FakeTracer` (conftest, the FakeMonitor template) through all five `_run_*` helpers (plus a real-FileTracer decompose E2E covering the round-robin node-uniqueness risk).

### Advisory preflight (`preflight.py` — S5 of the ecosystem plan)

`preflight.py` is the flat module for **toolgraph advisory preflight**: before dispatching a strategy, the Supervisor optionally runs `toolgraph preflight` **once** — for the **lead matched agent's** mapped toolgraph identity — to check the run's ambient MCP surface (memtomem, syncmill's own read-only `serve` gateway) against toolgraph's policy graph. **Advisory only**: EVERY failure class (binary absent, timeout, non-zero exit, bad JSON, unknown major `schema_version`, all-unmapped identity) degrades to a **yellow CLI warning** and the run **CONTINUES** — preflight never blocks or aborts orchestration (the memory idiom). `build`-idiom: `run_preflight(cfg, *, run_id, agent_ids, out_dir)` returns **`None` when disabled** (the default — no subprocess, byte-identical behavior) and otherwise **NEVER raises** (a last-resort `except Exception` net wraps the inner). **Lead-agent single call** (maintainer decision): all `agent_ids` are mapped locally through `agent_map` (verbatim real-id keys — `kimi-code`, the `[capabilities.agents]` rule), every unmapped id emits a warning, and the FIRST mapped identity is the one probed (`agent_map` empty / nothing mapped → `unresolved_identity` block + warning, **no subprocess**). Per-agent fan-out is deliberately deferred (the envelope has ONE `preflight` block; per-agent would need block-aggregation semantics the schema doesn't define — recorded as a possible future extension). **argv only, no stdin** — `_build_request` produces the `contracts/preflight-request.schema.json` shape and `_request_argv` serializes it as `command + [agent, *candidate_tools, --profile, --run-id, --out]` (`command` is the test/override seam; the subprocess lookup site is `syncmill.preflight._sync_run` (the shared owned-process-group runner)). **The subprocess ALWAYS writes `--out` to a tempdir**; only a validated artifact (`schema_version == 1`) is then **atomically copied** into the run dir as `preflight.json` (the report `mkstemp`+`os.replace` recipe) + digested, so a rejected artifact never lingers in the run dir and the envelope digest covers the exact copied bytes. **Decision → envelope status**: `advisory_allow`/`advisory_warn` → `"ok"` (+`warning_count` = number of rejected rows); `unresolved_identity` → `"unresolved_identity"`; timeout → `"timeout"`; every other failure → `"error"`. `out_dir=None` (report disabled) still runs the probe (its identity warning is the whole tier-1 value) but discards the artifact (`artifact_path=None` — nothing pretends an artifact exists). **Wiring** (Supervisor `run`, S5): called once AFTER `_matched_order` + the empty-agents guard + `reporter.start`, **OUTSIDE the try/finally** (so it can never affect cleanup — the design's "preflight runs before the try block"); `self.preflight_warnings` (reset per run, the `last_report_path` seam) feeds a yellow `click.secho` block in the CLI beside the memory/breaker degrade notices; the block rides into the envelope via `reporter.finish(preflight=)` (the same skeleton-merge pattern as `trace=` — the skeleton stays `{"status":"disabled"}` so a SIGKILL'd run honestly reports neither). **Config** `[integration.toolgraph]` / `SYNCMILL_INTEGRATION__TOOLGRAPH__*`: `enabled=False`, `mode="advisory"` (a `field_validator` **rejects** `"strict"` — enforcement is reserved for P3.1, the `_make_strategy` hard-fail style), `profile ∈ {strict,review,explore}`, `timeout_seconds≥1`, `command`, `candidate_tools` (server-qualified `server::tool` keys — the ambient MCP surface an operator wants policy-checked), `agent_map: dict[str,str]` (verbatim keys, JSON-object env form). Hermetic tests never need the toolgraph binary or Neo4j: `test_preflight.py` monkeypatches `syncmill.preflight._sync_run` with a fake that writes one **vendored golden** (`tests/fixtures/toolgraph/preflight-{allow,warn,unresolved-identity,additive,v2}.json`) to the `--out` path, driving the decision/failure matrix (v2 rejected + not copied, additive tolerated, byte-identical copy + digest, hyphenated-key verbatim mapping, all-unmapped no-subprocess, `out_dir=None` discards); `test_supervisor.py` covers the envelope block + warning surfacing + failure-continues-and-cleans-up + disabled-skeleton; `_build_request` validates against the request schema.

### Config (`config.py`)

`SyncmillConfig` is pydantic-settings. Config resolves from three layers, **precedence env > file > defaults** (#11): `SYNCMILL_*` env vars (nested delimiter `__`, e.g. `SYNCMILL_CLAUDE__TIMEOUT_SECONDS`) override a project `syncmill.toml`, which overrides field defaults — so **every field stays env-overridable** (the long-standing invariant) while a checked-in `syncmill.toml` gives a project baseline. The seam is `settings_customise_sources`, which returns the source tuple **in precedence order** (`init_settings, env_settings, dotenv_settings, TomlConfigSettingsSource, file_secret_settings`) — env above the toml source, the toml source above defaults; **`init_settings` stays at the top**, so explicit constructor kwargs win (the programmatic/test path, e.g. `SyncmillConfig(default_strategy="pipeline")`). The CLI flags `--repo`/`--strategy`/`--timeout` do **not** ride that init source — `run` builds a bare `SyncmillConfig()` then **mutates the built config post-construction** (`config.repo_root = repo`, etc.), each only when the flag is actually passed; assigning onto the resolved object trivially overrides every source regardless of tuple order. Sources **deep-merge** nested tables, so an env override of one nested field (e.g. `SYNCMILL_CLAUDE__TIMEOUT_SECONDS`) leaves the rest of that `[claude]` table from the file intact. **Discovery is cwd-relative** (`toml_file="syncmill.toml"`) — not `repo_root`, which the file itself can set (chicken-and-egg); a missing file is silently empty. TOML mirrors env naming exactly: per-agent tables use the **field** name (`[kimi_code]`, underscored), while `[capabilities.agents]` is keyed by the **real agent id** (`kimi-code`, verbatim) — the same underscore-field-vs-verbatim-dict-key split as the env layer. Unknown **top-level** toml keys are rejected (root config is `extra`-default `forbid` → typo protection); per-agent sub-tables stay lenient (`extra="ignore"`). The CLI's `--repo` defaults to `None` (not `"."`) precisely so an unset flag lets `repo_root` come from the file/env instead of clobbering it; orphan cleanup then uses the resolved `config.repo_root`, not the raw flag. `default_team` (P3 TEAM pane) is the one field deliberately NOT cross-validated at construction (a dangling value must not brick `team use --clear`, its own fix — see the teamfile section); `syncmill.toml` is also now WRITTEN by `team save`/`team use`/the dashboard TEAM pane, always through `teamfile.py` (tomlkit round-trip — never hand-serialize toml elsewhere). Ship `syncmill.toml.example` as the copyable reference; **never commit a real `syncmill.toml`** at the repo root — the hermetic suite builds `SyncmillConfig()` from cwd=repo-root and would pick it up.

### Worktrees (`worktree.py`)

Normal Supervisor runs create a private snapshot under `<workspace.root>/<run-id>/` and place worktrees at `<workspace.root>/<run-id>/worktrees/{agent}-{taskid}-{slot}` on branch `syncmill/{agent}/{taskid}-{slot}`. The sibling `../.syncmill-worktrees/` and tempdir fallback belong to the legacy/non-snapshot helper path; production `run` rejects unsafe or non-Git input before that path. The `{slot}` is a per-acquire counter `WorktreePool` threads into `create_worktree`: most strategies acquire one worktree per agent, but `DecomposeStrategy` acquires several for the **same** agent (planner + per-subtask + per-synthesizer), and without the slot the second `git worktree add` for that agent would collide on the existing branch/path, fail, and silently fall back to an empty tempdir — so the slot keeps every acquisition a distinct, real git worktree. A run's worktrees are managed by a **`WorktreePool`**: the Supervisor owns one per run and calls `cleanup_all()` in `finally` (each removal independent, so one stuck worktree can't strand the rest), while the *strategy* decides topology — `RouteStrategy`, `CompeteStrategy`, and `CouncilStrategy` `acquire` one isolated worktree per agent so parallel agents never clobber each other and each result's `files_changed` is its own (Council reuses each agent's single worktree across all its propose/critique/synthesize phases); `PipelineStrategy` acquires a single shared one so stages hand files down the chain; `DecomposeStrategy` acquires the most — a scratch worktree for the planner, one per subtask (concurrent isolation), and a fresh one per synthesizer — all normally torn down the same way (the winner's diff comes from its own synthesis worktree; recovery retention is exempt). Two sweeps cover crash leftovers, because the two layouts live in different places: `cleanup_orphaned_worktrees` handles the legacy in-repo `.syncmill-worktrees` layout, and `sweep_orphaned_workspaces` handles the snapshot workspaces under `workspace.root` (the live path — a SIGKILL skips `cleanup_all` and nothing else reclaims the control clone). The latter needs three guards because `workspace.root` is shared with room and interactive-session workspaces that legitimately outlive a run. A dir is a candidate only if it carries the `.syncmill-run` sentinel, written by `capture_repository_snapshot(sweepable=True)` **as soon as the directory exists, BEFORE the clone** — the slow part an interrupt lands in, and an unmarked leftover is one the sweep can never reclaim (rooms/sessions pass `sweepable=False`, so their workspaces are never candidates). `retain()` **adds** `.syncmill-recovery` rather than removing the run sentinel (creating a file is likelier to succeed than deleting one, and the exemption must survive for a LATER process to honor). And liveness is **the owning pid, asked directly** (`os.kill(pid, 0)`), never inferred from file timestamps: two successive review rounds found mtime heuristics deleting live workspaces, because an agent thinking for hours writes nothing and any bounded scan understates activity — the direction that destroys work. `acquire` rewrites the sentinel, refreshing both pid and mtime. Age survives ONLY as the pid-reuse backstop (`workspace.stale_seconds`, a week by default; the three `cli.py` sweep call sites pass it, and `_STALE_WORKSPACE_SECONDS` remains the function default for direct callers): a dead owner whose pid was recycled would otherwise be protected forever, so a live pid stops counting once nothing has touched the workspace for that long. The config floor is an hour precisely because this value **overrides a live pid** — it is the one knob whose misconfiguration deletes a running run's workspace, so it is bounded rather than free-form. A sentinel with no pid (an older version's) falls back to age alone. The Supervisor's pool creation is itself inside a try/except that cleans the workspace on any setup failure — the run's own `try/finally` starts later, after constructions (artifact store, monitor, tracer) that can raise. Because a normally finalized run tears down its worktrees, the winner's code survives durably as `TaskResult.patch` — a full applyable diff `_collect_files_changed` captures at the same seam as `files_changed` (via `_git_diff_patch`: `git add -A` then `git diff --binary --cached`, so untracked files are included; run strictly AFTER the file listing, since staging empties the untracked list). `run --emit-patch <file>` exports it (`emit_patch_file`, beside `render_result` in `monitor.py`, consuming the same result.json contract); on a monitored run the flag is OUTER-owned — never in `_inner_argv`, written from result.json's `patch` field. `syncmill run` still never auto-applies a diff; explicit `syncmill apply` performs the reviewed application.

## Design invariants (the maintainer cares about these)

- **Don't pre-abstract.** The package stays flat until the code demands a split. The **first** justified split was `strategies/` (#12), carved out only after all four strategies (Route/Pipeline/Compete/Council) had landed and `supervisor.py` had grown past ~960 lines — the real code pressure the issue gated on, not a speculative one. Everything else stays as top-level modules under `src/syncmill/`; don't carve out further subpackages until they demand it the same way.
- **memtomem is the default PyPI memory dependency; mem0 and LangGraph SQLite are optional extras.** Use the runtime adapters, never reimplement their storage. `memory_migration.py` is the one sanctioned maintenance exception: it owns private enumerate/import/delete primitives unavailable on the runtime contract, with fake-SDK boundary tests and required real integration smokes. **autocli** is a pattern reference only, not a dependency.
- **No `health_check` on agents.** Run, and fall back on failure. Don't add liveness probes to the agent contract. The circuit breaker (#8) is **not** an exception: it skips an OPEN agent based on its *recorded past failures*, never by calling the agent to test it — reactive memory of failure, not a probe.
- **Sync-first orchestration.** `CLIAgent` exposes *both* a sync `execute` (`subprocess.run`) and an async `aexecute` twin (`asyncio.create_subprocess_exec`, plus the `aexecute_all` / `aexecute_isolated` / `aexecute_each` fan-out helpers — the last two sharing one cancel-drain tail, `_gather_or_drain`, so they can't drift) — but the Supervisor and the sequential strategies (route, pipeline) still call only `execute` and stay fully sync. `run_async` bridges memtomem **and** the concurrent path: `CompeteStrategy`, `CouncilStrategy`, and `DecomposeStrategy` are the live consumers — they call `run_async(aexecute_isolated(...))` / `run_async(aexecute_each(...))` to fan agents out over `aexecute` (Council does so once per phase: propose, each critique round, then synthesize; Decompose runs its planner step **sync** via `execute` — a single sequential step needs no fan-out — then fans out the concurrent subtask phase via `aexecute_each` and the synthesis phase via `aexecute_isolated`). The shared-loop rule still holds: do all memory I/O strictly **before/after** each fan-out, never `run_async` from inside the gathered coroutines (that re-enters the running loop) — Council's and Decompose's per-phase `search_context`/`share_result` calls all sit between their fan-outs, never inside them. `aexecute` + per-agent worktrees are the foundation any further concurrent strategy will await; `aexecute_each` (distinct prompt per agent) is the new shape Decompose added beside `aexecute_isolated` (one prompt broadcast to all); its optional `labels=` gives each fan-out ITEM its own live-monitor stream key via the ambient `_SINK_LABEL` ContextVar (set per item immediately before `ensure_future`, so each Task copies its own) — needed only by Decompose, whose round-robin runs one agent several times concurrently and would otherwise interleave two subtasks byte-wise into one log and one pane. Unlabeled callers are byte-identical (the key stays the agent id), and the agent contract is untouched. Don't async-ify the Supervisor or the sequential strategies until a concurrent strategy actually needs it. The two paths share success/failure classification via `_build_result`/`_failure`, so they can't drift; **both decode with `errors="replace"`** — an agent CLI emitting non-UTF-8 must never raise `UnicodeDecodeError` (a `ValueError` no handler catches, which would escape `execute` and fail the whole run); the deliberate divergences are (a) a timed-out `aexecute` reports empty output (asyncio discards a killed child's buffer) where `execute` keeps `TimeoutExpired.stdout`, and (b) when a live-monitor sink is active (#16, the `_OUTPUT_SINK` contextvar seam) `aexecute` tees output through `_communicate_teed` instead of `communicate()` — same `TaskResult`, but the sink/log sees pre-timeout bytes on a teed timeout (the log is a live view, the result is the contract); with no sink it's byte-for-byte the original path. See the live-monitor section.
- When adding an agent, **verify the real CLI's JSON output format with an actual run first** — CLIs return errors in non-obvious ways (e.g. Claude can exit 0 while returning `{"is_error": true}`, which `ClaudeAgent._is_error_output` specifically catches).
