# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

syncmill orchestrates multiple CLI coding agents (Claude Code, Codex CLI, Kimi Code) over a single task, giving them a shared long-term memory (memtomem) so they collaborate and compete. It ships five orchestration strategies — `route` (priority fallback), `pipeline` (sequential chain), `compete` (concurrent head-to-head), `council` (multi-round propose → critique → synthesize deliberation), and `decompose` (split the task into subtasks, run them across agents concurrently, then synthesize) — and the architecture is built to grow more.

## Commands

```bash
uv sync                              # install deps + create .venv (uses uv, Python 3.12)
uv run syncmill run "<prompt>"       # run a task through the orchestration pipeline
uv run syncmill run "<prompt>" -a claude   # force one agent, no fallback
uv run syncmill run "<prompt>" -s pipeline   # chain agents as sequential stages (default: route)
uv run syncmill run "<prompt>" -s compete   # run all agents concurrently, head-to-head; keep the winner
uv run syncmill run "<prompt>" -s council   # agents propose → critique (×SYNCMILL_COUNCIL__ROUNDS) → synthesize, deliberating via shared memory
uv run syncmill run "<prompt>" -s decompose   # planner splits into ≤SYNCMILL_DECOMPOSE__MAX_SUBTASKS subtasks, run across agents concurrently, then synthesize
uv run syncmill run "<prompt>" --exclude claude   # run the rest; drive claude interactively yourself (repeatable)
uv run syncmill run "<prompt>" -c python -c refactor   # capability hints — prefer an agent declaring them (needs SYNCMILL_CAPABILITIES__AGENTS), else priority order
uv run syncmill run "<prompt>" -r /path/to/repo -t 600   # target repo + timeout override
uv run syncmill run "<prompt>" -s compete --monitor   # live tmux monitor of a concurrent run (one pane per agent, auto-attached)
uv run syncmill session start [agent]   # durable interactive agent in a dedicated tmux session (survives detach; reattach by name)
uv run syncmill session list / attach <agent|name> / stop <agent|name>|--all   # manage interactive sessions
SYNCMILL_BOARD__ENABLED=true uv run syncmill board add "<task>" --goal "<g>"   # persistent work-board: add a planned item (disabled by default)
uv run syncmill board list [--state --goal] / show <id>   # view the board / one item (state, evidence, audit history)
uv run syncmill board run [--id --loop --strategy --agent]   # claim the next dispatchable item (or --id), orchestrate it, record the outcome
uv run syncmill board update <id> [--state --evidence --sign-off --clear-human-required]   # human path; `done` REQUIRES evidence/sign-off (bare --state done rejected)
uv run syncmill board decide "<text>" [--scope <goal> --supersedes <id>]   # Phase 2: record a never-re-litigate decision (injected into matching board runs)
uv run syncmill board decisions [--goal] / board stats   # list active decisions / team-health stats (dup-work, stalls, false-done)
# Phase 2 also extends `serve` with read-only board_list/board_get/board_stats MCP tools (6-tool surface)
uv run syncmill agents               # list registered agents in priority order
uv run syncmill status               # check memtomem connection / db path
uv run syncmill serve                # read-only MCP gateway over `shared` (stdio; --http/--host/--port)
uv add <pkg>                         # add a dependency (edits pyproject.toml + uv.lock)
uv sync --group dev                  # install dev deps (pytest)
uv run pytest -q                     # run the hermetic test suite (tests/)
uv run pytest tests/test_agents.py -q -k execute   # one file / one pattern
```

The agents shell out to real `claude`/`codex`/`kimi` binaries (note the `kimi-code` agent's binary is `kimi`), so `syncmill run` requires those CLIs installed and authenticated. The **test suite is fully hermetic** — `tests/conftest.py` provides fake agents/memory/store/registry so tests never touch the real `~/.memtomem` DB, the network, or the agent binaries. When adding behavior, mirror the existing pattern: monkeypatch `syncmill.agents.subprocess.run` (sync path) or `syncmill.agents.asyncio.create_subprocess_exec` (async path) for agent execution, inject a `FakeStore` via `make_memory()` for memory logic, inject a `FakeGate` for quality-gate behavior (and exercise the real `CommandGate` with harmless `true`/`false`/`python` commands), and use the `git_repo` fixture for worktree/git tests.

## Architecture

The whole system is one rule made concrete: **the Supervisor is the only component that touches both agents and memory. Agents are pure functions — prompt in, `TaskResult` out — and know nothing about memtomem, each other, or the Supervisor.** This isolation is enforced at the type level: `AgentRunner.execute`/`aexecute`(prompt, workdir, timeout) receive only a `str` prompt. Never thread a `Task`, memory handle, or another agent's result into an agent.

Request flow (`CLI → Supervisor.run`, in `supervisor.py`):

1. `cleanup_orphaned_worktrees` sweeps leftovers from crashed runs.
2. `Supervisor` builds an `AgentRegistry` (priority-ordered, enabled agents) and a `SyncmillMemory`.
3. Per run: build a `WorktreePool` (the strategy acquires worktrees from it), start a memtomem task session.
4. The Supervisor **re-orders the candidate agents by capability fit for this task** (#9 — `_matched_order`, a no-op by default; see the capability-matching extension point), then the selected **`Strategy`** executes: it searches memory for context, **enriches the prompt** with it, acquires worktree(s), then runs agents — recording per-worktree `files_changed` on the result it returns.
5. On success: the Supervisor writes that result's summary to the `shared` memory namespace.
6. `finally`: end the memory session, then `pool.cleanup_all()` removes every worktree + branch the run acquired.

### The extension points

- **Agents** (`agents.py`): subclass `CLIAgent`, implement `_build_command`, and override `_parse_output` / `_is_error_output` for that CLI's output format — you get both the sync `execute` and the async `aexecute` paths for free from the base class. Register the class in `_AGENT_CONSTRUCTORS`, add a matching `AgentConfig` field in `config.py` (an id with a hyphen — e.g. `kimi-code` — uses the underscore field name `kimi_code`, which `SyncmillConfig.agent_config` maps for you), and add the id to `agent_priority`. Output formats differ per CLI: Claude extracts the `result` key from its JSON, Codex joins `agent_message` items from its JSONL, and Kimi Code (`kimi`) keeps the `role:"assistant"` text lines from its `stream-json` JSONL. Only Claude exits 0 on an in-band error (hence its `_is_error_output`); the others signal failure with a non-zero exit.
- **Strategies** (`strategies/`): implement the `Strategy` Protocol and register it in `_STRATEGIES`, then select it via `default_strategy` (or the `--strategy/-s` CLI flag). `_make_strategy` raises on an unknown name — mirror that hard-fail rather than silently defaulting. **Package layout** (extracted from `supervisor.py` in #12, once all four strategies made that module unwieldy — the demand the "don't pre-abstract" invariant gated on): `strategies/base.py` holds the `Strategy` Protocol plus every cross-strategy helper (`_enrich_prompt`; the gate helper `_gate_accepts`; the breaker helpers `_breaker_runnable`/`_breaker_record`/`_breaker_all_open_failure`; the failure builders `_no_stages_failure`/`_aggregate_failure`; the convergence seam `_select_winner`; and the per-worktree diff collection `_collect_files_changed`/`_git_changed_files`) — diff collection lives *below* the strategy modules here, not in `supervisor.py`, precisely to keep the import graph acyclic (the Supervisor imports the registry, so it sits *above* the strategies). Each strategy is then its own module (`route.py`, `pipeline.py` with its private `_pipeline_failure`, `compete.py`, `council.py` with the `_council_*` prompt builders, `decompose.py` with the `_decompose_*` prompt builders + `_parse_subtasks`), and `strategies/__init__.py` owns the registry (`_STRATEGIES`, `available_strategies`, `_make_strategy`) because it needs every concrete class. The Supervisor imports `Strategy`/`_make_strategy` from the package and keeps only the run lifecycle + `_matched_order` (capability re-ordering is applied once at the Supervisor, never per strategy). Tests that monkeypatch `_git_changed_files` must target `syncmill.strategies.base` (where `_collect_files_changed` looks it up), **not** `syncmill.supervisor`. Five strategies exist: `RouteStrategy` (try agents in priority order, fall back on failure, aggregate errors if all fail), `PipelineStrategy` (run agents as sequential stages — each reads prior stages' results from `shared` and writes its own there, fail-fast on a broken stage; the prompt enricher `_enrich_prompt` is shared by all), `CompeteStrategy` (run every agent **concurrently**, each in its own worktree, then keep a winner), `CouncilStrategy` (multi-round deliberation; see below), and `DecomposeStrategy` (split the task into subtasks, run them across agents concurrently, then synthesize; see below). Each strategy is handed a `WorktreePool` and owns its worktree topology — Route/Compete/Council acquire one isolated worktree per agent, Pipeline a single shared one, Decompose one per planner + per subtask + per synthesizer — and sets per-worktree `files_changed` (via `_collect_files_changed`) on the result it returns. `CompeteStrategy` is syncmill's first *concurrent* strategy: it bridges async via `run_async` over the `aexecute_isolated` fan-out (per-agent worktree + per-agent timeout), and picks the winner deterministically in `_select_winner` — the **first gate-passing COMPLETED result in priority order** (never wall-clock/`duration_seconds`), aggregating failures like Route when none qualify. `_select_winner` is where quality gates (#10) plug in: with a gate it ranks completers by verified pass with priority as the deterministic tie-break (see the quality-gates extension point below); it does **not** auto-apply the winner's diff (worktrees stay disposable — the Supervisor shares the winner to `shared` and tears every worktree down). `CouncilStrategy` (#13, v0.3) is the **multi-round** strategy: each agent gets one worktree reused across three kinds of *concurrent* phase — **propose** (every runnable agent drafts a solution; the completers become the council *members* and each proposal is published to `shared`), **critique** (`config.council.rounds` times — each member re-reads the council's proposals + prior critiques from `shared` and refines its own worktree, publishing each critique back; a failed critique is tolerated, not dropped), then **synthesize** (every member produces a final solution from the whole deliberation, and the council converges by **reusing `_select_winner`** — so a council is "deliberate over rounds, then compete on the synthesized candidates"). Deliberation flows **only** through `shared` (relevance-ranked, best-effort — the same handoff Pipeline uses), never agent-to-agent, so the synthesized winner reflects more than one agent's input by construction. `members` is just `(agent, worktree)` pairs — no per-member result state — because synthesis re-runs everyone and `_select_winner` is the single convergence point; the returned winner's `duration_seconds` is the council wall-clock (sum of each concurrent phase's slowest agent). Like Compete it neither cleans worktrees nor applies the winner's diff — the Supervisor shares the winner and tears every worktree down. `DecomposeStrategy` (#14, v0.3) is syncmill's first task-**splitting** strategy — where every other strategy runs agents on the *same* task, decompose runs them on *different pieces* (the maintainer chose the concurrent/isolated integration model over a sequential shared-tree one: collaborate via shared *knowledge*, not file merges). Three phases: **decompose** — the highest-priority runnable agent (`runnable[0]`) plans the breakdown in a scratch worktree via the **sync** `execute` path (a single sequential step needs no fan-out, like route/pipeline), returning a JSON array parsed by `_parse_subtasks` (robust to fences/prose; a failed/empty/unparseable plan **degrades** to a single whole-task subtask, so a flaky planner never aborts — best-effort like memory); **subtasks** — the subtasks are distributed **round-robin** over the runnable agents (`runnable[i % len(runnable)]` — "across agents") and run **concurrently**, each in its own worktree via the new `aexecute_each` fan-out (the per-item-prompt counterpart to `aexecute_isolated`'s broadcast), each completed subtask's summary published to `shared` (a failed subtask is tolerated, not shared; **none** completing → aggregate failure, like council with no proposal); **synthesize** — every runnable agent reads the subtask summaries from `shared` and produces the integrated solution in a **fresh** worktree (broadcast via `aexecute_isolated`), converging through the shared `_select_winner` seam (first gate-passing COMPLETED in priority order). All memory I/O sits strictly between fan-outs (the shared-loop rule); the winner's `duration_seconds` is the decompose wall-clock (planner + slowest subtask + slowest synthesizer). Like Compete/Council it neither cleans worktrees nor applies a diff — integration is by shared knowledge (the subtask worktrees are torn down, their code discarded, exactly as the losers' trees are). `config.decompose.max_subtasks` (≥1, default 8) caps the breakdown.
- **Quality gates** (`gates.py`, #10): a gate validates an agent's work **after it finishes**, against the diff in that agent's worktree — reactive, never a pre-run liveness probe (respects "no `health_check`"). Implement the `QualityGate` Protocol (`evaluate(worktree) -> GateReport`); the shipped `CommandGate` runs each configured command (via `shlex.split`, no shell — chain checks by adding entries, not `&&`) and passes iff all exit 0. `build_gate(config.gate)` returns the gate or **`None` when no commands are configured** — the disabled default, so behavior is unchanged out of the box (set `SYNCMILL_GATE__COMMANDS='["pytest -q", ...]'`). The gate is plumbed through the **strategy layer only** — agents stay pure `(prompt, workdir, timeout)` functions and never see it. The Supervisor builds it per-run and injects it into `Strategy.execute(..., gate=)`; the shared `_gate_accepts` helper means "passed the gate" is one thing everywhere: pass → accept; fail → downgrade the result to FAILED with a gate error (attached as `result.gate`) so the rejection flows through the existing failure plumbing. Each strategy applies that verdict per its topology — **Route** falls back to the next agent, **Pipeline** fails the chain (gating only the final cumulative tree, since intermediate stages may legitimately be broken mid-chain), **Compete** downranks failers in `_select_winner`, **Council** gates only the synthesis phase (reusing `_select_winner` — propose/critique are ungated deliberation, only the converged final solution must clear the gate), and **Decompose** likewise gates only the synthesis phase (the planner and the individual subtasks are ungated — a subtask is a partial piece that needn't pass alone — and only the integrated synthesis, again via `_select_winner`, must clear the gate). A gate-rejected result is never shared to `shared` (it's a FAILED result, which the Supervisor already skips).
- **Circuit breaker** (`breaker.py`, #8): reactive per-agent back-off from *repeatedly* failing agents — `RouteStrategy` already falls back on one failure, the breaker remembers failures **across runs**. `CircuitBreaker` tracks consecutive failures per agent: after `failure_threshold` in a row the circuit **opens** (the agent is skipped) for `cooldown_seconds`, then goes **half-open** (one trial), and any success **closes** it (resets the count). The three states are derived from `(failures, opened_at)`, never stored. **Reactive, not a `health_check`:** `allows()` decides purely from *recorded past outcomes* — it never calls an agent to test liveness; skipping an OPEN agent is "it kept failing when we ran it," not a probe. State **persists** to `state_path` (JSON, atomic temp+`os.replace`) loaded on construction — this is mandatory, since each `syncmill run` runs an agent at most once, so "N in a row" only accumulates across separate invocations. `build_breaker(config.breaker)` returns **`None` when `enabled=False`** (the default), so the disabled path never touches the filesystem and behavior is unchanged. Like the gate it's plumbed through the **strategy layer only** (agents never see it); the Supervisor builds it once (it carries cross-run state + a `degraded` flag the CLI surfaces, unlike the stateless per-run gate) and injects it into `Strategy.execute(..., breaker=)`. Shared helpers keep it uniform: `_breaker_runnable` drops OPEN agents (all five strategies skip them; Route falls back, Pipeline chains the remaining stages, Compete, Council, and Decompose fan out only the survivors — all return `_breaker_all_open_failure` if the breaker tripped everyone), and `_breaker_record` records each run agent's **RAW execution status taken *before* the gate** — so a gate rejection (a quality verdict on a *working* agent) does **not** trip the breaker; only an agent that fails to *run* does. **CouncilStrategy is the one deliberate exception to "one record per run."** A council runs each member up to `2 + rounds` times (propose + critique rounds + synthesize), but records the breaker **exactly once per agent, at the propose phase** — the unique phase where every runnable agent executes once, from identical input, so it is the fair "can this agent run?" probe. The threshold is denominated in *runs*; recording every council execution would make council trip the breaker ~`(2 + rounds)`× faster than the other strategies (a strategy-dependent regression) and would conflate execution-reliability with a working member struggling on the harder critique/synthesize prompts — the same reason a gate rejection never trips it. So council's critique/synthesize re-runs of an already-recorded member are deliberately **not** recorded, keeping council's contribution to the cross-run "N in a row" count one-per-agent-per-run, identical to the other strategies. **DecomposeStrategy preserves that same one-record-per-agent-per-run invariant by a different mechanism: it records each agent's RAW outcome at its FIRST execution this run** (a `recorded` set), deduping all later runs. Decompose has no council-style uniform-and-easy phase to record at: the planner is one agent on a planning prompt, the subtasks are a non-uniform round-robin, and synthesis (the only phase where *every* runnable agent runs) is the **hardest** prompt — recording there would over-penalize a working agent struggling on integration, the very reason council records at propose, not synthesize. So "first execution" records the planner at its short/early (typically easy) planning step and every other agent at its first subtask (or, failing that, its synthesis), probing every agent that runs exactly once — and, as everywhere, the pre-gate status, so a synthesis gate rejection never trips it. Two "agent didn't run" cases are deliberately different: a **degraded** breaker (unreadable/malformed state file) is best-effort/advisory like memory — it degrades *permissive* (`allows()` returns True for everyone, surfaced as a yellow CLI notice) so a broken breaker never blocks or aborts work; an **OPEN** circuit (recorded failures, still within cooldown) is *intentionally* skipped, and if that empties the candidate pool the strategy fails fast with a clear "all circuit-open, cooling down — retry or disable" result (`_breaker_all_open_failure`, parallel to the gate failing the run when every output is rejected). That fail-fast is the back-off doing its job — respecting the cooldown the user opted into — not the breaker aborting healthy work; "advisory / never aborts" describes only the degraded path.
- **Capability matching** (`matcher.py`, #9): declarative, config-driven re-ordering of the candidate agents by *suitability* for a task, layered **over** the `agent_priority` baseline. Each agent declares capability tokens in config (`SYNCMILL_CAPABILITIES__AGENTS='{"codex": ["python"], "kimi-code": ["rust"]}'` — a map keyed by the **real** agent id, so hyphenated `kimi-code` is a verbatim key, unlike the underscore `AgentConfig` fields); a task carries a hint in its `Task.tags` (the previously-unused field, reused — set via the repeatable `--capability/-c` CLI flag). `DeclarativeMatcher.order` scores each agent by the **set-intersection size** of its declared capabilities with the (normalized, case-insensitive) hint and **stable-sorts descending**, so a matching agent moves ahead of raw priority while equal-fit agents keep priority order (the tie-break is sort stability over the input). It **re-orders, never drops** — the output is a permutation, so nothing is stranded and the two acceptance criteria hold by construction: a matching agent sorts ahead (score ≥ 1 > 0), and *nothing matching* (or no hint) is an all-zero stable sort = identity = priority order. **DECLARATIVE, never a probe** — a pure dict-lookup + set-intersection of static config with `task.tags`, strictly more passive than the breaker (respects "no `health_check`"). `build_matcher(config.capabilities, config.agent_priority)` returns **`None` when no agent declares a capability** (the disabled default → identity ordering, behavior unchanged); the optional `known_agent_ids` only **advisory-warns** (never raises) on a capability declared for an id not in the lineup (a config typo), while free-form *tokens* are never validated (an unmatched token is the graceful fallback). Unlike the gate/breaker — whose verdicts mean different things per strategy, so they're threaded **into** `Strategy.execute` — capability matching has **no topology-specific semantics**: it produces exactly one artifact, a re-ordering of the flat candidate list every strategy already consumes as a priority sequence. So the Supervisor applies it **once** in `run` (`_matched_order`, the `else`/non-forced path only — a forced `-a` agent has no ordering to influence), **before** dispatching to the strategy and **before** the breaker's per-strategy OPEN-agent filter (preference first, then availability) — making **all five** strategies capability-aware with no `Strategy` protocol change: Route tries the best-matched agent first, Pipeline leads its chain with it, Compete and Council make it the winner-priority (Council's members preserve the matched order, so the best-matched agent leads the synthesis selection), and Decompose makes it the planner + leads its subtask round-robin and synthesis-winner priority. This is the deliberate, uniform reading of #9's "layered over the existing priority order" (#9 only mandates Route; Pipeline/Compete/Council/Decompose are the free consequence of re-ordering at the source). Built once in `Supervisor.__init__` (stateless/config-derived, no filesystem — unlike the breaker); the CLI rebuilds a display-only matcher so the `Agents: …` banner shows the **actual** matched order rather than raw priority.

### Memory (`memory.py`)

`SyncmillMemory` wraps memtomem's `MemtomemStore` with syncmill conventions: namespace `agent-runtime:{agent_id}` is private per agent, `shared` is the cross-agent knowledge base (both derived from `memtomem.constants` — `AGENT_NAMESPACE_PREFIX`/`SHARED_NAMESPACE` — so they track memtomem's scheme; matches the 0.2.x MCP multi-agent tools). The Supervisor is the **sole reader/writer** — there is intentionally no MCP sharing between agents. memtomem is async, and so is the agents' `aexecute` path; syncmill's orchestration (Supervisor, route/pipeline strategies) is sync. `run_async()` bridges async into that sync world by **reusing a module-level event loop** — do not switch to `asyncio.run()`, which closes the loop and breaks memtomem's later embedding calls (a fixed bug); `close_event_loop()` releases it at CLI shutdown.

**Memory is advisory/best-effort.** Every `SyncmillMemory` method catches its own exceptions, logs a warning, sets `degraded`/`last_error`, and returns a safe default. A broken or misconfigured memtomem (e.g. an unsupported embedding provider) must never abort a task — the agent still runs, just without shared context. Preserve this when editing memory or the Supervisor; the CLI surfaces `supervisor.memory.degraded` as a yellow notice. Note memtomem applies `~/.memtomem/config.json` *last* (inside `create_components`), overriding both env vars and programmatic `config_overrides` — so the embedding provider is governed by that global file, and syncmill shares `~/.memtomem/memtomem.db` by default.

### Interactive collaboration (human drives one agent, syncmill runs the rest)

Programmatic `claude` runs may be billed separately from interactive use. To keep Claude **interactive** while syncmill orchestrates the others: exclude claude from the run (`run … --exclude claude`, repeatable; or persistently via `SYNCMILL_CLAUDE__ENABLED=false`) and drive Claude yourself in the terminal. The two sides collaborate **only through the `shared` namespace** — never by syncmill invoking claude, so the agent-isolation invariant is untouched (the interactive session is a separate process, not a syncmill agent).

This needs zero extra wiring: syncmill's `SyncmillMemory` and memtomem's MCP multi-agent tools use the **same `shared` literal on the same `~/.memtomem/memtomem.db`** (exact-match namespaces). The one rule — the interactive session must target `shared` **explicitly**, because its default namespace is cwd-scoped (`claude:<cwd>`), which syncmill does not read.

- Interactive session **writes** (so syncmill sees it): `mem_add(content=..., namespace="shared")`, or `mem_agent_share(chunk_id=..., target="shared")` to promote an existing chunk.
- Interactive session **reads** syncmill's results: `mem_agent_search(query=..., include_shared=True)` or `mem_search(query=..., namespace="shared")`.
- syncmill side is unchanged: `share_result` writes the winner to `shared`; `search_context` reads `shared` to enrich the programmatic agents' prompts.

Collaboration is via shared *knowledge*, not file merges: the interactive session edits your real working tree while syncmill agents edit isolated worktrees, so syncmill's diff never sees the interactive edits. `CompeteStrategy` now runs the syncmill *agents* head-to-head; entering the human's interactive session as a competitor judged alongside them is still future work (the interactive session is a separate process, not a syncmill agent).

`syncmill session` (#17, below) makes this mode **durable**: instead of running the bare CLI in your own terminal (where it dies on terminal close / SSH drop), it launches that same interactive binary inside a dedicated, reattachable tmux session. The collaboration contract is identical — the session still targets `shared` explicitly (`session start` prints the `mem_add`/`mem_agent_search` reminder) — it just survives detach.

### Read-only MCP gateway (`gateway.py`, #15)

The `serve` command runs a **one-way (read-only) MCP gateway** over the `shared` namespace so external/interactive MCP clients (Claude Code/Desktop, Cursor, …) can *read* syncmill's shared knowledge — the **consumer-facing** complement to the interactive mode above. It is **not** a strategy and **not** an agent: it preserves the core invariant exactly (agents never touch MCP; the Supervisor remains the sole *writer*) by being a separate, non-agent, read-only *consumer*. The gateway touches memory but never agents, so "the Supervisor is the only component that touches both agents and memory" still holds. `gateway.py` is a **flat top-level module** (no subpackage — don't pre-abstract; one module is enough). The seam is `build_gateway(memory, *, board=None, board_error=None, host, port) -> FastMCP` (the official `mcp.server.fastmcp.FastMCP`), which registers the read-only tools as closures over the injected `memory` (and, in **Phase 2**, the injected `board`) and returns the server *without running it* (the test seam — `mcp._tool_manager.list_tools()` asserts the exact tool set so a write/delete/index tool can never sneak in; tools are driven in tests via `await mcp.call_tool(...)`, which returns `([TextContent], {"result": str})`). #15 shipped the three `shared` tools — `shared_search(query, top_k)`, `shared_read(chunk_id)`, `shared_stats()`; **Phase 2 adds three read-only `board_*` tools** — `board_list(state, goal, limit)`, `board_get(item_id)`, `board_stats()` — so **the exact-set guard now asserts six tools** (`test_exactly_six_readonly_tools`), still with **no write tool** for memory OR the board. The board tools are registered **unconditionally** (a stable surface) and report `_BOARD_DISABLED` ("not enabled") when no board is injected, OR `_BOARD_UNAVAILABLE: <error>` when the board was **enabled but failed to open** (`board_error`, threaded from `serve`) — the disabled-vs-broken distinction, mirroring the shared tools' healthy-empty-vs-unavailable split, while the shared gateway stays alive. `board_list` clamps `limit` to `[1, MAX_BOARD_LIMIT=200]` and returns **most-recent-first** (reversing `Board.list`'s FIFO so a truncated read keeps the newest, not the oldest, items); board **id (uuid) validation lives in `board.py`** (`Board.get` rejects a malformed id as not-found without a query — the single-coupling rule, mirroring `get_shared`). Board reads are sync sqlite called directly inside the async MCP handlers (quick — no thread offload); `serve` builds the board best-effort and closes it in its `finally`. **All memtomem coupling stays in `memory.py`** (the same single-coupling rule as the Supervisor): three shared-scoped, best-effort read methods on `SyncmillMemory` — `search_shared`, `get_shared`, `shared_stats` — each returning **`None` on a genuine per-call backend failure** (vs `[]`/a `dict` on success) so the gateway distinguishes "unavailable" from "healthy-empty" **without** consulting the sticky `degraded` flag (a prior unrelated degrade must not poison a later healthy empty read). **Isolation is load-bearing:** `MemtomemStore.get` is *not* namespace-scoped, so `get_shared` verifies the returned chunk's `namespace == shared` and returns `None` otherwise (else a guessed/leaked id would leak an `agent-runtime:*` private chunk); `search_shared` always passes `namespace="shared"` (never the agent prefix/`None`/`include_shared`) and filters non-shared rows defensively; `shared_stats` uses `list_namespace_meta()` (the only meta method carrying `chunk_count`) and reports the `shared` entry **alone** — never enumerating other namespaces (a metadata-leak guard). A malformed `chunk_id` is a client typo → `get_shared` returns *not-found* **without** degrading (validate the UUID first; only a real store error degrades). The CLI clamps `top_k` to `[1, MAX_TOP_K=50]` (untrusted-input guard). **Event-loop & transport:** the `serve` path never uses `run_async` — `FastMCP.run()` owns its own anyio loop and the async tools `await` the memory methods directly inside it; memory is constructed eagerly (sync; lazy memtomem init) and closed in a `finally` via `anyio.run(memory.close)` (a fresh loop, deliberately off syncmill's shared module loop). Under stdio, **stdout is the JSON-RPC channel** — every human-facing line (startup notice, degraded/HTTP warnings) goes to **stderr** (`err=True`); the command writes nothing to stdout. HTTP (`--http`, `streamable-http`) is loopback-by-default; `host`/`port` are passed at **FastMCP construction** (not mutated onto `mcp.settings` afterward) because FastMCP computes its DNS-rebinding `transport_security` allow-list from the constructor host in `__init__`; a non-loopback `--host` is warned about and there is **no auth** (v0.3 — document/front with a trusted network or authenticated proxy). `mcp>=1.26.0` is now a direct dependency (was transitive via memtomem).

### Live tmux monitor (`monitor.py`, #16)

The `--monitor` flag (or `SYNCMILL_MONITOR__ENABLED`) gives a **live tmux view of a concurrent run** — one pane per agent, streaming output as it happens, auto-attached. Like the gateway it's an **observability layer, not a strategy or agent**, and it preserves agent purity exactly: the `AgentRunner` signature is **unchanged** (still only `(prompt, workdir, timeout)`). Four locked design decisions (maintainer-approved via AskUserQuestion): (1) streaming via an **ambient `contextvars` seam** in `agents.py` — `_OUTPUT_SINK` (default `None` → today's `communicate()` path **byte-for-byte**) + the `stream_to(sink)` context manager + the `OutputSink` Protocol, which live in `agents.py` precisely so `agents.py` imports nothing from `monitor.py` (acyclic). When a sink is set, `aexecute` uses `_communicate_teed` (drains stdout/stderr concurrently like `communicate`, tees each chunk to the sink, **bounded** reap via `wait_for(proc.wait(), _REAP_TIMEOUT_SECONDS)` — never a bare `await proc.wait()`, which would re-introduce the grandchild-pipe hang). (2) The `Monitor` is **threaded through the strategy layer** (`Strategy.execute(..., monitor=None)`), like the gate/breaker: the concurrent strategies call the shared `base.py` helpers `_monitor_phase`/`_monitor_streaming(agent_ids)`/`_monitor_status` (no-ops when `None`) — announce each phase, wrap each fan-out in `_monitor_streaming` (opens the seam **and** lazily creates that agent's pane), report per-agent raw status; the sequential strategies (route/pipeline) accept-and-ignore (the seam is async-only, so they can't stream). (3) UX = **auto-attach**. (4) Because orchestration is deliberately **sync on the main thread** and `tmux attach` needs the foreground, the mechanism is **run-orchestration-inside-tmux** (outer/inner split): the OUTER `syncmill run` builds a detached tmux session whose control pane runs the REAL orchestration by re-invoking `syncmill run` (DETERMINISTIC argv reconstruction in `_inner_argv`, **never `sys.argv`**; `--monitor` deliberately OMITTED). The inner argv is launched through a `sys.executable -c <_ENV_SHIM>` exec shim that **replaces** the pane's inherited environment with the OUTER's **`0600` `<run_dir>/env` snapshot** (`_write_env_snapshot`) — it `os.environ.clear()`s, applies the snapshot, then re-keeps only the tmux-owned pane vars (`TERM`/`TMUX`/`TMUX_PANE`, the same set `_SNAPSHOT_SKIP_ENV` omits) before `execvp`. **Replace, not additive `update`:** a new session inherits the (possibly stale) tmux **server** env, not the client's, so an additive overlay would leave any stale `SYNCMILL_*`/auth/PATH var the outer client lacks and silently change the inner's config — clearing first gives the inner **exactly** the outer's full env (PATH/`SYNCMILL_*`/auth, **incl.** `SYNCMILL_MONITOR_DIR`) plus the pane's three terminal vars. This is **without** serializing secrets into the tmux command-line argv (the earlier `-e KEY=VALUE` approach leaked secrets into `ps` and could blow the exec arg limit — **do not reintroduce it**). All argv is passed DIRECTLY (no shell re-parse → no injection, works under fish/csh). The snapshot excludes the tmux-owned `TERM`/`TMUX`/`TMUX_PANE` (`_SNAPSHOT_SKIP_ENV`); the OUTER then `tmux attach`es (foreground, blocks) with only `TMUX`/`TMUX_PANE` stripped (`_ATTACH_STRIP_ENV` — **`TERM` is KEPT**, the attaching client needs it to render; stripping it breaks attach) so attach works even from inside an existing tmux session, and `_tmux_attach` returns the rc so a failed attach (non-zero, no `result.json`) is surfaced + exits non-zero rather than mistaken for a clean "detached, exit 0". On detach it reads the inner's `result.json`, renders it (the **shared** `render_result`/`render_task_result`, so monitored and unmonitored output are byte-identical), and exits with its code. The INNER detects itself via `inner_dir()` — the **single source of truth** requiring **both** the env var **and** a `.syncmill-inner` sentinel file (so a stray exported var can't masquerade a normal run as inner) — builds a `TmuxFileMonitor` (`build_monitor(config, *, monitor_dir)`, pure, `None` when `monitor_dir` is `None` so normal runs/the outer never build one), tees output to per-agent logs via `FileSink` (a single **non-blocking `os.write`** in `O_APPEND` — never blocks the shared event loop, never raises out), drives the panes **from inside the session** (`$TMUX` inherited; lazy `split-window` + `tail -F` per agent it actually runs, so panes track the **real** runnable set after the breaker/matcher filters — no outer/inner drift), and on `finish(result)` writes `result.json` (atomic temp+`os.replace`) + keeps the control pane's result on screen (`remain-on-exit`). The Supervisor builds the monitor per-run (`build_monitor(config.monitor, monitor_dir=inner_dir())`), injects it into `Strategy.execute(..., monitor=)`, and calls `monitor.finish(result)` in its `finally`. The CLI **gates the outer launch** on (monitoring enabled ∧ NOT inner ∧ strategy in `CONCURRENT_STRATEGIES` ∧ `_stdout_isatty()` ∧ `tmux_available()`) — each missing precondition prints a notice and **falls through to a normal run** (the monitor is a convenience, never required; a `MonitorLaunchError` from a failed `tmux new-session` likewise falls back). The inner installs a SIGHUP/SIGTERM→`SystemExit` handler so the Supervisor's `finally` (worktree cleanup) still runs on tmux-server death. `monitor.py` is a **flat top-level module** (gateway.py precedent), banner-split into shared / INNER monitor / OUTER launcher, with the OUTER half importing nothing from the INNER half. **Two NEW deliberate `aexecute` divergences to preserve:** a *teed timeout* surfaces the pre-timeout bytes to the sink/log (plus a `[timed out…]` marker) even though the result's `output` stays empty (the log is a live VIEW, the result is the CONTRACT); and the teed path replaces `communicate()` only when a sink is active. Hermetic tests never launch tmux: `_FakeProc` grew `.stdout`/`.stderr` `_FakeStream`s for the teed path, an autouse `reset_output_sink` fixture forces `_OUTPUT_SINK` back to `None` per test, `FakeMonitor` records ordered events + opens the real sink, and `monitor._tmux`/`_tmux_attach`/`tmux_available`/`_stdout_isatty`/`inner_dir`/`launch_monitored_run` are all patchable seams. **Scope note (v0.3):** Claude's `--output-format json` emits one final blob (no incremental stream), so its pane fills at completion where codex/kimi (JSONL) stream live; the M10a detached-run GC registry was deliberately **not** built — the existing `cleanup_orphaned_worktrees` already sweeps stranded worktrees every run.

### Durable interactive sessions (`session.py`, #16-sibling, #17, v0.4)

The `session` command group (`start`/`list`/`attach`/`stop`) makes the interactive-collaboration mode **durable**: it launches an agent's **bare interactive CLI** (`claude`/`codex`/`kimi`) inside a dedicated tmux session that survives detach (`Ctrl-b d` / terminal close / SSH drop) and **reattaches by deterministic name** — the v0.4 acceptance criterion. The **complement** to #16: where `--monitor` is an *ephemeral* view of a *programmatic* concurrent run, `session` is a *long-lived* host for a *human-driven interactive* agent. Maintainer-approved (AskUserQuestion): (1) scope = the four-verb lifecycle; (2) a new **flat `session.py`** (gateway/monitor precedent) that *reuses* monitor's tmux primitives; (3) a **standalone `_INTERACTIVE` map** (`{agent_id: [binary]}`) for the launch command.

Core invariants: **not an agent, not a strategy, touches neither agents nor memory** — pure tmux + process launch (so the "Supervisor is the only thing touching both agents and memory" invariant is untouched). The interactive session NEVER enters `AgentRunner.execute`/`aexecute` (that would re-incur programmatic billing and break agent purity), so the per-agent launch command is a standalone `_INTERACTIVE` map **deliberately separate from** `CLIAgent._build_command` (it duplicates the `kimi-code → kimi` binary fact on purpose — interactive mode does **not** route through the registry, so it can run an agent that is `enabled=false` for orchestration; the CLI validates the requested agent against `_INTERACTIVE` keys, **not** `registry.available()`). `session.py` **reuses monitor's primitives** via `from syncmill.monitor import _tmux, _tmux_attach, _SNAPSHOT_SKIP_ENV, INNER_ENV` (`monitor.py` stays **UNCHANGED**) — private cross-module imports, the established `cli.py`→`supervisor._matched_order` pattern, so tests patch the **lookup site** `session._tmux` (not `monitor._tmux`, the `strategies.base` `_git_changed_files` lesson). It defines its **own `SessionLaunchError`** rather than reusing `MonitorLaunchError` (whose contract is "the CLI falls back to a normal run on catch" — but `session` has **no fallback**, it errors: `session` IS the tmux feature; the CLI gates `tmux_available()` as a hard error, and `_stdout_isatty()` for the foreground-attaching `start`/`attach`).

Durability mechanism: **deterministic names** `syncmill-session-<agent>` (not the monitor's uuid suffix) are the reattach key — `start` recomputes the name, and if the session exists it skips creation and attaches (reattach); else it creates a **detached** `new-session -d -s <name> -c <workdir>` running the bare binary through a session-specific exec shim, then attaches. No `remain-on-exit` (unlike the monitor — the session **should** vanish when the user quits the agent). The working dir is the **resolved `repo_root`** (the real tree — interactive edits land there, per the collaboration contract; the CLI validates `is_dir()` because tmux `-c` silently falls back to `$HOME`). Like the monitor, the detached session would inherit the stale tmux-**server** env, so the outer's environment is restored from a **`0600` snapshot file** (never argv — no secrets in `ps`) via **`_SESSION_ENV_SHIM`** — a *session-specific* shim (NOT `monitor._ENV_SHIM`) with two deliberate differences, both codex-design-review-driven: (a) it **self-unlinks the env file in a `finally` immediately after the read, BEFORE `json.loads`** — the detached pane's shim runs *asynchronously after* `new-session` returns, so the parent can't delete the file without a use-after-free; the shim consuming it is race-free and shrinks the secret window even on a corrupt snapshot; the parent only `rmtree`s the run dir on the **failure** paths (where the shim never started); (b) the snapshot **excludes `INNER_ENV`** as well as `_SNAPSHOT_SKIP_ENV`, so an already-exported `SYNCMILL_MONITOR_DIR` can't reach the interactive process and false-trip `monitor.inner_dir`. **Lifecycle ops match EXACT known names** (`{session_name(a) for a in _INTERACTIVE}`), never the `syncmill-session-` prefix — so `list`/`stop --all` can't show or kill a monitor run even if a user sets `SYNCMILL_MONITOR__SESSION_PREFIX=syncmill-session` (a destructive-op collision codex flagged). `#{session_attached}` is a client **count**, so attached = `int > 0`. A sentinel-guarded (`.syncmill-session`, distinct from monitor's `.syncmill-inner`), age-bounded `_sweep_stale_session_dirs` reaps orphaned run dirs (the #16 R5 ownership lesson). Hermetic tests (`tests/test_session.py`) never launch real tmux (patch `session._tmux`/`_tmux_attach`/`_sweep_stale_session_dirs`); the shim is exercised in a real tmux-free `python -c` child (env applied + file unlinked, incl. a corrupt-env case), and the gate/arg-shape surface in `tests/test_cli.py` via `_patch_session_seams`. **#17 = last v0.4 item.** No new config table (don't pre-abstract — the session prefix is a module constant).

### Persistent work-board (`board.py`, Phase 1 + Phase 2 of the agent-team platform)

The `board` command group turns syncmill from a single-run, stateless orchestrator into one with **durable, structured records of team work** — goal, owner, state, what's blocked/why, what's done **and verified**, dependencies, and a handoff baton. It is a **new flat top-level module** (gateway/monitor/session precedent — *don't pre-abstract*) backed by its **own SQLite store** at `~/.syncmill/board.db`: memtomem can't back it (markdown+embedding *knowledge* chunks have no structured status/dependency fields, no state machine, no atomic compare-and-swap). *State lives only on the board; knowledge lives only in memtomem's `shared`; the two cross-link by id.* Five locked design decisions (codex-reviewed pre-code over 5 rounds):

1. **Applied at the Supervisor run-lifecycle level, NOT threaded into `Strategy.execute`** — like `_matched_order`, the board has no topology-specific meaning. A new `Supervisor.run_item` *wraps* `run`; the **`Strategy` protocol is unchanged**; `run` gains exactly **one optional kwarg `memory=`** (`mem = memory or self._memory`, used at ALL five memory call sites — register/start_session/strategy/share/end — so plain `run` is behavior-identical). 2. **Agents stay pure** — orchestrated agents NEVER touch the board; the Supervisor mediates by rendering the item into the prompt (`render_item_prompt`, deterministic) and parsing an OPTIONAL ` ```syncmill-board ` fenced block back out of `result.output` (`parse_board_update` — its OWN parser, NOT a reuse: it degrades to `{}` and **NEVER raises** — incl. on pathologically-nested JSON, whose `json.loads` raises `RecursionError`, a `RuntimeError` not a `ValueError`, so it is caught explicitly. Recognized fields are sanitized **individually** (one malformed field can't discard a valid `state`); the all-or-nothing part is the `outputs` **list** (a mixed list is dropped whole, never salvaged to a subset — the `DecomposeStrategy._parse_subtasks` *philosophy*). `_extract_board_block` requires a genuine close fence — a 2nd `syncmill-board` OPEN fence is never mistaken for the first block's close, matching `strip_board_block` so the parser and the stripper agree on block bounds). 3. **The board store is LOAD-BEARING, built LAZILY** — it's the source of work + system of record, so unlike memory/breaker it does **not** degrade silently: a corrupt/unopenable db raises `BoardError` (caught at `Board.__init__` for both `sqlite3.Error` *and* `OSError` — an unwritable parent dir) → the CLI converts to `click.ClickException` (the `session.SessionLaunchError` "no fallback — it IS the feature" contract). Disabled by default (`build_board`→`None`); the Supervisor builds it lazily on first `run_item` (stored on `self._board`, closed in `close()`), **NOT** in `__init__`, so an enabled-but-corrupt board can never break a plain `run` (which never calls `run_item`). 4. **State machine `planned → running → (blocked | review) → done`**, where **`review` vs `done` = "done AND verified"**, load-bearing in `Board.transition`: a move TO `done` requires ≥1 passing structured `Evidence` (a `GateReport` maps to one) OR a human sign-off (`Evidence{kind:"human"}`), else `BoardError` — a bare `board update ID --state done` is rejected (the human CLI path). An AGENT's advisory `state:done` is honored only when **THIS run** produced passing verification (a gate that passed *this* run) — stale evidence from an earlier, now-discarded run does NOT certify the current work (`apply_update` gates the advisory `done` on the run's own evidence, while still persisting the accumulated evidence that backs the human `review→done` promotion); otherwise it is CLAMPED to `review`+audit (**never raises** — a good run is never turned `blocked` by an invalid advisory field). The human path also rejects a manual move INTO `running` (it is owned by the claim lease, never set by hand — `board update` does not offer it). Dependencies gate dispatch; an **atomic claim** (`BEGIN IMMEDIATE` CAS `planned→running`, stamping `lease_run_id`+`claimed_at`) is the no-duplicate-work guard on **every** path (`claim` by-id and `next_runnable` alike — opened in autocommit `isolation_level=None` so writers drive `BEGIN IMMEDIATE`/`COMMIT` by hand; WAL + `busy_timeout`); `human_required` items are excluded from auto-dispatch; FIFO order is `created_at, rowid` (rowid breaks same-clock-tick ties so insertion order holds). Append-only `transitions` audit table. **Stale-claim recovery** `recover_stale_running()` reclaims items past `lease_timeout_seconds` from `running`→`planned` (the `cleanup_orphaned_worktrees`/`_sweep_stale_session_dirs` analogue), run at the top of every `run_item`. The lease is the **fencing token**, not just a dispatch guard (adversarial-review catch): `apply_update(run_id=)` is a **lease-fenced CAS** (`WHERE id=? AND state='running' AND lease_run_id=?`) so a slow run whose item was reclaimed + re-dispatched to another runner can't clobber the new owner or revert a verified `done` — its stale write is dropped; the **crash-block path is fenced the same way** (`Supervisor._block_on_crash` threads `run_id` into `transition(run_id=)`, an identical `WHERE state='running' AND lease_run_id=?` CAS that drops a 0-row match), so a stale *crashed* run can't clobber a re-dispatched owner or revert a verified state either — including a crash AFTER `apply_update` already resolved the item (e.g. Ctrl-C during the shared-memory write), since the item has then left `running`; and `transition` preserves the lease on a *same-state annotate of a running item* (only clearing it when actually leaving `running`) and resolves a no-`--state` annotate's target from its **in-transaction** read (a `to_state=None` sentinel, never a stale pre-read), so a `board update` annotation can't strand a live claim into stale-recovery. Every transactional method rolls back on **any** exception (not only `sqlite3.Error` — e.g. a corrupt-row `ValueError`), so a `BEGIN IMMEDIATE` write lock is never leaked. 5. **The board↔`shared` boundary is closed via a per-run memory scope** — `run_item` runs the item through the normal pipeline with a **board-scoped `SyncmillMemory.scoped(run_id)`** that collapses BOTH the shared namespace AND every per-agent (session/search) namespace to `board-run:{run_id}` (via a single `_agent_ns` seam). So the strategy-internal shares (pipeline/council/decompose) AND `start_task_session`'s prompt-log all write to the per-run scope — intra-run handoff still works — and **nothing board-enriched leaks into the persistent global `shared` or `agent-runtime:*`**. After the strategy returns, `run_item` writes ONE sanitized summary to GLOBAL `shared` via `SyncmillMemory.share_board_result(item_id, task, strip_board_block(output))` (built from the item task + the agent output with the `syncmill-board` block stripped — never the enriched prompt); the **cross-link is the SINGLE composite tag `board-result:{item_id}`** (memtomem `add()` returns no chunk id; `search(tag_filter=...)` is a `str`/comma-OR, NOT a list). Decisions + the handoff baton are injected DETERMINISTICALLY from the board into the prompt, never via top-k recall (**Phase 2 (D4)** additionally has board runs **union-read** global cross-run `shared` — the scoped view's *reads* widen to the real `shared` while its *writes* stay confined to `board-run:{run_id}`, so the leak guard is untouched; the per-run `board-run:{run_id}` scratch namespaces are still not GC'd — a later housekeeping follow-up).

`run_item` flow: `_require_board` (lazy build; clear error if disabled) → `recover_stale_running()` → atomically claim (`claim(id)` or `next_runnable(run_id)`; `None` stops a `--loop` caller) → `Task(prompt=render_item_prompt(item))` → `run(memory=scoped)` → `parse_board_update(result.output)` → `board.apply_update(...)` [advisory] → `share_board_result(...)` to global shared. Wrapped in `try/except BaseException` → a genuine CRASH transitions the item `→ blocked` (`_block_on_crash`, best-effort, sets `human_required`) and re-raises; a FAILED result is **not** a crash (`apply_update` records it as `blocked`). **`--strategy` is NOT a `run_item` param** — the board CLI mutates `config.default_strategy` BEFORE constructing the `Supervisor` (matching how `run` selects a strategy in `__init__`). The CLI `board` group mirrors `session`: `_require_board` (mirror `_require_tmux`) hard-errors when disabled; `add TASK [--goal --depends-on(repeatable) --human-required]` (no `--owner` — `owner_agent` is RECORD-ONLY in v1, stamped from `result.agent_id`), `list [--state --goal]`, `show ID`, `run [--id --loop --strategy --agent]`, `update ID [--state --evidence --sign-off --note --clear-human-required]` (the human path; `done` REQUIRES `--evidence`/`--sign-off`). **Hermetic tests:** `tests/test_board.py` drives the REAL `Board` against `tmp_path/"board.db"` with an injected `now` (like `test_breaker.py`) — CRUD/audit, atomic dedup on BOTH paths (two `Board`s/one db → exactly one claims), dep/skip, stale recovery, done-gate, gate→Evidence, advisory-done-clamps, corrupt+unopenable db→`BoardError`, parse/strip tables; `conftest.py` adds a duck-typed `FakeBoard` + `FakeMemory.scoped`/`share_board_result` (the scoped child's shares stay off the parent's global `.shared` — the leak guard); `test_supervisor.py` covers `run_item` (board-scoped-memory leak guard, crash→blocked, lazy build never touched by a plain `run`, `close()` closes the board); `test_cli.py` exercises the `board` subcommands via `CliRunner` with a tmp db. **`Evidence`/`WorkItem`/`WorkState`/`Decision`/`BoardStats` live in `board.py`, not `models.py`** (they never flow through a strategy — the `breaker._AgentState` rule).

**Phase 2 — Collaboration depth + read API** (4 deliverables, one PR; the design grounded against the merged Phase-1 code, which shifted two plan details — see below):
- **D1 Decisions (never-re-litigate).** A separate `decisions` table in the same db (orthogonal to work items — no state machine, no lease): `Board.add_decision(text, *, scope="", supersedes=None)` (atomically retires the superseded one — a missing/already-retired target raises `BoardError`, and the new decision is NOT inserted; empty text rejected) + `Board.active_decisions(goal=None)` (non-superseded, oldest-first; `goal=None` → all, a goal string → global `scope=""` + that-goal-scoped). `run_item` fetches `active_decisions(goal=item.goal)` and injects the texts via the EXISTING `render_item_prompt(item, active_decisions=)` seam — **deterministic, in full, never top-k**. **Grounded divergence from the plan:** the plan put a `_enrich_with_decisions` helper in `strategies/base.py`, but Phase 1 already shipped the injection seam *inside* `board.py::render_item_prompt`, and a `base.py` helper would force a `board → strategies` import that violates the acyclicity invariant — so the seam stays in `board.py` (no `base.py` helper). The decisions read is **best-effort in `run_item`** (a `BoardError` degrades to no-decisions and logs, never blocks the item — decision injection is advisory prompt enrichment, not load-bearing dispatch). CLI: `board decide "<text>" [--scope --supersedes]`, `board decisions [--goal]`.
- **D2 `board stats`.** `Board.stats(*, now=None, stall_seconds=None) → BoardStats` computed entirely from existing rows + the append-only audit (no new write-path instrumentation): `false_done` (DONE with no passing `Evidence` — an integrity alarm, impossible via the gate), `redispatched` (items with >1 `planned→running` audit row = work a stale reclaim forced a redo — the *materialised* duplicate-work signal; a purely concurrent claim the CAS averts leaves no trace by design and need not be counted), `reclaimed_stale` (count of `recover_stale_running` reclaims, matched by the shared `_STALE_RECLAIM_NOTE`), and aged `blocked`/`human_required`/`dropped_handoffs` (untouched past `stall_seconds`). `BoardConfig.stall_seconds` (≥1, default 3600) is the aging window (`SYNCMILL_BOARD__STALL_SECONDS`); `build_board` threads it into `Board`. CLI: `board stats`; renderer `render_board_stats`.
- **D3 gateway `board_*` read tools.** `build_gateway(memory, *, board=None, …)` registers three MORE read-only tools — `board_list(state, goal, limit)`, `board_get(item_id)`, `board_stats()` — so the exact-tool-set regression guard goes **3 → 6** (`test_exactly_six_readonly_tools`). The tools are registered **unconditionally** (stable surface) and report `_BOARD_DISABLED` when `board is None`; a `BoardError` surfaces as unavailable (per-call, like the shared tools); `board_list` clamps `limit` to `[1, MAX_BOARD_LIMIT=200]`. **No board-write MCP tool** (read-only + no-auth posture preserved). **Board id (uuid) validation lives in `board.py`** (the single-coupling rule): `Board.get` now rejects a non-uuid id as not-found WITHOUT a query (mirrors `SyncmillMemory.get_shared`; every real id is a `uuid4`). `serve` builds the board best-effort (a corrupt board degrades the board_* tools with a stderr warning rather than killing the shared gateway) and closes it in the `finally`. Board reads are sync sqlite inside the async MCP handlers (quick — no thread offload).
- **D4 board-run global-`shared` union-read.** A board-scoped `SyncmillMemory` view now captures the REAL global `shared` namespace (`_global_shared_ns`, set in `scoped()`); `search_context` UNION-READs it alongside the per-run scope **only when scoped** — so a board run is enriched by cross-run knowledge (prior `board-result` summaries) while its WRITES stay confined to `board-run:{run_id}` (the leak guard is untouched). A plain (unscoped) run is byte-identical (its `_shared_ns` IS global `shared`).

**Phase-2 hermetic tests** (full suite stays green): `test_board.py` (+decisions scope/supersede/retire, stats over a seeded db with the injected clock, `get` uuid-validation, `add`/`add_decision` broad-rollback-on-non-sqlite-error, redispatch-excludes-running-annotation, `build_board` threads `stall_seconds`), `test_memory.py` (the scoped-search test split into a WRITE-leak-guard test + a new UNION-READ test + an unscoped-no-double-read test), `test_gateway.py` (+board_* via a real `Board` on a tmp db: disabled/list/filter/limit-clamp/unknown-state-surfaced/get-found/not-found/malformed-id/stats), `test_supervisor.py` (+decision injection into the prompt, +decision-read-failure degrades-not-blocks), `test_cli.py` (+`board decide`/`decisions`/`stats`, disabled-errors extended). **Phases 3–5 (TUI dashboard; named multi-team profiles; A2A spike) remain deferred.**

### Config (`config.py`)

`SyncmillConfig` is pydantic-settings. Config resolves from three layers, **precedence env > file > defaults** (#11): `SYNCMILL_*` env vars (nested delimiter `__`, e.g. `SYNCMILL_CLAUDE__TIMEOUT_SECONDS`) override a project `syncmill.toml`, which overrides field defaults — so **every field stays env-overridable** (the long-standing invariant) while a checked-in `syncmill.toml` gives a project baseline. The seam is `settings_customise_sources`, which returns the source tuple **in precedence order** (`init_settings, env_settings, dotenv_settings, TomlConfigSettingsSource, file_secret_settings`) — env above the toml source, the toml source above defaults; **`init_settings` stays at the top**, so explicit constructor kwargs win (the programmatic/test path, e.g. `SyncmillConfig(default_strategy="pipeline")`). The CLI flags `--repo`/`--strategy`/`--timeout` do **not** ride that init source — `run` builds a bare `SyncmillConfig()` then **mutates the built config post-construction** (`config.repo_root = repo`, etc.), each only when the flag is actually passed; assigning onto the resolved object trivially overrides every source regardless of tuple order. Sources **deep-merge** nested tables, so an env override of one nested field (e.g. `SYNCMILL_CLAUDE__TIMEOUT_SECONDS`) leaves the rest of that `[claude]` table from the file intact. **Discovery is cwd-relative** (`toml_file="syncmill.toml"`) — not `repo_root`, which the file itself can set (chicken-and-egg); a missing file is silently empty. TOML mirrors env naming exactly: per-agent tables use the **field** name (`[kimi_code]`, underscored), while `[capabilities.agents]` is keyed by the **real agent id** (`kimi-code`, verbatim) — the same underscore-field-vs-verbatim-dict-key split as the env layer. Unknown **top-level** toml keys are rejected (root config is `extra`-default `forbid` → typo protection); per-agent sub-tables stay lenient (`extra="ignore"`). The CLI's `--repo` defaults to `None` (not `"."`) precisely so an unset flag lets `repo_root` come from the file/env instead of clobbering it; orphan cleanup then uses the resolved `config.repo_root`, not the raw flag. Ship `syncmill.toml.example` as the copyable reference; **never commit a real `syncmill.toml`** at the repo root — the hermetic suite builds `SyncmillConfig()` from cwd=repo-root and would pick it up.

### Worktrees (`worktree.py`)

Each worktree is `../.syncmill-worktrees/{agent}-{taskid}-{slot}` on branch `syncmill/{agent}/{taskid}-{slot}`, with a tempdir fallback for non-git repos — living *beside* `repo_root`, not inside it. The `{slot}` is a per-acquire counter `WorktreePool` threads into `create_worktree`: most strategies acquire one worktree per agent, but `DecomposeStrategy` acquires several for the **same** agent (planner + per-subtask + per-synthesizer), and without the slot the second `git worktree add` for that agent would collide on the existing branch/path, fail, and silently fall back to an empty tempdir — so the slot keeps every acquisition a distinct, real git worktree. A run's worktrees are managed by a **`WorktreePool`**: the Supervisor owns one per run and calls `cleanup_all()` in `finally` (each removal independent, so one stuck worktree can't strand the rest), while the *strategy* decides topology — `RouteStrategy`, `CompeteStrategy`, and `CouncilStrategy` `acquire` one isolated worktree per agent so parallel agents never clobber each other and each result's `files_changed` is its own (Council reuses each agent's single worktree across all its propose/critique/synthesize phases); `PipelineStrategy` acquires a single shared one so stages hand files down the chain; `DecomposeStrategy` acquires the most — a scratch worktree for the planner, one per subtask (concurrent isolation), and a fresh one per synthesizer — all torn down the same way (the winner's diff comes from its own synthesis worktree). `cleanup_orphaned_worktrees` still sweeps any leftovers from crashes.

## Design invariants (the maintainer cares about these)

- **Don't pre-abstract.** The package stays flat until the code demands a split. The **first** justified split was `strategies/` (#12), carved out only after all four strategies (Route/Pipeline/Compete/Council) had landed and `supervisor.py` had grown past ~960 lines — the real code pressure the issue gated on, not a speculative one. Everything else stays as top-level modules under `src/syncmill/`; don't carve out further subpackages until they demand it the same way.
- **memtomem is a PyPI dependency** — use it, never reimplement memory. **autocli** is a *pattern* reference only (e.g. the ANSI stripper in `agents.py`), **not a dependency** — don't add it.
- **No `health_check` on agents.** Run, and fall back on failure. Don't add liveness probes to the agent contract. The circuit breaker (#8) is **not** an exception: it skips an OPEN agent based on its *recorded past failures*, never by calling the agent to test it — reactive memory of failure, not a probe.
- **Sync-first orchestration.** `CLIAgent` exposes *both* a sync `execute` (`subprocess.run`) and an async `aexecute` twin (`asyncio.create_subprocess_exec`, plus the `aexecute_all` / `aexecute_isolated` / `aexecute_each` fan-out helpers — the last two sharing one cancel-drain tail, `_gather_or_drain`, so they can't drift) — but the Supervisor and the sequential strategies (route, pipeline) still call only `execute` and stay fully sync. `run_async` bridges memtomem **and** the concurrent path: `CompeteStrategy`, `CouncilStrategy`, and `DecomposeStrategy` are the live consumers — they call `run_async(aexecute_isolated(...))` / `run_async(aexecute_each(...))` to fan agents out over `aexecute` (Council does so once per phase: propose, each critique round, then synthesize; Decompose runs its planner step **sync** via `execute` — a single sequential step needs no fan-out — then fans out the concurrent subtask phase via `aexecute_each` and the synthesis phase via `aexecute_isolated`). The shared-loop rule still holds: do all memory I/O strictly **before/after** each fan-out, never `run_async` from inside the gathered coroutines (that re-enters the running loop) — Council's and Decompose's per-phase `search_context`/`share_result` calls all sit between their fan-outs, never inside them. `aexecute` + per-agent worktrees are the foundation any further concurrent strategy will await; `aexecute_each` (distinct prompt per agent) is the new shape Decompose added beside `aexecute_isolated` (one prompt broadcast to all). Don't async-ify the Supervisor or the sequential strategies until a concurrent strategy actually needs it. The two paths share success/failure classification via `_build_result`/`_failure`, so they can't drift; the deliberate divergences are (a) a timed-out `aexecute` reports empty output (asyncio discards a killed child's buffer) where `execute` keeps `TimeoutExpired.stdout`, and (b) when a live-monitor sink is active (#16, the `_OUTPUT_SINK` contextvar seam) `aexecute` tees output through `_communicate_teed` instead of `communicate()` — same `TaskResult`, but the sink/log sees pre-timeout bytes on a teed timeout (the log is a live view, the result is the contract); with no sink it's byte-for-byte the original path. See the live-monitor section.
- When adding an agent, **verify the real CLI's JSON output format with an actual run first** — CLIs return errors in non-obvious ways (e.g. Claude can exit 0 while returning `{"is_error": true}`, which `ClaudeAgent._is_error_output` specifically catches).
