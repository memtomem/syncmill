# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

syncmill orchestrates multiple CLI coding agents (Claude Code, Codex CLI, Kimi Code) over a single task, giving them a shared long-term memory (memtomem) so they collaborate and compete. It ships three orchestration strategies — `route` (priority fallback), `pipeline` (sequential chain), and `compete` (concurrent head-to-head) — and the architecture is built to grow more (council).

## Commands

```bash
uv sync                              # install deps + create .venv (uses uv, Python 3.12)
uv run syncmill run "<prompt>"       # run a task through the orchestration pipeline
uv run syncmill run "<prompt>" -a claude   # force one agent, no fallback
uv run syncmill run "<prompt>" -s pipeline   # chain agents as sequential stages (default: route)
uv run syncmill run "<prompt>" -s compete   # run all agents concurrently, head-to-head; keep the winner
uv run syncmill run "<prompt>" --exclude claude   # run the rest; drive claude interactively yourself (repeatable)
uv run syncmill run "<prompt>" -r /path/to/repo -t 600   # target repo + timeout override
uv run syncmill agents               # list registered agents in priority order
uv run syncmill status               # check memtomem connection / db path
uv add <pkg>                         # add a dependency (edits pyproject.toml + uv.lock)
uv sync --group dev                  # install dev deps (pytest)
uv run pytest -q                     # run the hermetic test suite (tests/)
uv run pytest tests/test_agents.py -q -k execute   # one file / one pattern
```

The agents shell out to real `claude`/`codex`/`kimi` binaries (note the `kimi-code` agent's binary is `kimi`), so `syncmill run` requires those CLIs installed and authenticated. The **test suite is fully hermetic** — `tests/conftest.py` provides fake agents/memory/store/registry so tests never touch the real `~/.memtomem` DB, the network, or the agent binaries. When adding behavior, mirror the existing pattern: monkeypatch `syncmill.agents.subprocess.run` (sync path) or `syncmill.agents.asyncio.create_subprocess_exec` (async path) for agent execution, inject a `FakeStore` via `make_memory()` for memory logic, inject a `FakeGate` for quality-gate behavior (and exercise the real `CommandGate` with harmless `true`/`false`/`python` commands), and use the `git_repo` fixture for worktree/git tests.

## Architecture

The whole system is one rule made concrete: **the Supervisor is the only component that touches both agents and memory. Agents are pure functions — prompt in, `TaskResult` out — and know nothing about memtomem, each other, or the Supervisor.** This isolation is enforced at the type level: `AgentRunner.execute`/`aexecute`(prompt, workdir, timeout) receive only a `str` prompt. Never thread a `Task`, memory handle, or another agent's result into an agent.

Request flow (`CLI → Supervisor.run`, in `supervisor.py`):

1. `cleanup_orphaned_worktrees` sweeps leftovers from crashed runs.
2. `Supervisor` builds an `AgentRegistry` (priority-ordered, enabled agents) and a `SyncmillMemory`.
3. Per run: build a `WorktreePool` (the strategy acquires worktrees from it), start a memtomem task session.
4. The selected **`Strategy`** executes: it searches memory for context, **enriches the prompt** with it, acquires worktree(s), then runs agents — recording per-worktree `files_changed` on the result it returns.
5. On success: the Supervisor writes that result's summary to the `shared` memory namespace.
6. `finally`: end the memory session, then `pool.cleanup_all()` removes every worktree + branch the run acquired.

### The extension points

- **Agents** (`agents.py`): subclass `CLIAgent`, implement `_build_command`, and override `_parse_output` / `_is_error_output` for that CLI's output format — you get both the sync `execute` and the async `aexecute` paths for free from the base class. Register the class in `_AGENT_CONSTRUCTORS`, add a matching `AgentConfig` field in `config.py` (an id with a hyphen — e.g. `kimi-code` — uses the underscore field name `kimi_code`, which `SyncmillConfig.agent_config` maps for you), and add the id to `agent_priority`. Output formats differ per CLI: Claude extracts the `result` key from its JSON, Codex joins `agent_message` items from its JSONL, and Kimi Code (`kimi`) keeps the `role:"assistant"` text lines from its `stream-json` JSONL. Only Claude exits 0 on an in-band error (hence its `_is_error_output`); the others signal failure with a non-zero exit.
- **Strategies** (`supervisor.py`): implement the `Strategy` Protocol and register it in `_STRATEGIES`, then select it via `default_strategy` (or the `--strategy/-s` CLI flag). `_make_strategy` raises on an unknown name — mirror that hard-fail rather than silently defaulting. Three strategies exist: `RouteStrategy` (try agents in priority order, fall back on failure, aggregate errors if all fail), `PipelineStrategy` (run agents as sequential stages — each reads prior stages' results from `shared` and writes its own there, fail-fast on a broken stage; the prompt enricher `_enrich_prompt` is shared by all), and `CompeteStrategy` (run every agent **concurrently**, each in its own worktree, then keep a winner). Each strategy is handed a `WorktreePool` and owns its worktree topology — Route/Compete acquire one isolated worktree per agent, Pipeline a single shared one — and sets per-worktree `files_changed` (via `_collect_files_changed`) on the result it returns. `CompeteStrategy` is syncmill's first *concurrent* strategy: it bridges async via `run_async` over the `aexecute_isolated` fan-out (per-agent worktree + per-agent timeout), and picks the winner deterministically in `_select_winner` — the **first gate-passing COMPLETED result in priority order** (never wall-clock/`duration_seconds`), aggregating failures like Route when none qualify. `_select_winner` is where quality gates (#10) plug in: with a gate it ranks completers by verified pass with priority as the deterministic tie-break (see the quality-gates extension point below); it does **not** auto-apply the winner's diff (worktrees stay disposable — the Supervisor shares the winner to `shared` and tears every worktree down). CouncilStrategy is the remaining planned v0.3 addition — the registry, the prompt-only agent contract, the async `aexecute` path, and per-agent worktrees exist to make it drop-in.
- **Quality gates** (`gates.py`, #10): a gate validates an agent's work **after it finishes**, against the diff in that agent's worktree — reactive, never a pre-run liveness probe (respects "no `health_check`"). Implement the `QualityGate` Protocol (`evaluate(worktree) -> GateReport`); the shipped `CommandGate` runs each configured command (via `shlex.split`, no shell — chain checks by adding entries, not `&&`) and passes iff all exit 0. `build_gate(config.gate)` returns the gate or **`None` when no commands are configured** — the disabled default, so behavior is unchanged out of the box (set `SYNCMILL_GATE__COMMANDS='["pytest -q", ...]'`). The gate is plumbed through the **strategy layer only** — agents stay pure `(prompt, workdir, timeout)` functions and never see it. The Supervisor builds it per-run and injects it into `Strategy.execute(..., gate=)`; the shared `_gate_accepts` helper means "passed the gate" is one thing everywhere: pass → accept; fail → downgrade the result to FAILED with a gate error (attached as `result.gate`) so the rejection flows through the existing failure plumbing. Each strategy applies that verdict per its topology — **Route** falls back to the next agent, **Pipeline** fails the chain (gating only the final cumulative tree, since intermediate stages may legitimately be broken mid-chain), **Compete** downranks failers in `_select_winner`. A gate-rejected result is never shared to `shared` (it's a FAILED result, which the Supervisor already skips).
- **Circuit breaker** (`breaker.py`, #8): reactive per-agent back-off from *repeatedly* failing agents — `RouteStrategy` already falls back on one failure, the breaker remembers failures **across runs**. `CircuitBreaker` tracks consecutive failures per agent: after `failure_threshold` in a row the circuit **opens** (the agent is skipped) for `cooldown_seconds`, then goes **half-open** (one trial), and any success **closes** it (resets the count). The three states are derived from `(failures, opened_at)`, never stored. **Reactive, not a `health_check`:** `allows()` decides purely from *recorded past outcomes* — it never calls an agent to test liveness; skipping an OPEN agent is "it kept failing when we ran it," not a probe. State **persists** to `state_path` (JSON, atomic temp+`os.replace`) loaded on construction — this is mandatory, since each `syncmill run` runs an agent at most once, so "N in a row" only accumulates across separate invocations. `build_breaker(config.breaker)` returns **`None` when `enabled=False`** (the default), so the disabled path never touches the filesystem and behavior is unchanged. Like the gate it's plumbed through the **strategy layer only** (agents never see it); the Supervisor builds it once (it carries cross-run state + a `degraded` flag the CLI surfaces, unlike the stateless per-run gate) and injects it into `Strategy.execute(..., breaker=)`. Shared helpers keep it uniform: `_breaker_runnable` drops OPEN agents (all three strategies skip them; Route falls back, Pipeline chains the remaining stages, Compete fans out only the survivors — all three return `_breaker_all_open_failure` if the breaker tripped everyone), and `_breaker_record` records each run agent's **RAW execution status taken *before* the gate** — so a gate rejection (a quality verdict on a *working* agent) does **not** trip the breaker; only an agent that fails to *run* does. Best-effort/advisory like memory: a broken state file degrades (permissive — `allows()` returns True for everyone) and never aborts a task.

### Memory (`memory.py`)

`SyncmillMemory` wraps memtomem's `MemtomemStore` with syncmill conventions: namespace `agent-runtime:{agent_id}` is private per agent, `shared` is the cross-agent knowledge base (both derived from `memtomem.constants` — `AGENT_NAMESPACE_PREFIX`/`SHARED_NAMESPACE` — so they track memtomem's scheme; matches the 0.2.x MCP multi-agent tools). The Supervisor is the **sole reader/writer** — there is intentionally no MCP sharing between agents. memtomem is async, and so is the agents' `aexecute` path; syncmill's orchestration (Supervisor, route/pipeline strategies) is sync. `run_async()` bridges async into that sync world by **reusing a module-level event loop** — do not switch to `asyncio.run()`, which closes the loop and breaks memtomem's later embedding calls (a fixed bug); `close_event_loop()` releases it at CLI shutdown.

**Memory is advisory/best-effort.** Every `SyncmillMemory` method catches its own exceptions, logs a warning, sets `degraded`/`last_error`, and returns a safe default. A broken or misconfigured memtomem (e.g. an unsupported embedding provider) must never abort a task — the agent still runs, just without shared context. Preserve this when editing memory or the Supervisor; the CLI surfaces `supervisor.memory.degraded` as a yellow notice. Note memtomem applies `~/.memtomem/config.json` *last* (inside `create_components`), overriding both env vars and programmatic `config_overrides` — so the embedding provider is governed by that global file, and syncmill shares `~/.memtomem/memtomem.db` by default.

### Interactive collaboration (human drives one agent, syncmill runs the rest)

Programmatic `claude` runs may be billed separately from interactive use. To keep Claude **interactive** while syncmill orchestrates the others: exclude claude from the run (`run … --exclude claude`, repeatable; or persistently via `SYNCMILL_CLAUDE__ENABLED=false`) and drive Claude yourself in the terminal. The two sides collaborate **only through the `shared` namespace** — never by syncmill invoking claude, so the agent-isolation invariant is untouched (the interactive session is a separate process, not a syncmill agent).

This needs zero extra wiring: syncmill's `SyncmillMemory` and memtomem's MCP multi-agent tools use the **same `shared` literal on the same `~/.memtomem/memtomem.db`** (exact-match namespaces). The one rule — the interactive session must target `shared` **explicitly**, because its default namespace is cwd-scoped (`claude:<cwd>`), which syncmill does not read.

- Interactive session **writes** (so syncmill sees it): `mem_add(content=..., namespace="shared")`, or `mem_agent_share(chunk_id=..., target="shared")` to promote an existing chunk.
- Interactive session **reads** syncmill's results: `mem_agent_search(query=..., include_shared=True)` or `mem_search(query=..., namespace="shared")`.
- syncmill side is unchanged: `share_result` writes the winner to `shared`; `search_context` reads `shared` to enrich the programmatic agents' prompts.

Collaboration is via shared *knowledge*, not file merges: the interactive session edits your real working tree while syncmill agents edit isolated worktrees, so syncmill's diff never sees the interactive edits. `CompeteStrategy` now runs the syncmill *agents* head-to-head; entering the human's interactive session as a competitor judged alongside them is still future work (the interactive session is a separate process, not a syncmill agent).

### Config (`config.py`)

`SyncmillConfig` is pydantic-settings. Every field is overridable via `SYNCMILL_*` env vars (nested delimiter `__`, e.g. `SYNCMILL_CLAUDE__TIMEOUT_SECONDS`).

### Worktrees (`worktree.py`)

Each worktree is `../.syncmill-worktrees/{agent}-{taskid}` on branch `syncmill/{agent}/{taskid}`, with a tempdir fallback for non-git repos — living *beside* `repo_root`, not inside it. A run's worktrees are managed by a **`WorktreePool`**: the Supervisor owns one per run and calls `cleanup_all()` in `finally` (each removal independent, so one stuck worktree can't strand the rest), while the *strategy* decides topology — `RouteStrategy` and `CompeteStrategy` `acquire` one isolated worktree per agent so parallel agents never clobber each other and each result's `files_changed` is its own; `PipelineStrategy` acquires a single shared one so stages hand files down the chain. `cleanup_orphaned_worktrees` still sweeps any leftovers from crashes.

## Design invariants (the maintainer cares about these)

- **Don't pre-abstract.** The package is intentionally flat (8 files under `src/syncmill/`). Don't split into subpackages until the code demands it.
- **memtomem is a PyPI dependency** — use it, never reimplement memory. **autocli** is a *pattern* reference only (e.g. the ANSI stripper in `agents.py`), **not a dependency** — don't add it.
- **No `health_check` on agents.** Run, and fall back on failure. Don't add liveness probes to the agent contract. The circuit breaker (#8) is **not** an exception: it skips an OPEN agent based on its *recorded past failures*, never by calling the agent to test it — reactive memory of failure, not a probe.
- **Sync-first orchestration.** `CLIAgent` exposes *both* a sync `execute` (`subprocess.run`) and an async `aexecute` twin (`asyncio.create_subprocess_exec`, plus the `aexecute_all` / `aexecute_isolated` fan-out helpers) — but the Supervisor and the sequential strategies (route, pipeline) still call only `execute` and stay fully sync. `run_async` bridges memtomem **and** the concurrent path: `CompeteStrategy` is the live consumer — it calls `run_async(aexecute_isolated(...))` to fan agents out over `aexecute`, the first use of `run_async` for *agent* execution (previously only memtomem). The shared-loop rule still holds: do all memory I/O strictly **before/after** the fan-out, never `run_async` from inside the gathered coroutines (that re-enters the running loop). `aexecute` + per-agent worktrees remain the foundation the next concurrent strategy (council) will await. Don't async-ify the Supervisor or the sequential strategies until a concurrent strategy actually needs it. The two paths share success/failure classification via `_build_result`/`_failure`, so they can't drift; the one deliberate divergence is that a timed-out `aexecute` reports empty output (asyncio discards a killed child's buffer) where `execute` keeps `TimeoutExpired.stdout`.
- When adding an agent, **verify the real CLI's JSON output format with an actual run first** — CLIs return errors in non-obvious ways (e.g. Claude can exit 0 while returning `{"is_error": true}`, which `ClaudeAgent._is_error_output` specifically catches).
