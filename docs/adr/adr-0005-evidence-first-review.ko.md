# ADR-0005 — 검증 증거와 사람의 판단을 연결하는 작업 흐름

Status: **Proposed** · Date: 2026-10-16

제품 수준 ADR이며 기존 ecosystem ADR과 저장소 전체 번호를 공유한다.
[ADR 목록](README.md) · [영어 정본](adr-0005-evidence-first-review.md).

## 배경

SyncMill에는 격리 실행, Rooms 후보 보존, 품질 게이트, 명시적 apply, 공유 메모리,
board decision이 있다. 하지만 사용자는 후보별 증거를 모아 판단하고, 수정 요청을
다음 prompt에 옮기며, 무엇을 채택했는지 별도로 기억해야 한다. 단순한 병렬 실행은
이미 [Conductor](https://www.conductor.build/docs) 등에서도 제공한다. 차별화는
기능 수보다 **검토 가능한 변경을 선택하고 적용하는 데 드는 사람의 시간**으로 검증한다.

이 ADR은 제품 방향과 증거 의미에 대한 제안이다. 현재 API나 기존 메모리 동작을
변경하지 않으며 구현 완료·사용자 수요 확인·독점적 차별성을 뜻하지 않는다.

## 제안하는 결정

- 개인 개발자·소규모 팀을 첫 대상으로, 하나의 작업에서 시작 → 후보 비교 →
  수정 요청 → 검토 → 명시적 적용을 연결한다. 기본 비교 단위는 같은 소스 기준과
  검증 설정을 가진 **Rooms의 후보**다. 기존 `compete`의 lazy gate/승자 보존 계약을
  바꿔 모든 실행을 비교 가능한 것으로 표시하지 않는다.
- 후보의 완료, gate 통과, 선택, apply 성공, 사용자의 수용을 별도 사실로 취급한다.
  gate 미설정/미실행, 없는 usage, 실패한 복구는 unknown을 유지한다. gate 통과는
  명세 전체의 정답이나 보안 보장을 뜻하지 않는다.
- 피드백은 candidate ID와 patch digest에 연결하고 수정 결과는 새 후보로 남긴다.
  기존 후보·검증 결과·선택 이력을 덮어쓰지 않는다. 새 후보에 이전 gate 결과를
  승계하지 않고, 파일 위치가 달라지면 줄 단위 피드백은 stale로 표시한다.
- 사람의 선택 이유·수용 여부는 내구성 있는 별도 판단 기록에 보존한다. 실행 상태의
  정본은 기존 store이며, 메모리 검색 결과나 모델 요약이 상태를 바꾸지 않는다.
  apply receipt가 있어도 사용자 만족이나 운영 성공을 추론하지 않는다.
- 재사용할 교훈은 사람이 명시적으로 선택한 내용만 프로젝트 범위로 승격한다.
  기존 board decision과 같은 범위·대체 관계를 재사용하고 독립된 상충 규칙 체계를
  만들지 않는다. 기존 task-result/room-result 공유는 유지하되 이를 자동으로
  “검증된 지식”으로 승격하거나 과거 자료에 수용 상태를 소급 부여하지 않는다.
- 로컬 검토용 묶음은 명시적으로 export한다. 기본값은 요약·해시·검증 상태이며,
  prompt·전체 로그·원문 patch는 포함 항목을 미리 보여 준 뒤 선택하도록 한다.
  export는 PR 게시나 외부 서비스 업로드를 포함하지 않는다.

## 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 먼저 웹 Kanban/더 많은 provider/클라우드 실행을 추가 | 지원·운영 범위가 커지며 기존 CLI/TUI의 선택·검토 부담을 직접 줄이지 못함. 구체적 사용자 요구 전까지 보류 |
| LLM 점수로 항상 최선 후보를 자동 적용 | 추가 비용과 평가 오류를 숨길 수 있음. 기존 명시적 apply 및 unknown 원칙과 맞지 않음 |
| 비교 화면만 추가 | 첫 개선으로 유용하나 수정 요청과 다음 작업에서의 재사용까지 이어지지 않음. 순차 배포하되 전체 흐름의 첫 단계로 취급 |
| 검증 증거·판단·후속 수정을 연결 | 기존 자산을 활용하며 관측 가능한 사용자 시간을 줄일 수 있는 가설. 권고안 |

## 영향과 검증

제품 상태나 공개 telemetry schema를 이 문서만으로 확장하지 않는다. 필요한
read model·판단 기록·피드백 API는 연결 이슈에서 버전·호환성을 명시하고 추가한다.
로그와 프롬프트를 body-free telemetry에 넣지 않는다. 전역 사용 통계 수집은 기본 OFF다.

먼저 기존 데이터로 비교 화면과 무료 체험을 만들고, 이후 후보별 수정과 판단 기록을
연결한다. 초기 사용자 6명을 대상으로 동일 난이도의 3개 작업을 순서 교차 배정하여
현재 흐름과 비교한다. 검토 시간·첫 검증/적용까지 시간·잘못된 승인·UNKNOWN 인지를
측정한다. 20% 시간 단축은 목표 가설이며 현재 측정 결과나 통계적 유의성 주장이 아니다.
안전성 지표가 악화되면 시간 단축만으로 다음 단계를 승인하지 않는다.

한 번의 사용자 연구나 편향된 로컬 실행 이력으로 모델 자동 라우팅을 활성화하지 않는다.
기존 model-routing observe→평가→enforce 원칙과 A2A 보류 결정을 유지한다.
