# Run reports (`report.py` — run identity S2 + the envelope writer S3 of the ecosystem plan)

> Design record for `report.py`, moved verbatim from `CLAUDE.md`. `CLAUDE.md` keeps a
> short rule list for this module; this file holds the full reasoning, history and test map.

`report.py` is the flat module for the **run-envelope join artifact** of the toolgraph/tracegraph/syncmill ecosystem (`contracts/run-envelope.schema.json`, shipped with fixtures + `tests/test_contracts.py` in S1). Two halves. **Identity (S2):** `resolve_run_id(explicit)` is the single resolver every path converges on — precedence **explicit > monitor-inner env > fresh uuid4**: board `run_item` passes its lease/scope run_id (lease, `board-run:{run_id}` memory scope, and envelope are provably ONE id — no double issuance); a monitored run's OUTER mints the id (it never builds a Supervisor) and propagates it via the 0600 env snapshot as `SYNCMILL_RUN_ID` (never argv), honored ONLY when `inner_dir()`'s env-var+sentinel double-check confirms this process is the in-tmux inner (a stray exported `SYNCMILL_RUN_ID` can never leak into a normal run); a direct run mints fresh. **Writer (S3):** `build_reporter(config.integration.report)` returns **`None` when disabled (the default — zero filesystem touch, byte-identical behavior)**; enabled, the Supervisor-built `RunReporter` writes `{runs_dir}/{run_id}/envelope.json` (default `~/.syncmill/runs`) — `start()` right after the candidate lineup exists (retention sweep + a **fully schema-VALID skeleton**: honest `result.status:"failed"`, `finished_at == created_at`, every sub-block present — `finished_at` is required non-nullable, so even a SIGKILL'd run leaves a parseable artifact for the contract's strict consumers), `finish()` **first in `run`'s `finally`** — before `monitor.finish` (whose result.json unblocks the OUTER, whose report-path print is existence-gated) and before `pool.cleanup_all()` (no worktree race: patch/files_changed were already captured by `_collect_files_changed`). The envelope is **body-free by contract**: digests (`sha256:<64hex>`) and counts only — never prompts/output/patch content/file-path lists; `finish` writes the one body-carrying artifact `result.json` into the run dir via **`monitor._result_to_json`** (the mandated private cross-import, `session.py` precedent, so the payload can't drift from the monitor's IPC file), digests the exact bytes written, and digests the patch over the same surrogateescape bytes `emit_patch_file` writes (the digest verifies the actual `--emit-patch` file). **Everything degrades** (the memory idiom): `RunReporter` methods catch `(OSError, ValueError, RuntimeError)` (RuntimeError = no-HOME `expanduser`, the board lesson) and warn; the Supervisor wraps `start`/`finish` in belt-and-suspenders `except Exception` guards (the `monitor.finish` discipline) so nothing report-shaped can ever skip the memory-session close or worktree cleanup. **Not threaded into `Strategy.execute`** — the reporter is Supervisor-run-lifecycle-level like `_matched_order`/the board (it only consumes the returned `TaskResult`); agents stay pure. **3-path unification:** direct — the Supervisor writes it and the CLI prints `[syncmill] report: <path>` from the `supervisor.last_report_path` seam after `render_task_result`; monitored — the INNER (the real Supervisor) writes under the OUTER-minted id and the OUTER prints the same line after `render_result`, **gated on the envelope actually existing** (the OUTER can't know the inner's config; `launch_monitored_run(report_runs_dir=)` takes a plain path — monitor never imports report, acyclic); board — `run_item` best-effort **patches the `board` block** (`patch_envelope_board`, a read-modify-write atomic rewrite) after `apply_update`, deliberately NOT gated on the lease fence (the fence protects the board/shared system of record; the envelope records what THIS run worked on) — on a crash the block honestly stays `null`. The envelope's `team` comes from **`config.applied_team`**, stamped by `apply_team` (covers direct/inner-forwarded/board paths by construction); `degraded` lists the run's degraded best-effort subsystems (`memory`, `breaker` — open vocabulary). **Retention** is Supervisor-level, never the CLI (it must cover all three producer paths): oldest owned run dirs beyond `keep_last` (≥1, default 50, counting the current run) are removed, the current run_id always excluded, each removal independent, and **only directories syncmill marked as its own** are candidates at all, since `runs_dir` is free-form user config and an unmarked dir is somebody else's data (the `monitor.py`/`session.py` sentinel rule). The marker is `RUN_DIR_SENTINEL`, written by BOTH producers — `RunReporter._ensure_run_dir` and `FileTracer._write` (the trace-only path creates the dir itself, so `tracer` imports that one constant from `report`; acyclic, since `report` never imports `tracer`). Run dirs predating the marker are accepted via their envelope, but **only** when it parses, carries syncmill's `kind`, AND names its own directory — a filename alone is never ownership (`result.json` is as generic as names get, and a foreign dir holding one must survive). `_sweep_retention` has **two callers** sharing that one implementation so the semantics can't drift — `RunReporter.start()` when reporting is on, and the public `sweep_runs_dir(runs_dir, keep_last, current_run_id)` wrapper the Supervisor calls when reporting is OFF but tracing is on (the tracer's default dir is this same tree, so `build_reporter`'s `None` would otherwise leave it unowned; see the tracer section). The wrapper degrades on every **ordinary** exception (`except Exception` inside, no caller guard) rather than relying on a belt-and-suspenders call site like `start`/`finish`, because it is called *inside* `run`'s try — whose `except BaseException` marks the run artifact recovery-required, so a raising sweep would falsely condemn a healthy run. `BaseException` is deliberately not caught: an interrupt belongs to that finalization path. **Atomic writes use the breaker `mkstemp` recipe** (unique temp in the same dir + `os.replace` — collision-safe for a `finish`/`patch_envelope_board` overlap, unlike monitor's single-owner `.tmp` sibling). The run dir's lifetime is retention-owned — never couple it to `_gc_board_run_namespaces` (the memtomem scratch GC). Read surface: `syncmill report list` / `report show <run_id>` (`list_reports`/`load_envelope`/`render_report`) are **read-only viewers that work while writing is disabled** (the `team list` posture). Config: `[integration.report]` / `SYNCMILL_INTEGRATION__REPORT__ENABLED` — `IntegrationConfig` nests `report` because the design doc reserves sibling `[integration.*]` tables for the tracer/toolgraph stages (`[integration.trace]` shipped as S3′ and `[integration.toolgraph]` as S5, both below — sub-blocks are ALWAYS present, consumers never branch on absence; `finish(trace=, preflight=)` merges the real blocks over the skeleton's disabled defaults, which stay `disabled` on the SIGKILL path). Hermetic tests validate **every generated envelope against the real schema + the `test_contracts` redaction `_scan`** (`test_report.py` writer/retention/digest-stability matrix, `test_supervisor.py` per-path goldens incl. the inner seam + crash + degrade-never-strands-cleanup + reporter-before-monitor ordering, `test_cli.py` report group + report-line + OUTER pass-through, `test_monitor.py` existence-gated print).
