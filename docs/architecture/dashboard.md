# TUI dashboard (`dashboard.py`, Phase 3 — 보드 관제)

> Design record for `dashboard.py`, moved verbatim from `CLAUDE.md`. `CLAUDE.md` keeps a
> short rule list for this module; this file holds the full reasoning, history and test map.

**Current report slice:** `p` opens a read-only `ReportScreen` modal over
`config.integration.report.runs_dir`: `list_reports` supplies newest-first rows,
`render_report` supplies byte-identical detail to `report show`, and `r` reloads
while the modal is open. Viewing is not gated on report recording being enabled.
The app-owned `report_detail_text` seam is tested headlessly alongside the TEAM
pane seams. This extends the original board/config touch boundary with read-only
run-envelope filesystem access; it still never touches agents, memory, or MCP.

`syncmill dashboard` is a **live Textual TUI over the work-board** — a polling item table + detail pane (the `render_item`/`render_board_stats` strings verbatim, so it reads byte-identically to `board show`/`board stats`) + a stats overlay, with the **human-path edits bound to keys**: `e` opens a modal mirroring `board update` 1:1 (state/note/evidence-ref/sign-off/clear-human-required), `u` unblocks, `h` clears human-required, `f` cycles the state filter, `r` refreshes, `s` shows stats, and (the P3 TEAM-pane follow-up) `t` opens the **TEAM pane** — a `TeamScreen` modal (StatsScreen shape, deliberately NOT a TabbedContent restructure) listing the configured profiles with a `* (default)` marker, detail = the shared `teamfile.render_team` verbatim (byte-identical to `team show`); inside it `e` opens `TeamEditModal` (dumb like `EditModal` — dismisses raw strings; all parsing/validation in the app funnels) and `u` toggles the highlighted team as the persisted default. The TEAM writes funnel through `_apply_team_save`/`_apply_default_team` — EXACTLY the `team save`/`team use` recipe (both-view validation, comment-preserving write); a rejection mirrors into `last_team_error` (+ error toast) and the app never dies; after every successful write `_reload_teams` re-reads config via `teamfile.load_config_at(self._toml_path)` — pinned to the exact injected path, never the ambient cwd (a codex design-review Major). `config`/`toml_path` are threaded `cli dashboard → run_dashboard → DashboardApp` as OPTIONAL kwargs (board-only constructions untouched; `t` without them degrades to a notice). A **new flat top-level module** (gateway/monitor/session/board precedent; no new config table — `--refresh` + module constants, the session.py call). Original locked scope (maintainer-approved via AskUserQuestion): **BOARD+RUNS-as-polling first PR**, TEAM pane as this follow-up; the board data source is **polling board.db only** (WAL — readers never block against a live `board run` writer; no Supervisor changes, no run-events stream). Invariants: a **separate observer/editor process**, never on the orchestration thread (the tmux monitor outer/inner rationale); not an agent, not a strategy; touches the board — and, for the TEAM pane, the project `syncmill.toml` via the `teamfile.py` write helpers — still never memory, never agents (the Supervisor invariant untouched); every board write is an in-process `board.py` call with `actor="human"` — EXACTLY the `board update` recipe, so the audit trail is surface-independent — and **never** the read-only MCP gateway. Reads stay **inline on Textual's event-loop thread**: the Board connection is `check_same_thread=True` (a thread worker would raise; a future async refactor needs a dedicated reader connection, not a thread hop). Poll reads are **best-effort** (a mid-run `BoardError` → DEGRADED status notice, last good snapshot stays on screen, app lives); the **launch hard-fails** (session precedent, no fallback): `_require_board` → TTY gate (before the db is opened) → `build_board` `BoardError`→`ClickException`, board closed in the CLI `finally` (the app never opens/closes it — `serve`'s memory-ownership precedent). The seam tests patch is `syncmill.cli.run_dashboard` + `syncmill.cli._stdout_isatty` (lookup-site, the `session._tmux` lesson). Testability is structural: `take_snapshot(board, state=, selected_id=, now=) -> BoardSnapshot` is the pure fetch seam (unit-tested against a real Board, no Textual); the interval timer's callback IS `action_refresh` (same path as the `r` key and the post-edit refresh), so `tests/test_dashboard.py` builds apps with `refresh_seconds=3600` and drives every tick explicitly under headless `App.run_test()` — no timer waits, no real TTY; edit-matrix coverage goes through the single write funnel `_apply_update` directly (one modal end-to-end test proves the widget plumbing), and assertions target app-owned seams (`status_text`/`detail_text`/`last_action_error`, plus the TEAM-pane mirrors `team_detail_text`/`last_team_error`), never Textual widget internals (version-shifty across textual's 1.x→8.x majors); the TEAM-pane tests follow the same recipe (funnel-direct matrix + one `TeamEditModal` end-to-end + a `u`-toggle end-to-end, config loaded from a tmp toml via `load_config_at`). `textual` is a direct dependency (floor = the uv-resolved version actually tested); its `rich` comes bundled — don't add rich directly.
