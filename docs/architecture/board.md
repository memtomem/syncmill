> - "`run` gains exactly **one optional kwarg `memory=`**" — `run_item` also passes `run_id=` and `enable_routing=False` (`supervisor.py`, `run_item`).

The `board` command group turns syncmill from a single-run, stateless orchestrator into one with **durable, structured records of team work** — goal, owner, state, what's blocked/why, what's done **and verified**, dependencies, and a handoff baton. It is a **new flat top-level module** (gateway/monitor/session precedent — *don't pre-abstract*) backed by its **own SQLite store** at `~/.syncmill/board.db`: memtomem can't back it (markdown+embedding *knowledge* chunks have no structured status/dependency fields, no state machine, no atomic compare-and-swap). *State lives only on the board; knowledge lives only in memtomem's `shared`; the two cross-link by id.* Five locked design decisions (codex-reviewed pre-code over 5 rounds):

1. **Applied at the Supervisor run-lifecycle level, NOT threaded into `Strategy.execute`** — like `_matched_order`, the board has no topology-specific meaning. A new `Supervisor.run_item` *wraps* `run`; the **`Strategy` protocol is unchanged**; `run` gains exactly **one optional kwarg `memory=`** (`mem = memory or self._memory`, used at ALL five memory call sites — register/start_session/strategy/share/end — so plain `run` is behavior-identical). 2. **Agents stay pure** — orchestrated agents NEVER touch the board; the Supervisor mediates by rendering the item into the prompt (`render_item_prompt`, deterministic) and parsing an OPTIONAL ` ```syncmill-board ` fenced block back out of `result.output` (`parse_board_update` — its OWN parser, NOT a reuse: it degrades to `{}` and **NEVER raises** — incl. on pathologically-nested JSON, whose `json.loads` raises `RecursionError`, a `RuntimeError` not a `ValueError`, so it is caught explicitly. Recognized fields are sanitized **individually** (one malformed field can't discard a valid `state`); the all-or-nothing part is the `outputs` **list** (a mixed list is dropped whole, never salvaged to a subset — the `DecomposeStrategy._parse_subtasks` *philosophy*). `_extract_board_block` requires a genuine close fence — a 2nd `syncmill-board` OPEN fence is never mistaken for the first block's close, matching `strip_board_block` so the parser and the stripper agree on block bounds). 3. **The board store is LOAD-BEARING, built LAZILY** — it's the source of work + system of record, so unlike memory/breaker it does **not** degrade silently: a corrupt/unopenable db raises `BoardError` (caught at `Board.__init__` for `sqlite3.Error` — a corrupt file, `OSError` — an unwritable parent dir, *and* `RuntimeError` — an unresolvable `~` when no home dir is set; `expanduser()` runs **inside** that try so `Board()` raises **only** `BoardError`, the contract `serve` relies on to catch a bad board and still close memory in its `finally`) → the CLI converts to `click.ClickException` (the `session.SessionLaunchError` "no fallback — it IS the feature" contract). Disabled by default (`build_board`→`None`); the Supervisor builds it lazily on first `run_item` (stored on `self._board`, closed in `close()`), **NOT** in `__init__`, so an enabled-but-corrupt board can never break a plain `run` (which never calls `run_item`). 4. **State machine `planned → running → (blocked | review) → done`**, where **`review` vs `done` = "done AND verified"**, load-bearing in `Board.transition`: a move TO `done` requires ≥1 passing structured `Evidence` (a `GateReport` maps to one) OR a human sign-off (`Evidence{kind:"human"}`), else `BoardError` — a bare `board update ID --state done` is rejected (the human CLI path). An AGENT's advisory `state:done` is honored only when **THIS run** produced passing verification (a gate that passed *this* run) — stale evidence from an earlier, now-discarded run does NOT certify the current work (`apply_update` gates the advisory `done` on the run's own evidence, while still persisting the accumulated evidence that backs the human `review→done` promotion); otherwise it is CLAMPED to `review`+audit (**never raises** — a good run is never turned `blocked` by an invalid advisory field). The human path also rejects a manual move INTO `running` (it is owned by the claim lease, never set by hand — `board update` does not offer it). Dependencies gate dispatch; an **atomic claim** (`BEGIN IMMEDIATE` CAS `planned→running`, stamping `lease_run_id`+`claimed_at`) is the no-duplicate-work guard on **every** path (`claim` by-id and `next_runnable` alike — opened in autocommit `isolation_level=None` so writers drive `BEGIN IMMEDIATE`/`COMMIT` by hand; WAL + `busy_timeout`); `human_required` items are excluded from auto-dispatch; FIFO order is `created_at, rowid` (rowid breaks same-clock-tick ties so insertion order holds). Append-only `transitions` audit table. **Stale-claim recovery** `recover_stale_running()` reclaims items past `lease_timeout_seconds` from `running`→`planned` (the `cleanup_orphaned_worktrees`/`_sweep_stale_session_dirs` analogue), run at the top of every `run_item`. The lease is the **fencing token**, not just a dispatch guard (adversarial-review catch): `apply_update(run_id=)` is a **lease-fenced CAS** (`WHERE id=? AND state='running' AND lease_run_id=?`) so a slow run whose item was reclaimed + re-dispatched to another runner can't clobber the new owner or revert a verified `done` — its stale write is dropped; the **crash-block path is fenced the same way** (`Supervisor._block_on_crash` threads `run_id` into `transition(run_id=)`, an identical `WHERE state='running' AND lease_run_id=?` CAS that drops a 0-row match), so a stale *crashed* run can't clobber a re-dispatched owner or revert a verified state either — including a crash AFTER `apply_update` already resolved the item (e.g. Ctrl-C during the shared-memory write), since the item has then left `running`; and `transition` preserves the lease on a *same-state annotate of a running item* (only clearing it when actually leaving `running`) and resolves a no-`--state` annotate's target from its **in-transaction** read (a `to_state=None` sentinel, never a stale pre-read), so a `board update` annotation can't strand a live claim into stale-recovery. Every transactional method rolls back on **any** exception (not only `sqlite3.Error` — e.g. a corrupt-row `ValueError`), so a `BEGIN IMMEDIATE` write lock is never leaked. 5. **The board↔`shared` boundary is closed via a per-run memory scope** — `run_item` runs the item through the normal pipeline with a **board-scoped `SyncmillMemory.scoped(run_id)`** that collapses BOTH the shared namespace AND every per-agent (session/search) namespace to `board-run:{run_id}` (via a single `_agent_ns` seam). So the strategy-internal shares (pipeline/council/decompose) AND `start_task_session`'s prompt-log all write to the per-run scope — intra-run handoff still works — and **nothing board-enriched leaks into the persistent global `shared` or `agent-runtime:*`**. After the strategy returns, `run_item` writes ONE sanitized summary to GLOBAL `shared` via `SyncmillMemory.share_board_result(item_id, task, strip_board_block(output))` (built from the item task + the agent output with the `syncmill-board` block stripped — never the enriched prompt); the **cross-link is the SINGLE composite tag `board-result:{item_id}`** (memtomem `add()` returns no chunk id; `search(tag_filter=...)` is a `str`/comma-OR, NOT a list). Decisions + the handoff baton are injected DETERMINISTICALLY from the board into the prompt, never via top-k recall (**Phase 2 (D4)** additionally has board runs **union-read** global cross-run `shared` — the scoped view's *reads* widen to the real `shared` while its *writes* stay confined to `board-run:{run_id}`, so the leak guard is untouched). The per-run `board-run:{run_id}` scratch namespaces are **GC'd automatically** after a run outcome or an empty claim, using `Board.collectible_board_run_ids(limit=100)` to read ownership and liveness in one SQLite snapshot. Claims atomically write their lease and ledger row; active leases and reclaimed-run grace remain protected. The sweep excludes the just-finished run, takes a nonblocking board-specific cross-process GC lock, and tombstones only backend-acknowledged deletions. Failure backoff prevents a poisoned namespace from monopolizing later sweeps. The exiting run reactivates its ledger row in `finally`; a process killed between a late write and this finalizer can still leave residue. Collection is advisory and can remove scratch from a slow run after reclaimed-lease grace expires. `delete_board_runs` reconstructs `board-run:` from ledger IDs, preserving `shared` and `agent-runtime:*`. Optional atomic backend purge and its limits are described above; historical mixed shared day files require manual review. See [the stabilization roadmap](../improvement-roadmap-2026-09-08.ko.md) for evidence and recovery boundaries.

`run_item` flow: `_require_board` (lazy build; clear error if disabled) → `recover_stale_running()` → atomically claim (`claim(id)` or `next_runnable(run_id)`; `None` stops a `--loop` caller) → `Task(prompt=render_item_prompt(item))` → `run(memory=scoped)` → `parse_board_update(result.output)` → `board.apply_update(...)` [advisory] → `share_board_result(...)` to global shared. Wrapped in `try/except BaseException` → a genuine CRASH transitions the item `→ blocked` (`_block_on_crash`, best-effort, sets `human_required`) and re-raises; a FAILED result is **not** a crash (`apply_update` records it as `blocked`). **`--strategy` is NOT a `run_item` param** — the board CLI mutates `config.default_strategy` BEFORE constructing the `Supervisor` (matching how `run` selects a strategy in `__init__`). The CLI `board` group mirrors `session`: `_require_board` (mirror `_require_tmux`) hard-errors when disabled; `add TASK [--goal --depends-on(repeatable) --human-required]` (no `--owner` — `owner_agent` is RECORD-ONLY in v1, stamped from `result.agent_id`), `list [--state --goal]`, `show ID`, `run [--id --loop --strategy --agent --team --goal]` (Phase 4: `--goal <g>` scopes the atomic claim to that goal via `next_runnable(goal=)` — mutually exclusive with `--id` — and auto-applies the team declaring `g`; `--team` overlays a profile pre-`Supervisor` and beats the goal mapping), `update ID [--state --evidence --sign-off --note --clear-human-required]` (the human path; `done` REQUIRES `--evidence`/`--sign-off`). **Hermetic tests:** `tests/test_board.py` drives the REAL `Board` against `tmp_path/"board.db"` with an injected `now` (like `test_breaker.py`) — CRUD/audit, atomic dedup on BOTH paths (two `Board`s/one db → exactly one claims), dep/skip, stale recovery, done-gate, gate→Evidence, advisory-done-clamps, corrupt+unopenable db→`BoardError`, parse/strip tables; `conftest.py` adds a duck-typed `FakeBoard` + `FakeMemory.scoped`/`share_board_result` (the scoped child's shares stay off the parent's global `.shared` — the leak guard); `test_supervisor.py` covers `run_item` (board-scoped-memory leak guard, crash→blocked, lazy build never touched by a plain `run`, `close()` closes the board); `test_cli.py` exercises the `board` subcommands via `CliRunner` with a tmp db. **`Evidence`/`WorkItem`/`WorkState`/`Decision`/`BoardStats` live in `board.py`, not `models.py`** (they never flow through a strategy — the `breaker._AgentState` rule).

**Phase 2 — Collaboration depth + read API** (4 deliverables, one PR; the design grounded against the merged Phase-1 code, which shifted two plan details — see below):
- **D1 Decisions (never-re-litigate).** A separate `decisions` table in the same db (orthogonal to work items — no state machine, no lease): `Board.add_decision(text, *, scope="", supersedes=None)` (atomically retires the superseded one **of the same scope** — a missing/already-retired/cross-scope target raises `BoardError` (same-scope CAS: `WHERE id=? AND superseded_by IS NULL AND scope=?`, so superseding can never silently retire a different goal's decision), and the new decision is NOT inserted; empty text rejected) + `Board.active_decisions(goal=None)` (non-superseded, oldest-first; `goal=None` → all, a goal string → global `scope=""` + that-goal-scoped). `run_item` fetches `active_decisions(goal=item.goal)` and injects the texts via the EXISTING `render_item_prompt(item, active_decisions=)` seam — **deterministic, in full, never top-k**. **Grounded divergence from the plan:** the plan put a `_enrich_with_decisions` helper in `strategies/base.py`, but Phase 1 already shipped the injection seam *inside* `board.py::render_item_prompt`, and a `base.py` helper would force a `board → strategies` import that violates the acyclicity invariant — so the seam stays in `board.py` (no `base.py` helper). The decisions read is **best-effort in `run_item`** (a `BoardError` degrades to no-decisions and logs, never blocks the item — decision injection is advisory prompt enrichment, not load-bearing dispatch). CLI: `board decide "<text>" [--scope --supersedes]`, `board decisions [--goal]`.
- **D2 `board stats`.** `Board.stats(*, now=None, stall_seconds=None) → BoardStats` computed entirely from existing rows + the append-only audit (no new write-path instrumentation): `false_done` (DONE with no passing `Evidence` — an integrity alarm, impossible via the gate), `redispatched` (items with >1 `planned→running` audit row = work a stale reclaim forced a redo — the *materialised* duplicate-work signal; a purely concurrent claim the CAS averts leaves no trace by design and need not be counted), `reclaimed_stale` (count of `recover_stale_running` reclaims, matched by the shared `_STALE_RECLAIM_NOTE`), and aged `blocked`/`human_required`/`dropped_handoffs` (untouched past `stall_seconds`). `BoardConfig.stall_seconds` (≥1, default 3600) is the aging window (`SYNCMILL_BOARD__STALL_SECONDS`); `build_board` threads it into `Board`. CLI: `board stats`; renderer `render_board_stats`.
- **D3 gateway `board_*` read tools.** `build_gateway(memory, *, board=None, …)` registers three MORE read-only tools — `board_list(state, goal, limit)`, `board_get(item_id)`, `board_stats()` — so the exact-tool-set regression guard goes **3 → 6** (`test_exactly_six_readonly_tools`). The tools are registered **unconditionally** (stable surface) and report `_BOARD_DISABLED` when `board is None`; a `BoardError` surfaces as unavailable (per-call, like the shared tools); `board_list` clamps `limit` to `[1, MAX_BOARD_LIMIT=200]` and **validates `state` up front** against the work-item state set (`_VALID_BOARD_STATES`, derived from `WorkState`) — a bad `state` filter is a **client argument error** returned as a corrective message naming the valid states, NOT mislabeled as the board being "unavailable" (which would make an LLM abandon a healthy board; only a genuine backend `BoardError` is "unavailable"). **No board-write MCP tool** (read-only + no-auth posture preserved). **Board id (uuid) validation lives in `board.py`** (the single-coupling rule): `Board.get` now rejects a non-uuid id as not-found WITHOUT a query (mirrors `SyncmillMemory.get_shared`; every real id is a `uuid4`). `serve` builds the board best-effort (a corrupt board degrades the board_* tools with a stderr warning rather than killing the shared gateway) and closes it in the `finally`. Board reads are sync sqlite inside the async MCP handlers (quick — no thread offload).
- **D4 board-run global-`shared` union-read.** A board-scoped `SyncmillMemory` view now captures the REAL global `shared` namespace (`_global_shared_ns`, set in `scoped()`); `search_context` UNION-READs it alongside the per-run scope **only when scoped** — so a board run is enriched by cross-run knowledge (prior `board-result` summaries) while its WRITES stay confined to `board-run:{run_id}` (the leak guard is untouched). A plain (unscoped) run is byte-identical (its `_shared_ns` IS global `shared`).

**Phase-2 hermetic tests** (full suite stays green): `test_board.py` (+decisions scope/supersede/retire incl. cross-scope-supersede-rejected + same-scope-still-works, stats over a seeded db with the injected clock, `get` uuid-validation, `add`/`add_decision` broad-rollback-on-non-sqlite-error, unresolvable-`~`→`BoardError`, redispatch-excludes-running-annotation, `build_board` threads `stall_seconds`), `test_memory.py` (the scoped-search test split into a WRITE-leak-guard test + a new UNION-READ test + an unscoped-no-double-read test), `test_gateway.py` (+board_* via a real `Board` on a tmp db: disabled/list/filter/limit-clamp/unknown-state-as-client-arg-error/get-found/not-found/malformed-id/stats), `test_supervisor.py` (+decision injection into the prompt, +decision-read-failure degrades-not-blocks), `test_cli.py` (+`board decide`/`decisions`/`stats`, disabled-errors extended). **Phase 3 (first slice) shipped as the TUI dashboard below; Phase 4 shipped as the named multi-team profiles below; the P3 TEAM pane (tomlkit `syncmill.toml` editing — `teamfile.py`, `team save`/`use`, `default_team`, the dashboard `t` pane) shipped as the follow-up described in both sections; Phase 5 (A2A spike) closed with a DEFER decision — see `docs/a2a-decision-memo.md` (board states verified A2A-mappable as-is; build only on the memo's revisit triggers).**
