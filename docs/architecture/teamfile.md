# Team-profile writing (`teamfile.py`, the P3 TEAM-pane follow-up — `team save`/`use`, `default_team`)

> Design record for `teamfile.py`, moved verbatim from `CLAUDE.md`. `CLAUDE.md` keeps a
> short rule list for this module; this file holds the full reasoning, history and test map.

> **Known stale statements** — checked against the code on 2026-10-21. The text below
> is kept verbatim; where it disagrees with these notes, the code (and `CLAUDE.md`) win.
>
> - "The **first (and only) toml-WRITING module**" — `project.py` (`init`) also builds documents with tomlkit, though it writes through `teamfile.write_document` under the lock. The TUI TEAM pane is another lock holder the text does not list.

The **first (and only) toml-WRITING module** — a new flat top-level module (gateway/monitor/session/board/dashboard precedent): `team save`/`team use` and the dashboard TEAM pane all funnel through it, while reads stay on pydantic-settings' `TomlConfigSettingsSource`. It lives OUTSIDE `config.py` deliberately (imperative writes don't belong in the declarative-settings module, and the unknown-agent check needs `_AGENT_CONSTRUCTORS` — a `config → agents` import cycle); the import graph stays acyclic: `teamfile → config, agents, artifacts`; `cli → teamfile`; `dashboard → teamfile`. **tomlkit** (new dep) gives comment-preserving round-trips: every write parses the existing document, mutates the smallest span, dumps, and lands via a temp+`os.replace` atomic write (the breaker/board recipe) — a failed write can never truncate `syncmill.toml`. **Atomicity is not enough on its own**, so every write also runs inside `config_write_lock(path)` — a BLOCKING cross-process lock delegating to `artifacts._cross_process_lock` (already re-entrant per thread, fork-guarded, `flock`/`msvcrt`). Atomic replace only guarantees no reader sees a half-written file; it does nothing about two writers each parsing the document and the second replace discarding the first's table — the lost update `team save` racing the dashboard/TUI TEAM pane (or `init --force`) actually produced. Blocking, not fail-fast (the `JobStore` never-wait rule is about *probing* a live holder): the critical section is one sub-millisecond parse-mutate-dump, so a waiter serializes invisibly where a busy error would surface a benign micro-race the user can do nothing about. `save_team`/`set_default_team`/`write_document` take it internally (so `project.py`'s `init` merge is covered too — it holds it across its own read→write), and the four callers that read-then-write (`team save`'s validate→save, `team use`'s `file_team_names`→set, the dashboard and TUI TEAM panes) hold it across the whole span, which re-entrancy makes free. **Only the acquisition is wrapped into `TeamFileError`** — a body failure keeps its own identity rather than being relabelled a locking one — and the lock file is never unlinked (a fresh inode per acquire would let two writers hold two different locks). **The lock path took two revisions to get right, and `_lock_path_for`'s docstring is the record.** It must be (a) DERIVED, never probed — a first attempt asked `git rev-parse --git-common-dir`, which made the lock's identity depend on a subprocess, so a writer without `git` (or with a read-only common dir) picks a different file and two locks serialize nothing; and (b) OUT of the working tree — a second attempt put it beside the config with a `.git/info/exclude` rule written by `init`, but that file is machine-local, so any clone or un-re-`init`ed upgrade drops an untracked lock into `git status` and into every agent worktree (snapshots capture untracked files). It now lives in syncmill's own state root (`~/.syncmill/locks/`, the board-db/breaker precedent) keyed by a sha256 of the config's **realpath**, so two routes to one file share a lock; an unresolvable/unwritable root is a `TeamFileError` (the `Board` precedent). Knowingly traded: the path is per-USER, so two OS users editing one shared config are not serialized — the rare case, degrading to the pre-lock behavior, in exchange for universal correctness in the case that actually happens. That primitive's `fchmod` is also now skipped where the call does not exist (Windows), since an `AttributeError` there is outside its `OSError` guard and would fail every config write before the lock was taken. `set_default_team(path, None)` checks for a missing file BEFORE locking, so `team use --clear` still touches nothing. `save_team` replaces `[teams.<name>]` **wholesale** (the flags/modal define the FULL profile — a partial merge could not express "clear goals"; only the replaced table's own comments are lost), emitting `strategy`/`goals`/`[teams.<name>.capabilities]` only when set/non-empty; tomlkit places a new top-level scalar BEFORE the first table (regression-tested in `set_default_team` — appended after `[teams.x]` it would re-parse as that table's member). The write target is `toml_path()` — derived from `SyncmillConfig.model_config["toml_file"]`, so write and discovery are the SAME file by construction (and the hermetic suite's autouse `isolate_toml_discovery` repoint automatically isolates every save test — a forgotten repoint writes to an absent tmp path, never the repo root). **Validation is two-view** (a codex pre-code design-review Major): `validate_team_save` runs the shared `config.check_team_goals` (extracted from the `_validate_teams` model validator so the rule can't drift) over BOTH the RESOLVED env+toml view with the candidate substituted (guarantees the next `_load_config()` under the current env can't die) AND the FILE-standing-alone view (an env override deep-merges above the file and can mask a dup-goal that would brick `_load_config` once that env is removed). `TeamFileError` is the single error type at the seam (the `BoardError` contract): the CLI converts flag-shaped failures to `BadParameter` and config/write failures to `ClickException` (the `_apply_team` split); the dashboard mirrors it into `last_team_error`. **`default_team`** (`team use <name>` / `--clear`; env `SYNCMILL_DEFAULT_TEAM`) is a plain `SyncmillConfig` field deliberately NOT validated against `teams` at construction — a dangling value must not brick every command *including its own fix* (`team use --clear` skips `_load_config()` entirely for the same reason); `run`/`board run` apply it via `cli._apply_default_team` (no explicit `--team` → overlay + a clean dangling-default `ClickException` naming the fix), an empty string counts as unset (the `-r ""` house rule), and the banner/echo says `(default)`. `team use` with an env-only team (resolves via `SYNCMILL_TEAMS` but absent from the file) warns that the persisted default dangles without that env (another codex Major — warn, not reject); `team save`/`use` also print env-shadow advisories when `SYNCMILL_TEAMS`/`SYNCMILL_DEFAULT_TEAM` are set. On a monitored run the resolved default rides the EXISTING `--team` forwarding (it's resolved into the same local `team` variable before `_launch_monitor_if_requested`), so `_inner_argv` is unchanged. `load_config_at(path)` (a one-off subclass pinning `toml_file`, global `model_config` never mutated) is the dashboard's post-write reload seam. Hermetic tests: `test_teamfile.py` (round-trip comment preservation, wholesale replace, both-view validation incl. the env-masked file conflict, `set_default_team` placement regression, atomic-write failure, the lock matrix — private lock file, re-entrant caller span, acquisition-failure conversion, body failures not relabelled, plus a real two-process lost-update regression under `skipif(no POSIX flock)` — `parse_capability_specs`, `render_team`, `load_config_at`), `test_config.py` (`default_team` env>toml, dangling-does-not-fail-construction), `test_cli.py` (save/use matrix, precedence incl. `board run` goal/peek/default, dangling-default error, `--monitor` forwards the default, `team show` byte-identity), `test_dashboard.py` (TEAM pane below).
