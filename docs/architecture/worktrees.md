> - "the three `cli.py` sweep call sites" — there are four `sweep_orphaned_workspaces` calls in `cli.py`.

Normal Supervisor runs create a private snapshot under `<workspace.root>/<run-id>/` and place worktrees at `<workspace.root>/<run-id>/worktrees/{agent}-{taskid}-{slot}` on branch `syncmill/{agent}/{taskid}-{slot}`. The sibling `../.syncmill-worktrees/` and tempdir fallback belong to the legacy/non-snapshot helper path; production `run` rejects unsafe or non-Git input before that path. The `{slot}` is a per-acquire counter `WorktreePool` threads into `create_worktree`: most strategies acquire one worktree per agent, but `DecomposeStrategy` acquires several for the **same** agent (planner + per-subtask + per-synthesizer), and without the slot the second `git worktree add` for that agent would collide on the existing branch/path, fail, and silently fall back to an empty tempdir — so the slot keeps every acquisition a distinct, real git worktree. A run's worktrees are managed by a **`WorktreePool`**: the Supervisor owns one per run and calls `cleanup_all()` in `finally` (each removal independent, so one stuck worktree can't strand the rest), while the *strategy* decides topology — `RouteStrategy`, `CompeteStrategy`, and `CouncilStrategy` `acquire` one isolated worktree per agent so parallel agents never clobber each other and each result's `files_changed` is its own (Council reuses each agent's single worktree across all its propose/critique/synthesize phases); `PipelineStrategy` acquires a single shared one so stages hand files down the chain; `DecomposeStrategy` acquires the most — a scratch worktree for the planner, one per subtask (concurrent isolation), and a fresh one per synthesizer — all normally torn down the same way (the winner's diff comes from its own synthesis worktree; recovery retention is exempt). Two sweeps cover crash leftovers, because the two layouts live in different places: `cleanup_orphaned_worktrees` handles the legacy in-repo `.syncmill-worktrees` layout, and `sweep_orphaned_workspaces` handles the snapshot workspaces under `workspace.root` (the live path — a SIGKILL skips `cleanup_all` and nothing else reclaims the control clone). The latter needs three guards because `workspace.root` is shared with room and interactive-session workspaces that legitimately outlive a run. A dir is a candidate only if it carries the `.syncmill-run` sentinel, written by `capture_repository_snapshot(sweepable=True)` **as soon as the directory exists, BEFORE the clone** — the slow part an interrupt lands in, and an unmarked leftover is one the sweep can never reclaim (rooms/sessions pass `sweepable=False`, so their workspaces are never candidates). `retain()` **adds** `.syncmill-recovery` rather than removing the run sentinel (creating a file is likelier to succeed than deleting one, and the exemption must survive for a LATER process to honor). And liveness is **the owning pid, asked directly** (`os.kill(pid, 0)`), never inferred from file timestamps: two successive review rounds found mtime heuristics deleting live workspaces, because an agent thinking for hours writes nothing and any bounded scan understates activity — the direction that destroys work. `acquire` rewrites the sentinel, refreshing both pid and mtime. Age survives ONLY as the pid-reuse backstop (`workspace.stale_seconds`, a week by default; the three `cli.py` sweep call sites pass it, and `_STALE_WORKSPACE_SECONDS` remains the function default for direct callers): a dead owner whose pid was recycled would otherwise be protected forever, so a live pid stops counting once nothing has touched the workspace for that long. The config floor is an hour precisely because this value **overrides a live pid** — it is the one knob whose misconfiguration deletes a running run's workspace, so it is bounded rather than free-form. A sentinel with no pid (an older version's) falls back to age alone. The Supervisor's pool creation is itself inside a try/except that cleans the workspace on any setup failure — the run's own `try/finally` starts later, after constructions (artifact store, monitor, tracer) that can raise. Because a normally finalized run tears down its worktrees, the winner's code survives durably as `TaskResult.patch` — a full applyable diff `_collect_files_changed` captures at the same seam as `files_changed` (via `worktree.capture_changes`, which stages into a PRIVATE `GIT_INDEX_FILE` and diffs `--binary --cached`, so untracked files are included and the agent's own index is never touched). `run --emit-patch <file>` exports it (`emit_patch_file`, beside `render_result` in `monitor.py`, consuming the same result.json contract); on a monitored run the flag is OUTER-owned — never in `_inner_argv`, written from result.json's `patch` field. `syncmill run` still never auto-applies a diff; explicit `syncmill apply` performs the reviewed application.
