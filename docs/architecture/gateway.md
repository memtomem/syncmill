# Read-only MCP gateway (`gateway.py`, #15)

> Design record for `gateway.py`, moved verbatim from `CLAUDE.md`. `CLAUDE.md` keeps a
> short rule list for this module; this file holds the full reasoning, history and test map.

> **Known stale statements** — checked against the code on 2026-10-21. The text below
> is kept verbatim; where it disagrees with these notes, the code (and `CLAUDE.md`) win.
>
> - "The CLI clamps `top_k` to `[1, MAX_TOP_K=50]`" — the clamp is in `gateway.py` (`shared_search`), not the CLI.
> - "`shared_stats` uses `list_namespace_meta()`" — `SyncmillMemory.shared_stats` calls `backend.count_namespace`; only the memtomem adapter uses `list_namespace_meta` beneath it.

The `serve` command runs a **one-way (read-only) MCP gateway** over the `shared` namespace so external/interactive MCP clients (Claude Code/Desktop, Cursor, …) can *read* syncmill's shared knowledge — the **consumer-facing** complement to the interactive mode above. It is **not** a strategy and **not** an agent: it preserves the core invariant exactly (agents never touch MCP; the Supervisor remains the sole *writer*) by being a separate, non-agent, read-only *consumer*. The gateway touches memory but never agents, so "the Supervisor is the only component that touches both agents and memory" still holds. `gateway.py` is a **flat top-level module** (no subpackage — don't pre-abstract; one module is enough). The seam is `build_gateway(memory, *, board=None, board_error=None) -> MCPServer` (the official `mcp.server.mcpserver.MCPServer`, mcp 2.0 SDK — `mcp.server.fastmcp` was removed in 2.0), which registers the read-only tools as closures over the injected `memory` (and, in **Phase 2**, the injected `board`) and returns the server *without running it* (the test seam — the public `await mcp.list_tools()` asserts the exact tool set so a write/delete/index tool can never sneak in; tools are driven in tests via `await mcp.call_tool(...)`, which returns a `CallToolResult` whose `structured_content == {"result": str}`). #15 shipped the three `shared` tools — `shared_search(query, top_k)`, `shared_read(chunk_id)`, `shared_stats()`; **Phase 2 adds three read-only `board_*` tools** — `board_list(state, goal, limit)`, `board_get(item_id)`, `board_stats()` — so **the exact-set guard now asserts six tools** (`test_exactly_six_readonly_tools`), still with **no write tool** for memory OR the board. The board tools are registered **unconditionally** (a stable surface) and report `_BOARD_DISABLED` ("not enabled") when no board is injected, OR `_BOARD_UNAVAILABLE: <error>` when the board was **enabled but failed to open** (`board_error`, threaded from `serve`) — the disabled-vs-broken distinction, mirroring the shared tools' healthy-empty-vs-unavailable split, while the shared gateway stays alive. `board_list` clamps `limit` to `[1, MAX_BOARD_LIMIT=200]` and returns **most-recent-first** via `Board.list_recent` (`ORDER BY created_at DESC, rowid DESC LIMIT ?` — exactly `reversed` of `Board.list`'s FIFO tie-break, but sorted and bounded in SQL so only the returned rows are materialized; #167 — the old reversed-FIFO slice converted the whole board to answer `limit=1`; `idx_work_items_created` lets the unfiltered read walk the index backwards; a truncated read keeps the newest, not the oldest, items); board **id (uuid) validation lives in `board.py`** (`Board.get` rejects a malformed id as not-found without a query — the single-coupling rule, mirroring `get_shared`). Board reads are sync sqlite called directly inside the async MCP handlers (quick — no thread offload); `serve` builds the board best-effort and closes it in its `finally`. **All memtomem coupling stays in `memory.py`** (the same single-coupling rule as the Supervisor): three shared-scoped, best-effort read methods on `SyncmillMemory` — `search_shared`, `get_shared`, `shared_stats` — `search_shared`/`shared_stats` return **`None` on a genuine per-call backend failure** (vs `[]`/a `dict` on success) and `get_shared` returns a `SharedRead` whose `status` is `found`/`not_found`/`unavailable` (#169 — a bare `None` conflated a backend outage with a missing chunk, so `shared_read` told the client "not found" while the store was down) so the gateway distinguishes "unavailable" from "healthy-empty" **without** consulting the sticky `degraded` flag (a prior unrelated degrade must not poison a later healthy empty read). **Isolation is load-bearing:** `MemtomemStore.get` is *not* namespace-scoped, so `get_shared` verifies the returned chunk's `namespace == shared` and reports `not_found` otherwise (else a guessed/leaked id would leak an `agent-runtime:*` private chunk); `search_shared` always passes `namespace="shared"` (never the agent prefix/`None`/`include_shared`) and filters non-shared rows defensively; `shared_stats` uses `list_namespace_meta()` (the only meta method carrying `chunk_count`) and reports the `shared` entry **alone** — never enumerating other namespaces (a metadata-leak guard). A malformed `chunk_id` is a client typo → `get_shared` returns *not-found* **without** degrading (validate the UUID first; only a real store error degrades). The CLI clamps `top_k` to `[1, MAX_TOP_K=50]` (untrusted-input guard). **Event-loop & transport:** the `serve` path never uses `run_async` — `MCPServer.run()` owns its own anyio loop and the async tools `await` the memory methods directly inside it; memory is constructed eagerly (sync; lazy memtomem init) and closed in a `finally` via `anyio.run(memory.close)` (a fresh loop, deliberately off syncmill's shared module loop). Under stdio, **stdout is the JSON-RPC channel** — every human-facing line (startup notice, degraded/HTTP warnings) goes to **stderr** (`err=True`); the command writes nothing to stdout. HTTP (`--http`, `streamable-http`) is loopback-by-default; on the mcp 2.0 SDK `host`/`port` are **run-time transport kwargs** — `mcp.run(transport="streamable-http", host=..., port=...)` — and the SDK computes its DNS-rebinding `transport_security` allow-list from the host actually passed at run time (loopback hosts get automatic protection), so the old construction-time-host rationale (a stale loopback policy after mutating settings) is structurally gone; a non-loopback `--host` is warned about (the warning doubles as the cue that auto-protection engages only for loopback hosts) and there is **no auth** (document/front with a trusted network or authenticated proxy). `mcp>=2.0.0,<3` is a direct dependency, moving in lockstep with the memtomem pin.
